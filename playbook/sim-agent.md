## 2. 模拟对战型（agent）

### 2.1 方法谱系（从规则到 RL 的真实路径）

- **纯规则**：Kore 2022 冠军就是规则型 agent——先穷尽规则方案上限，再考虑 RL（成本低、可控）。
- **规则骨架 + RL 局部**：Lux S2 的混合架构；规则/版本变更时先重估最优策略再改代码。
- **全 RL**：Lux S3 的**多头动作分解**（动作空间按语义拆分）是 agent 赛最通用设计；配套动态奖励缩放/自适应熵等稳定性技巧。
- **检索式决策**：Pokemon TCG 的 Pattern DB（检索相似历史局面 + 统计决策）+ 群体自对弈 + 对阵矩阵评估。

### 2.2 通用配方

1. **推理预算决定方法选择**（Orbit Wars 的核心判断）：每回合时限内能跑多少模拟/搜索，直接约束架构。
2. **自对弈 + 对手池/联盟训练**防策略退化；评估用对阵矩阵而非单一分数。
3. **关系型建模**（节点+边）适配任意实体交互场景（Orbit Wars）。
4. **分层处理组合决策**：构筑 + 策略分开（Pokemon）；同时 + 顺序决策分别设计（Lux S2）。
5. 系列赛的 Beta → 正式版 → 精英阶段是**低竞争迭代窗口**，可复用并改进已有方案。

## 3. 纯优化型

### 3.1 Santa 五年的方法演进（本主题的黄金主线）

| 届次 | 关键思想 |
| --- | --- |
| 2021 | 约束分解：先满足最强约束再优化其余；小规模人工+枚举可能优于元启发式 |
| 2022 | 搜索策略 + 时间管理：比谁更快进入更优盆地 |
| 2023 | 分治：小规模精确求解 + 大规模结构化构造；用群论等数学结构；双向搜索 |
| 2024 | **先本地精确复现打分函数**；经典组合优化（k-opt/ILS/SA）迁移；分样本独立优化再合并 |
| 2025 | 全局搜索 + 局部精修双层骨架；增量热启动；性能工程（语言/GPU 重写）直接换算分数 |

### 3.2 agent 化生产范式（NeuroGolf 2026）

**并行采样 + 自动验证 + 选择 + 结构化反馈** 的迭代回路；**验证器是一切的前提**；token 效率是硬约束；迭代与重采样混合防局部最优。

### 3.3 效率受限型

- FIDE 象棋：小网络 + 传统方法混合（NNUE 类增量更新思想）；量化/裁剪是一等约束。
- Code Golf：压缩 + 解压执行思路；自动化代码搜索与验证回路；正确性 + 长度的双约束工程。

## 4. 黑箱优化与安全攻防

- **本地精确复现打分函数是第一前提**（Santa 2024 与 LLM Prompt Recovery、AI Agent Security 同一结论）。
- 用排行榜反馈做迭代搜索，但要设停止条件并确认规则允许（CTF 2022/2023、AI Agent Security）。
- 观察提交分布异常（过度代表/缺失）可定位隐藏结构；LLM 当编程与思路助手。
- 限时解谜类（CTF）比的是**节奏管理**（先易后难、快速迭代），而非单点深度优化。

## 5. 常见坑

| 坑 | 证据 |
| --- | --- |
| 一上来就上 RL | Kore 2022（冠军纯规则）；Lux 前代经验表明规则上限可观 |
| 沿用旧赛季策略 | Lux S2（规则改动需重写策略；Lux S3 再次演进） |
| 套通用优化器而不理解约束结构 | Santa 2021 |
| 无验证器就大规模 agent 迭代 | NeuroGolf（没有自动验证无法筛选，成本爆炸） |
| 忽略工程性能 | Santa 2025、Code Golf（重写直接换分） |
| 大规模硬解（不利用数学结构） | Santa 2023 |
| 端到端输出联合动作 | Lux S3（多头分解更稳） |

## 6. 新手学习路径

1. **入门 agent**：Kore 2022（读纯规则冠军，建立"环境理解优先"的观念）。
2. **进阶 RL agent**：Lux S3（多头分解 + 稳定性技巧）→ Orbit Wars（预算判断 + 关系建模）。
3. **卡牌/不完全信息**：Pokemon TCG（Pattern DB + 自对弈评估）。
4. **纯优化**：Santa 2021（约束分解）→ Santa 2024（本地评分器 + 元启发式）→ Santa 2025（双层 + 工程）。
5. **效率/安全方向**：FIDE 象棋（NX 约束）、AI Village CTF（攻防入门）。

> 判断口诀：**能把环境完全规则化 → 先写规则；不能 → 找数学结构或检索结构；都无法 → 才是 RL/搜索。**

## 7. v2 增补（Tier B 204 场，2026-10）

1. **RL 课程 + 热启动**：16→32→64 地图、每段 80M 步、用前段最佳 checkpoint 初始化；向量化环境 1024/1024/512（L124，lux-ai-s2-neurips 459891）。
2. **收益拐点监控**：KL（32×32 在 30M 步后 >0.02）、金属产量（跌破 100 = 重机器人成本）、对旧 checkpoint 胜率曲线共同决定何时停训；loss 每 1000 步周期性尖刺（L125）。
3. **规则优先、RL 局部化**：Kore beta 的 1st 是七模块规则 agent，社区 Q-learning 打不过官方示例微调；maze-crawler 1st 是评分函数 BFS，3rd 才是 JAX+BC+PPO（L126/T33）。
4. **近镜像鲁棒性**：策略可被复制时，只针对主流打法调参会输给镜像变体；maze 1st 自述对 bunterrrr 约 53/47（L127/T32）。
5. **对手多样性**：自对弈池同质会养成"偏科"策略；用历史版本 + 针对性对抗对手（AlphaStar 式）补短板（maze 3rd 反思）。
6. **行动掩码与冲突取消**：复杂动作空间先把合法性/冲突处理写进环境包装层，再谈网络结构（lux：工厂格不转资源、冲突移动迭代取消）。
7. **基础设施**：回放/统计站（luxaistats）、每日 episode 数据集（maze）能让"用数据决定提交"成为可能，也是复盘与行为克隆的原料。
8. **beta/预览赛**：无奖励、规则可能在赛程中变（Kore 4p→2p、Lux beta 的 breaking change）；beta 优先读规则与 starter，正赛再拼策略（L123 相关）。
9. **Agent-Config 元竞赛**：提交"会自己建模的 agent"；schema/工具兼容/预算（60min、$2）是第一约束，先 validate_submission 再谈模型（L122/L123，autonomous-agent）。
