## 1. 音频

### 1.1 任务地图

| 比赛 | 任务 | 关键难点 |
| --- | --- | --- |
| BengaliAI Speech | 孟加拉语语音识别（低资源） | 领域预训练稀缺 |
| BirdCLEF 2022–2026 | 野外录音鸟种识别（多标签） | 弱标签、长尾、跨域（地域/设备） |

### 1.2 弱标签音频的五年不变配方

**切窗 → 多实例学习 → 伪标签/自训练（多轮）→ 集成**。

- 频谱图（mel）表示是默认输入；切窗粒度与重叠决定上限。
- 只有"整段出现过某物种"的弱标签时，切窗 + 多实例是唯一成熟路径。
- 伪标签要**多轮迭代**，单轮收工收益有限（2025 明确结论）。
- 跨域（不同地域/设备）必须先做跨域验证，单域调优会在隐藏测试崩掉（2024）。
- 2026 新增：按分类学层级构建专家模型；对预训练模型的选用要给明确理由；**全自动参赛有规则风险**（出现违规先例）。

### 1.3 年度演进（BirdCLEF）

- 2022–2023：方法起步——切窗与频谱表示确立。
- 2024：半监督与跨域评估进入标配。
- 2025：多轮自训练流程化。
- 2026：类别层级专家 + 预训练取舍 + 合规审视。

### 1.4 可迁移

- 低资源任务优先找**领域预训练模型**；换骨干后重置任务头（BengaliAI）。
- "弱标签 → 切窗 → 多实例 → 伪标签"可迁移到视频、医学影像、声学事件。

## 2. 其他（元类）

这一册收三类非预测型赛事：**评审制分析/论文赛、黑客松/应用赛、元报告与系统赛**。

### 2.1 评审制分析/论文赛

代表：NFL Big Data Bowl 2022–2024、Big Data Derby 2022、WiDS Phase II、Kaggle Survey 2021/2022、LLM Prompting with MakerSuite。

**通用打法**：

1. **先读规则与评审维度**：分析报告（BDB/Derby）、研究论文（WiDS）、营销叙事（Survey）、提示词设计（MakerSuite）各有评分口味。
2. **领域先定型**：BDB 系列前几届讨论区主体是擒抱技术分类、术语与统计口径——"把领域问题定义清楚"本身就是得分项；Survey 系列先判定测量尺度（定性数据禁用连续变量方法）。
3. **外部数据与差异化**：Survey 冠军用多源外部数据构造 AI adoption index；BDB 用历史文献与 NGS 指标家族；但加数据前先问规则（Derby 的马匹爬取、MakerSuite 的地区限制）。
4. **写作即产品**：7 条 notebook 军规（选具体问题、独特角度、引用来源、方法匹配数据类型、简单图表、解释所有结果、美学与导航）来自 Survey 系列，适用于全部评审制比赛。
5. **提前公开换反馈**：Survey 的早鸟奖官方激励此策略；2022 冠军提前两周公开并据评论调整。
6. **系列复用**：Survey 每届的"往届获奖陈列"、BDB 的历届档案是最便宜的起点；成熟赛型直接复用公开方案是理性选择（March Mania 冠军自述）。

### 2.2 黑客松 / 应用赛

代表：Gemini 3、Gemini 长上下文、Gemma 3n、Tunix、BigQuery AI、Data Assistants with Gemma、OpenAI to Z、GPT-OSS 红队、Med-Gemma、LLM Prompting with MakerSuite。

**共性**：

- **类别化评审**（MakerSuite 7 类；各类别独立出奖）——选题定位与实现同样重要；同一套写法套不同场景即可多线投稿。
- 产出物是应用/工具/报告；零算力或低算力即可入场，是新手第一次参赛的优选。
- 硬性资格先查清（地区/年龄限制曾劝退大量参赛者）。
- 提示词类获奖结构：**system prompt 定角色 + few-shot 输入/输出对 + JSON 等可评估输出**。

### 2.3 元报告与系统赛

- 调查报告类（2023 Kaggle AI Report）：跨社区征集洞见，重叙事与证据。
- 系统类（predict-ai-model-runtime）：编译/运行时性能预测——方法迁移自标准表格赛，但需要系统领域知识。

### 2.4 可迁移与新手指南

- 评审制比赛的修炼顺序：**领域知识 → 问题定义 → 指标/方法论 → 叙事**；与打榜赛"先基线再调参"完全不同。
- 元类比赛是**建立公开作品集**的最佳场所（BDB 官方明说"简历加速器"）。
- 学会按评委画像选题（Metric / Undergrad / Coaching / 应用类别……）。

## 3. 多模态融合（跨主题）

### 3.1 核心难点

不是"用两个模型"，而是**让不同模态互相提供对方没有的信息**，并处理模态缺失/不对齐。

### 3.2 已有证据（截至当前 188 场）

| 比赛 | 模态组合 | 关键做法 |
| --- | --- | --- |
| CMI 传感器行为识别 | IMU + 温度 + ToF | 每模态一个 1D-CNN 分支再融合；按缺失模式分别建模 |
| RSNA 乳腺 | 多视角图像 + DICOM 元数据 | 单视角建模 → 按患者聚合 |
| Petfinder | 图像 + 表格元数据 | 强相关元数据当辅助任务标签而非拼输入 |
| H&M / Otto | 交易序列 + 商品元数据 + 图像 | 召回阶段以结构化信号为主，图像补充 |
| ROGII | 物理模型输出 + 神经特征 | 物理模型提供可行域，网络拟合残差 |

### 3.3 可复用方法

- **分模态分支 + 后融合**（early fusion 常不如 late fusion 稳）。
- **模态缺失单独建模**：把缺失模式当作建模维度而不是统一填充。
- **辅助任务**：弱相关模态转为辅助标签，避免污染主输入。
- 先对齐（时间/空间）再谈模型。

## 4. 新手路径

1. 从黑客松/应用赛或 Survey 分析赛起步（零算力、练叙事）。
2. 再打 BDB 类数据丰富的分析赛（练领域型指标设计）。
3. 音频方向从 BirdCLEF 近两届的公开方案学"切窗 + 伪标签"骨架。
4. 多模态方向先掌握"分模态分支 + 后融合 + 缺失建模"三件套。
