I would like to share an XGBoost trick to handle larger data and more features. When we use the Python API, we create a xgb.DMatrix() to wrap our data before train and predict. If we use an xgb.QuantileDMatrix() instead, then we can train with up to 8x more data!

XGBoost uses Histogram

The most common tree_method is hist. This takes each column of numbers (whether int64, int32, float64, or float32, etc) and puts it into 256 bins for training and inference (when we use the default value for max_bins). This means that the original column of 8 bytes or 4 bytes per number becomes 1 byte per number!

So when our train data is 32bit precision, it gets reduced by 4x when XGB is training. (Or if it is originally 64bit precision, it gets reduced by 8x). This is good news because this means we can train with larger dataframes than we think when using XGB.

Use QuantileDMatrix (Trick 1)

Let's look at an example. Imagine that we have a dataframe with 1 million rows and 1000 columns. This is 1e9 elements (i.e. numbers). If each number is 32bit precision (i.e. 4 bytes), then this dataframe is 4GB of data. When we use xgb.DMatix(), this entire 4GB first gets loaded into GPU VRAM before it gets compressed into histograms and finishes as 1GB of data.

When we use xgb.QuantileDMatrix(), then the data gets loaded into memory in batches. First we load 1GB and it gets compressed to 250MB. Then we load another 1GB and it gets compressed to 250MB, etc etc. So the xgbQuantileDMatrix() doesn't require us to have 4GB of GPU VRAM if we wish to train on a 4GB dataframe. Also, we choose the size of the batches, so if we make them small, then we only need about 1GB of GPU VRAM to train with 4GB of 32bit dataframe.

Reduce Data Types (Trick 2)

By default, Pandas and NVIDIA cuDF loads numbers as int64 and float64. Usually this is more than we need. We can nearly always reduce integers to int32 and float32. Doing this reduces our data by a factor of 2x. So first, we should read and reduce our data. And second, we can use xgb.QuantileDMatrix(). The combination of both of these techniques allows us to train with up to 8x more data!

Maximize QuantileDMatrix with Disk (Trick 3)

To maximize the benefit of xgb.QuantileDMatrix(), we can use two notebooks. In the first notebook we perform GPU (i.e. NVIDIA cuDF) feature engineering and save the dataframe to disk. In the second notebook we design our data loader to read batches from disk.

The reason this maximizes the size of data we can train with is as follows. Imagine that we have a 15GB dataframe and 16GB of GPU VRAM. If we use NVIDIA cuDF to build our dataframe, then we are already using 15GB of GPU VRAM (to store our original dataframe) when we begin to build our xgb.QuantileDMatrix(), so we only have 1GB left over to fit the XGB train data.

If we build our 15GB GPU dataframe in one notebook and save to disk. Then our second notebook begins with all of its GPU VRAM available. Then inside our data loader which feeds our xgb.QuantileDMatrix(), we read 16k rows of our dataframe at a time, transfer it into GPU VRAM and compress it to 4x smaller size. In the end XGB will only use 15/4 = 3.75GB of our 16GB GPU VRAM. And the original 15GB dataframe is not anywhere in our notebook's memory. It only exists on disk.
