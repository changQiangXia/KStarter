final submission code

Overview

  • multiple context retrieval from 2+2 different wikipedia data
  • multiple choice by single DeBERTa model
  • max probability ensemble
  • tf-idf post process

Retrieval

There are four main types of Wiki data

  • Wikipedia database backup dump (extracted with wikiextractor)
    • Cons
      • All articles are there, but bullet lists and some sections are missing.
      • Some formulas are not extracted, e.g. "formula_1", "formula_13".
  • Wikipedia Cirrus dumps (extracted with wikiextractor)
    • Con
      • Cannot split into sections
  • 270k Data Cohere
  • 270k Data parsed

About dumps data

  • Split and embed articles 200~250 characters at a time, quantise the index with ivfpq in faiss to get it into memory and search for articles
  • After retrieving 10 articles, split the text with sliding window, vectorise it and search with faiss's indexflat to create a context
    • The answer should be contained within a few sentences
    • A single sentence is too short.
    • However, if you split the text into several sentences, it may be split at the centre of the sentence that is the answer → split with sliding window

About 270K data

The following two types of retrieval are used

  • tf-idf
  • Search with faiss indexflat as embedding

Since embedding of only questions can be computed during inference, even relatively large models (e.g. BAAI/bge-large-en-v1.5) can be used, but this did not make much difference.

Model

  • Same DeBERTa large single model used for all inference except post-processing
  • Inference used a context twice as long as the training one

Training data (especially Exam data)

  • 60K data (data generated by GPT-3.5 based on wikipedia + α)

Validation Strategy

  • Hold out
  • 200 train.csv + 1000 additional data (science exam from wikipedia made by GPT-3.5)

No high correlation, but informative. However, the last one was not very helpful as it was a mixture of questions with wrong answers or more than one correct answer.

Ensemble

  • Take the max of each prediction probability , and try to predict from largest to smallest
    • If there is an answer in the context, it should be high confidence
    • If there is no answer in the context, it should be low confidence
  • Robust, less likely to overfit, but better performance than simple blending.

Post Process

  • Modification of predictions by tf-idf with (4,7)-gram for specific conditions.
    • Post-processing to correct what is obviously wrong
