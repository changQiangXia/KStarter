as seen in another post potentially, I experimented with LLM-written solutions (besides using BlueCast).
The question for me was how far I can get with them when trying to get the best possible solution. However I did not try to aim for synthetic data or Kaggle specifics, but for a generally good solution.

In the end the LLM solution finished 789th place (top 21%), which is pretty decent given the little amount it required. You can find the code here. Except from some issues with Lightgbm 4.0 syntax it worked smoothly. ChatGPT4-o1 (preview) is a true game changer and can handle incredibly long context which makes debugging easier. It is also much smarter in it's reasoning. Also I was able to ask the LLM for complicated and crazy NN architectures and it has been able to write them mostly error free. This discipline has been really hard in the past with LLMs.

My BlueCast submission placed a bit behind (approx rank 1000) (generally no surprise as it uses Xgboost only). Despite past experience with playground comps I tried to engineer features, but it basically did nothing and performed slightly worse than just doing no feature engineering.

One of the biggest non-LLM learnings for me was how much unsupervised learners can be tuned in supervised fashion. The first Isolation Forest run achieved 0.78~ish private LB, but tuning the features to use, the clipping and the params brought it up to 0.84+. Especially tuning for features to use seems to have a good uplift.

So what can we take away from it? LLMs are marching forward with insane speed. Obviously you get what you ask for, but with the right questions they can unleash fanttastic solutions already.
