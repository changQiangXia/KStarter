Topic #466399: Simple direct ML (not RL) idea: train model to predict the DISTANCE to solution state, then just choose moves which decrease the estimate 
  Author: Alexander Chervov
  Posted: 2024-01-08 13:04:30.358000
  Votes: 29  Comments: 56

Some ideas - will be updated. What do you think about them ? 

Plan




All you need is DISTANCE: if one knows the distance from ANY state to the solution state - then it is trivial to solve any puzzle: start from the initial state - and always choose such move which decreases the distance to the solution state.  (Distance function - the minimal number of "moves" to connect a state and the solution state , i.e. the length of the shortest path ( standard thing in graph theory)). 


Pain: that function is not easy to compute - may be it is even NP-hard problem , however some approximation may also work.  (We will not find optimal path, but at least not so long path).  


Resolve pain - use of ML - train model to learn distance: we can first create some training set where we know pairs: (states + distances) - and then train ML model to predict distances. We will infer it on any state.  


That  is all the plan.  It is quite simple. 

Let us now go into details:

Details

4. Create training set by random walks + bit of brute force. 

4.1. The states which are "nearby" the solution state - can just all be listed by brute force - say on distance 2-3-4-5.. from the solution state. But since it grows exponentially - one cannot go much further. ( The number of states in 5x5x5 cube similar to number of atoms in the universe ) 

4.2 So to sample more data we can run the random walks starting from the solution state and going some "N" steps, for "N" not so big - less than "God's number"  (maximal  possible distance). So - if random walk comes to state in "k" steps - the distance is k or less, typically it is exactly "k" (if k &lt; Gods number). So we can use that as a at least use that random walk "k" as  a kind of "dirty-distance".  Any ideas to improve ? 

What is done ?




Preliminary experiments on the small puzzles shows that vanilla CatBoost can learn the distance with reasonable quality ( Wreath6/6, Wreath7/7 ). However it becomes worse if we decrease the training set: Wreath7/7, Even more smaller . Here are some experiments with CatBoost for cube 3/3/3: notebook.


The key question seems - how to sample, and for larger cubes that can require some ideas. For the moment the simple ways for cube3/3/3  tried tried in the notebook  States+Distance Generate+Save - where first we create brute force for ALL states nearby the solution states and then run random walks which move that ENTIRE initial set by several steps e.g. 20.  The results for Cube3/3/3 and the most frequent solution state are stored in the Kaggle dataset


Technical thing - it seems better to represent states as numeric vectors - for most cases np.int8 is Okay. Not like in the input file - as list of ['A','B',…], but encode something like A-&gt;0, B-&gt;1 etc… See e.g. here. The question is what are the best ways to hash these vectors ? (See the next section). Simple way - just the scalar product with another vector - floating number is a hash. (See e.g. here )


Questions/problems




The key question - how reasonable is the plan - let us try and see  - do not know yet. 


Understanding random walks. 

2a. Key question for random  walks sampling - estimate the diameter  - random walks should NOT be longer than maximal possible distance ! Do we have good estimates ? 

2b. The random walk making "k"-steps  may NOT generate the shortest path between stateA and stateB, however if "k" is less than diameter we can hope it is typically true (for these puzzles). But do we have an estimate - how true is ? I.e. what is the expected distance (from start point) of the random walk making k-steps   ?  


Are standard  random walks Okay - or may be we need to "thick tubes" i.e. not just one state is walking but its entire neighborhood - that is easy to implement since matrix multiplication of move matrix on the all-states-matrix "moves" ALL states at ONCE (see implementation here)  additional bonus that we have better confidence that such random walk is achieving really states on on distance "k", but not going into back direction - decreasing the direction to initial state. 


For larger cubes - do we need to utilize "big jumps" ? I.e. we can just random walk by some combinates of 10 or 100 moves at once - that can be useful to explore the space of states. Like idea of [I. Pavlyukevich: Levy Flights, Non-local Search and Simulated Annealing])https://arxiv.org/abs/cond-mat/0701653) (which is now popular in ML) - utilize big jumps like in Levy process.


What model to utilize for prediction  ? It should be quite fast - what is more important - model precision or ability to train/infer million/billion states ? 


The main pain is , of course, enormous number of states. When we create training state - how many states we need ? Any estimates? 


Technical thing - hashing states. In all the approaches - we need keep some array of states and efficiently decide whether the new state is in the array or not , i.e. is it really new, or we found old one. Since states can be represented by numeric vectors we can hash just my the scalar product with some random numeric vector - the floating number will be a hash - is it enough to hash big number of states ?  (See also remarks above).


Can we utilize "active learning" ideas - iterate a) increase of training sets b) retrain the model.  Such that we can improve the models quality with the least possible training data. 


Actually we do not need to know distances for all states - our primary interest is the "initial states"  which are given to us by the organizers  and the shortest paths connecting them to the solution states - but how to modify the approach to take that into account ?
