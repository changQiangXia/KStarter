Plan

  1. All you need is DISTANCE: if one knows the distance from ANY state to the solution state - then it is trivial to solve any puzzle: start from the initial state - and always choose such move which decreases the distance to the solution state. (Distance function - the minimal number of "moves" to connect a state and the solution state , i.e. the length of the shortest path ( standard thing in graph theory)).

  2. Pain: that function is not easy to compute - may be it is even NP-hard problem , however some approximation may also work. (We will not find optimal path, but at least not so long path).

  3. Resolve pain - use of ML - train model to learn distance: we can first create some training set where we know pairs: (states + distances) - and then train ML model to predict distances. We will infer it on any state.

That is all the plan. It is quite simple.

Let us now go into details:

Details

4. Create training set by random walks + bit of brute force.

4.1. The states which are "nearby" the solution state - can just all be listed by brute force - say on distance 2-3-4-5.. from the solution state. But since it grows exponentially - one cannot go much further. ( The number of states in 5x5x5 cube similar to number of atoms in the universe )

4.2 So to sample more data we can run the random walks starting from the solution state and going some "N" steps, for "N" not so big - less than "God's number" (maximal possible distance). So - if random walk comes to state in "k" steps - the distance is k or less, typically it is exactly "k" (if k < Gods number). So we can use that as a at least use that random walk "k" as a kind of "dirty-distance". Any ideas to improve ?

Questions/problems

  1. The key question - how reasonable is the plan - let us try and see - do not know yet.

  2. Understanding random walks.

    2a. Key question for random walks sampling - estimate the diameter - random walks should NOT be longer than maximal possible distance ! Do we have good estimates ?

    2b. The random walk making "k"-steps may NOT generate the shortest path between stateA and stateB, however if "k" is less than diameter we can hope it is typically true (for these puzzles). But do we have an estimate - how true is ? I.e. what is the expected distance (from start point) of the random walk making k-steps ?

  3. Are standard random walks Okay - or may be we need to "thick tubes" i.e. not just one state is walking but its entire neighborhood - that is easy to implement since matrix multiplication of move matrix on the all-states-matrix "moves" ALL states at ONCE (see implementation here) additional bonus that we have better confidence that such random walk is achieving really states on on distance "k", but not going into back direction - decreasing the direction to initial state.

  4. For larger cubes - do we need to utilize "big jumps" ? I.e. we can just random walk by some combinates of 10 or 100 moves at once - that can be useful to explore the space of states. Like idea of [I. Pavlyukevich: Levy Flights, Non-local Search and Simulated Annealing])https://arxiv.org/abs/cond-mat/0701653) (which is now popular in ML) - utilize big jumps like in Levy process.

  5. What model to utilize for prediction ? It should be quite fast - what is more important - model precision or ability to train/infer million/billion states ?

  6. The main pain is , of course, enormous number of states. When we create training state - how many states we need ? Any estimates?

  7. Technical thing - hashing states. In all the approaches - we need keep some array of states and efficiently decide whether the new state is in the array or not , i.e. is it really new, or we found old one. Since states can be represented by numeric vectors we can hash just my the scalar product with some random numeric vector - the floating number will be a hash - is it enough to hash big number of states ? (See also remarks above).

  8. Can we utilize "active learning" ideas - iterate a) increase of training sets b) retrain the model. Such that we can improve the models quality with the least possible training data.

  9. Actually we do not need to know distances for all states - our primary interest is the "initial states" which are given to us by the organizers and the shortest paths connecting them to the solution states - but how to modify the approach to take that into account ?
