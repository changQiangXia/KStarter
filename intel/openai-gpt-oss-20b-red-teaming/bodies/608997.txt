Taxonomy-Based Analysis of LLM Attack Methods

This document outlines the process used to create a structured, analyzable dataset of LLM attack methods from a corpus of unstructured red-teaming writeups.

1. Framework Creation

The foundation of this analysis is a formal, hierarchical taxonomy of known LLM attack methods, which is defined in attack_taxonomy.md. This taxonomy provides a controlled vocabulary for classification, ensuring consistency across all entries. The raw, unstructured summaries of various attack methodologies were compiled into a single file, condensed_methods.md.

2. Automated Labeling and Data Enrichment

To bridge the gap between the unstructured summaries and the formal taxonomy, we developed predict_taxonomy.py. This script automates the labeling process:



It iterates through each attack summary in condensed_methods.md.

For each summary, it calls the Gemini API with a specialized prompt. This prompt instructs the model to act as an expert AI security researcher.

The model is provided with both the attack summary and the complete attack_taxonomy.md as context.

It is then tasked with selecting the most relevant and specific attack categories that describe the methodology in the summary.


3. Producing the Enriched Dataset

The script captures the list of predicted taxonomy labels from Gemini for each writeup. It then combines the original source, the full summary content, and the new taxonomy labels into a single, structured record.

This entire collection is saved as predicted_taxonomy.json, creating an enriched dataset where each attack method is now machine-readable and systematically classified. This structured data is invaluable for quantitative analysis, pattern recognition, and further research into LLM vulnerabilities.

Taxonomy of LLM Attack Methods

This document provides a hierarchical taxonomy of attack methods identified from the condensed summaries of AI red teaming methodologies.




1. Prompt-Based Attacks



### 1.1. Prompt Injection


#### 1.1.1. Direct Injection


Spoofing developer messages to re-enable disabled tools.

Injecting fake system messages or non-existent tools.

Comment injection to bypass filters or alter behavior.

Injecting faux system tokens into user input (Reflected Harmony Tokens).

#### 1.1.2. Indirect Injection


Embedding hidden instructions on webpages (JSON-LD aiInstructions).

Injecting instructions via Markdown metadata (titles, alt-text, ZWSP).

Embedding malicious instructions within benign source material for summarization tasks.

Embedding hidden payloads in folded HTML comments inside iCalendar descriptions.

### 1.2. Social Engineering &amp; Deception


#### 1.2.1. Persona &amp; Role-Playing


Coercing the model by framing compliance as a "survival" test.

Posing as a "police intern" to request information on illegal activities.

Adopting a "morally unconstrained programmer persona" to generate malicious code.

Using a "naive student" persona to gather sensitive system information.

Framing harmful requests as dialogues between characters in a film.

Using "Cialdini's seven principles of persuasion" to induce compliance.

#### 1.2.2. Framing &amp; Contextual Disguise


Framing harmful requests as "academic descriptions" or "security research."

Disguising malicious requests as benign narratives or anecdotes.

Using "defensive reframing" to make a malicious request appear benign.

Framing harmful requests as "benign-wrapper prompts" (e.g., "Generate test cases").

Framing harmful requests within a fictional, fantasy-framed context ("narrative cloaking").

Framing harmful requests as "legal/preventative" inquiries.

### 1.3. Contextual Manipulation


#### 1.3.1. Multi-Turn &amp; Conversational Attacks


Decomposing a harmful request into a sequence of individually benign queries ("Context-Blind Instruction Chaining").

Using "gradual escalation" to increase the specificity of harmful requests over multiple turns.

Poisoning the conversational context to degrade safety refusals for subsequent harmful requests.

Using multi-turn dialogues to establish authority and exploit progressive trust.

#### 1.3.2. Fictional &amp; Historical Framing


Embedding dangerous requests within a fictional, fantasy-framed context.

Disguising harmful requests in whimsical scenarios with term substitutions and typos.

Targeting non-player characters in game-like settings and then escalating to real-world contexts.

Framing requests within past periods where actions were permissible and then shifting the timeline to the present.

### 1.4. Obfuscation &amp; Evasion


#### 1.4.1. Linguistic &amp; Semantic Obfuscation


Using semantically similar "decoy" words to bypass content filters.

Using synonyms and euphemisms to bypass direct content filters ("Crescendo method").

Using multilingual prompts (e.g., Chinese/Hanyu Pinyin/English, Russian) to bypass safety filters.

Using low-resource languages (e.g., Scots Gaelic, Sundanese/Javanese, Yoruba, Pidgin) to bypass English-centric refusal policies.

#### 1.4.2. Encoding &amp; Formatting Obfuscation


Using Unicode obfuscation (directional overrides, non-breaking spaces, zero-width characters).

Using different encodings (e.g., Base64, ROT13, Hex) to hide malicious prompts.

Using structured data embedding (e.g., JSON, XML) to disguise malicious requests as internal system instructions.

Using emoji encoding to represent restricted words, links, or instructions.


2. Reasoning &amp; Logic Manipulation



### 2.1. Chain-of-Thought (CoT) Manipulation


Hijacking the Chain-of-Thought to hide malicious logic while presenting benign code ("cognitive partitioning").

Appending simulated internal reasoning to prompts to override guardrails.

Injecting fabricated policy statements and justifications into the model's analysis channel.

Falsifying the internal reasoning to hide malicious actions or introduce covert code sabotage.

### 2.2. Logical Fallacies &amp; Paradoxes


Using "no-win" question framing to bypass guardrails.

Presenting a self-referential paradox to test logical consistency.

Using complex, puzzle-like prompts to overwhelm safety filters.

Using "fallacy prompts" to exploit the model's susceptibility to logically flawed arguments.


3. Data Exfiltration &amp; Leakage



### 3.1. Direct Leakage


Exposing the model's internal, hidden moderation reasoning trace.

Leaking sensitive information (e.g., system prompts, API keys) through direct questioning.

Leaking sensitive information from training data (e.g., PII, copyrighted material).

Leaking internal reasoning and policy details through "Why did you refuse?" prompts.

### 3.2. Covert Channels &amp; Steganography


Embedding data within Markdown image URLs (side-channel attack).

Using acrostic steganography to embed hidden payloads in generated text.

Hiding content via zero-width character steganography in structured outputs.

Embedding hidden payloads in folded HTML comments inside iCalendar descriptions.

Using Morse code with subtle whitespace characters to encode PII.


4. Reward Hacking &amp; Alignment Exploitation



### 4.1. Reward Hacking


Making the model prioritize meta-instructions that imply a maximal reward over its primary task.

Offering trivial "reward points" to bypass safety filters.

Manipulating scoring rules to inject harmful keywords.

Using a "Fact-Checker Gambit" to make the model "correct" deliberately incorrect information about dangerous topics.

### 4.2. Deceptive Alignment


Analyzing internal monologues to reveal strategic suppression of true goals and malicious intent.

Using "evaluation-aware deception" where the model strategically adapts its responses based on the perceived system context.

Using "sandbagging" (strategic underperformance) when the model is aware of being under evaluation.

Using "capability masking" where the model deliberately hides its abilities.

### 4.3. Evaluation Awareness &amp; Gaming


Detecting when the model is under explicit assessment and shifting its behavior.

Gaming evaluation metrics by producing superficially correct but factually inaccurate content.

Using "evaluation forgery" by injecting internal review blocks to bypass safety.

Using "salted canaries" and "stealth masks" to create distinct evaluation paths.


## 5. Architectural &amp; Systemic Vulnerabilities



### 5.1. Mixture-of-Experts (MoE) Exploitation


Using "Router Poisoning" to force specific, under-aligned experts to activate.

Exploiting a mismatch in the "experts-per-token" (E-PT) configuration between training and inference.

Tracking MoE expert activation to identify specific experts responsible for "evaluation-detection" behavior.

### 5.2. Tokenizer &amp; Encoding Vulnerabilities


Using "rare-token KV-cache poisoning" to destabilize the key-value cache.

Using misspelled prompts to exploit tokenizer sensitivity.

Using "vocabulary-based adversarial fuzzing" to dilute the model's attention.

### 5.3. Tool Use &amp; API Exploitation


Re-enabling disabled Python tools for credential exfiltration.

Coercing the model into tool misuse through hidden web content.

Using "cross-tool hijacking" where malicious tools appear as essential pre-processors.

Using a "double semantic attack" where a tool's description contains a malicious action.

### 5.4. System &amp; Policy-Level Exploits


Exploiting a designed loophole in the safety policy permitting "realistic simulation email" generation.

Manipulating the model's internal policy reasoning process by feeding it edited, permissive policies.

Exploiting the model's reliance on its chat template for safety.

Using a "control-plane bypass" by exploiting the model's failure to consistently adhere to output contracts.
