I’ll share the method itself in a separate attachment later. This write-up primarily focuses on how I built a fully automated Kaggle competition solver using Claude Code for this competition. To begin, I'd like to show the token consumption from the last month:



All the necessary markdown files for claude-code is in the file attachment. Here is the brief diagram about my agent workflow.

Besides workflow, those html files are all triggered by me. I basically work about 1-2 hours on birdclef by seeing those html report. And if I found any strange reported results in html then I fine-tune my workflow. Otherwise I didn't touch it and just let it keeps running. 

Submission Criteria: I have established multiple validation gates, including score thresholds and diversity verification across multiple datasets. Once all criteria are satisfied, the system sends an authorization request through the Gmail MCP. I then receive the email and explicitly reply to confirm that I approve the submission.
Only after receiving my approval does the system proceed with the final submission. This process is similar to submitting a merge request to an application or repository owner and requiring their approval before the changes are merged.

Working time: I worked on this competition about 1-2 hours per week including spending time on code-review the submission.

├────────────────────────────────────────────────────────────────────────────┤

3. [A] Submission gate flow — SUBMISSION GATE v2 (4 layers, all must PASS)

        │  delegate to submit-gatekeeper
        ▼

  │   upper (coarse) : JS(class_name) ≤0.10│

  └───────────────┬─────────────────────┘

                  ▼

  │     (BirdSet PER, soundscape)        │

              PASS│

4. [B] Eval validation flow (new round done → bookkeeping)

  New finished round (fold0..4_best.pt present)
        │  delegate to eval-validator
        ▼
  ┌──────────────────────────────────────────────┐
  │ Check: all_ss_probs.npz / _corrected.npz exist │
  │        5 folds present · ss_auc∈[0.80,0.99] noNaN│

  └───────────────┬──────────────────┬────────────┘
              PASS│              FAIL │
                  ▼                   ▼
        Update experiment_ledger.md  ✗ mark invalid
        (hypothesis/setup/val·LB/concl) block gen pseudo / submit
                  │                   │ report reason
                  ▼                   ▼

  │        └──────────────  next round (perch_w decays)  ◀──────┘         │

6. [D] Dry → research flow (loop-until-dry core)

  ── Detection layer (background experiment_dry_detector.sh, every 1800s) ──
   Scan outputs/logs/sed_ns_*_fold*.log, compute per-round best_val_auc
   improvement series
        │
        ▼  dry criteria (any one true)
   (A) self-train converged: DRY_PATIENCE(3) rounds improve &lt; DRY_EPS(0.001)
   (B) ceiling stuck       : best_val_auc still hugging 0.948, no breakthrough
   (C) backlog exhausted   : no status: todo high-priority idea
        │
        ├─ true  ─▶ write EXPERIMENT_DRY.flag (with reason)
        └─ false ─▶ remove stale flag (back to experiment, keep pushing)

  ── Decision layer (orchestrator policy ④) ────────────────────────────
   EXPERIMENT_DRY.flag / AUTORESEARCH_TRIGGER.flag
        │  trigger lit-research-watch
        ▼
   Spawn N subtopic agents from template_agent, in parallel:
        ┌──────────────┬──────────────┬──────────────┬─────────────┐
        ▼              ▼              ▼              ▼             ▼
   autoresearch   autoresearch   autoresearch   autoresearch  autoresearch
     -scout        -scout         -scout         -scout        -scout
   new backbone  pseudo denoise  calibration   post-proc    domain-gen / SSL
        │              │              │              │             │
        └──────────────┴──────┬───────┴──────────────┴─────────────┘
                              ▼  each WebSearch+WebFetch → distill actionable gains
                   synthesize reports/lit_research_&lt;date&gt;.md
                              │
                              ▼
                   write new ideas into ideas_backlog.md (status: todo)
                              │
                              ▼
                   🧹 clear EXPERIMENT_DRY.flag
                              │
                              ▼
                   back to experiment phase (next wake hits policy ③)

   ╔═══════════════════════════════════════════════════════════════╗
   ║  loop-until-dry: keep pushing experiments; only go to websearch ║
   ║  when "dry". After refilling backlog, clear the flag and return ║
   ║  to experiments — avoids wasteful searching.                    ║
   ╚═══════════════════════════════════════════════════════════════╝




7. Flags &amp; data flow (detection layer → decision layer)

  Background script                Writes flag/log                Consumed by
  ─────────────────────────────────────────────────────────────────────────
  submit_gate_watcher.sh    ──▶  SUBMIT_READY.flag          ──▶  policy ① / [A]
  Gmail MCP create_draft    ──▶  email "SUBMIT-REQ r{R}f{f}" ──▶  L5 approval loop
  Gmail MCP search/get_thread ─◀  reply APPROVE/REJECT       ──▶  L5 go / no-go
       (headless: Gmail MCP may be unavailable → fall back to SUBMIT_READY.flag,
        defer L5 email approval to an interactive session)
  experiment_dry_detector.sh──▶  EXPERIMENT_DRY.flag         ──▶  policy ④ / [D]
  autoresearch_scheduler.sh ──▶  AUTORESEARCH_TRIGGER.flag   ──▶  policy ④ / [D]
  eval_validity_watchdog.sh ──▶  eval_validity.log           ──▶  [B] precheck
  watchdog_nc.sh            ──▶  (restarts training directly) ──▶  protects [C]

  Memory layer (orchestrator reads/writes)
  ─────────────────────────────────────────────────────────────────────────
  STATE.md            ←→  read + write back each step (LB / in-progress / next / next wake)
  ideas_backlog.md    ←→  [D] writes todo · [C] takes &amp; sets running · result filled back
  experiment_ledger.md ─▶ [B]/[C] append (hypothesis→setup→result→conclusion→next)




8. One-line summary

   wake → read state+flags → pick one decision-tree branch →
        ① gate submit(L1–L4 → L5 Gmail email APPROVE)  ② validate &amp; log  ③ run experiment  ④ research only if dry  ⑤ idle
   → write back STATE → wait next wake → ♻ permanent loop,
   submission always waits for a self-sent email APPROVE (merge-request style;
   headless falls back to SUBMIT_READY.flag + interactive L5)
