Alvor part

Candidates selection:



all items from the session's history

items from co-visitation matrices. I did many experiments (window size, weights, action types etc.) and finally end up with 5 best matrices (in terms of maximum possible recall when using each matrix). Each of these 5 matrices I use both for candidates selection and for feature engineering (sum/avg/max candidate score, etc.)

I did not have fixed number of candidates per session

median number of candidates per session: 67

but there were sessions with very high number of candidates, so the average candidates number per session is 121.46

my recalls per target:
clicks recall: 0.631531
carts recall: 0.540274
orders recall: 0.729626
Total: 0.6630
What did not work for me:

add candidates from Word2Vec embeddings (K nearest neighbours)

add candidates from Matrix Factorization embeddings (K nearest neighbours)

simply increase number of candidates in my methods

all these attempts increased the maximum possible recall, but decreased the validation score


Feature engineering:



Sessions features

Items features

Items-2-Sessions interactions features

Co-Visitation matrices features (sum/avg/max of candidate score, etc.)

Word2Vec features: euclidean and angular distance between the candidate's embedding and session's last item's embedding

Matrix Factorization features: euclidean and angular distance between the candidate's embedding and last session's item's embedding

Features selection based on Feature importance of my experimental models
Some of my best candidates:

index of last interaction with the candidate in the session

relative number of interactions with given candidate among all session's interactions

timestamp differences

angular distance between candidate's w2v embedding and last session's item w2v embedding

number of co-visitation matrices containing given item as a candidate
What did not work for me:

Word2Vec and Matrix Factorization features: euclidean and angular distance between the candidate's embedding and session's penultimate item's embedding

Word2Vec and Matrix Factorization features: average/min euclidean and angular distance between the candidate's embedding and all session's items embeddings

Word2Vec and Matrix Factorization features: euclidean and angular distance between the candidate's embedding and session's last cart/order item's embedding (there was a minor improvement, but I abandoned these features)


Model



Group 3-Fold (by sessions) LightGBM Classifier (binary_logloss)

One model per one target (clicks/carts/orders)

No negative downsample (during almost the entire competition) so it required a lot of memory and time

1/5 negative downsample for carts/orders and 1/15 for clicks (last week of competition)

But I use another trick to reduce memory/time usage: When I train a model for carts/orders, I use only sessions for which I have at least one ground-truth candidate among my candidates. Because the main goal of model is to distinguish between good candidates and bad candidates. So I think that sessions with only bad candidates don't help my model.
(It could be by 2 reasons:
1) the session has not ground true cart/order at all
2) the session has ground-true cart/order, but I didn't select it among my candidates)

'dart' boosting for carts nodel, 'gbdt' boosting for clicks and orders model.

add "carts" prediction as a feature for "orders" model (the best feature)
What did not work for me:

Add second click to the positive samples as well as first click

add "clicks" prediction as a feature for "orders" model

multiple attempts to build a second model to re-arrange only top-X candidates from the first model




Makotu part

My pipeline consists mainly of preprocess/make co-matrix/candidate / make feature / modeling parts.



Data



I used Radek's train/validation/test data


Preprocess



make aid vector using w2v

make BPR(Bayesian Personalized Ranking) feature (recommended Sirius)


Make-co-matrix and candidate



I made many pattern co-matrix. Basically, co-matrix is created in the  form of probabilities. For example, the following pattern is used to quantify the relationship between aidA and aidB.


aid B count within same session / all aid A count

aid B count within same session (after aid A click) / all aid A count

aid B count within same session / all aid A count. (But if the same user has the same pair of idA and idB, make them unique and then aggregate)

aid B count within same session / all aid A count. (with time weighted)

aid B count within same session and within 1 hour / all aid A count.
like this.

Select a candidate based on session last action aid / top action aid / with in 1 hour action aid / within 1 day action aid

candidate recall


order: 0.732 (@190 candidates)

cart: 0.546 (@190 candidates)

click: 0.682 (@140 candidates)


Make feature



User / aid / user&amp;aid interaction features.

features that worked


last action aid

distance from last aid w2v to candidate aid w2v

BPR feature (recommened sirius)

co-matrix features (ex. probability of clicking on candidate aid after the last aid)

etc


Modeling



Catboost (loss: PairLogitPairwise)

Group Kfold(group: session)

Add oof features in addition to the above features


click model does not use oof.
However, two patterns of click models were created. in addition to predicting the next clicked id, it also predicts all subsequent clicks of the id, and then uses as oof.

cart model add above 2 model oof.

order model add click 2 model oofs, cart model's oof

Stacking



At the team merge, the scores were only 0.600 (makotu), 0.600 (sirius),0.598 (Alvor and Shimacos), but By rank blending each score as follows, we were able to produce a 0.603, which was the second at the time.


Use the top50 of each prediction.

And the each prediction was simply outer joined to create a pair of user items.

fillna with 1 / 50

rank blending with formula 1/rank_a + 1/rank_b + 1/rank_c and sort descending.

As the number of models increased, it became difficult to find the optimal weights, so stacking was performed.


Dataset is the same as above.

Feature: prediction score and rank

This resulted in a score of 0.604 by LightGBM. (CV: 0.59624)

The same was created in CatBoost (CV: 0.59592) and averaged.

Finally, I interpolated predictions by aid with the highest number of actions for each type in the test period.

Samples



Click model: the generated candidates which the user clicked are labeled with 1

Cart/Order model: the generated candidates which the user carted or ordered are labeled with 1. I merged cart and order labels because of their sharing of similar semantic

Downsampling of negtive samples is abopted. I just keep the negative samples with amount of 20*len(pos_samples)


Features



All the features are listed in the figure.

The feature with highest importance in my model is BPR①, implemented with Implicit package.  (Notebook will be public after everything is verified.)

Bi-gram② is a terminology of NLP, meaning the successive visiting of aid1, aid2 here. It is similar to co-visit matrix, but it only counts the next one action. And I normlize the count by the hotness of item then. This group of features gave the biggest boost among all my experiments, ~0.006.  (Notebook will be public after everything is verified.)

OOF of other action③ help improve my score ~0.001.

Features ①+③+ shimacos’s w2v improved Makotu's CV ~0.001 and features ①+② improved Alvor's CV ~0.003.


Models



Catboost is trained with Logloss. When training Cart/Order model, I set different weights to positive sample, 5 and 10 for is_carts and is_orders respectively. Along with the strategy of mergeing Cart labels and Order labels, it boosts CV ~0.002, compared with training Cart model and Order model separately.

MLP is trained with the same features as catboost, plus an standard scaler to normlize the features. But it is not accurate and diverse enough to improve the blending score. So in our final submission, it is not included. Beside MLP, I have tried to introduce GRU and pretrained item embedding into the NN model, but all failed.
