Topic #279327: 7 tips to make your notebook better (perspective of last year's laureate)
  Author: Michal Bogacz
  Posted: 2021-10-17 17:57:20.228000
  Votes: 94  Comments: 34

Hi, I would like to share with you some tips that I use to create notebooks based on this competition. I hope they will help you or change your mind a bit. If you have any comments/questions, feel free to share in the comments 😄 

1. Select a specific problem that is only part of the reality contained in the database

This is one thing I think we should start with and it's often overlooked. When we have a large data set, the reality it describes is very complex. If we want to analyze each variable and their relationships, this is a topic for a long book, not a notebook. Instead of analyzing the variable by variable, it's worth finding a point around which we'll make narration. This can be a comparative analysis (e.g. young vs. old), an analysis of changes over time (combining the results from the last years) or even the selection of only a few variables that we'll deal with properly (e.g. learning platforms). Don't be afraid that our analysis will be too short or narrow, this way it will definitely stand out and show data from a unique and interesting perspective. 

2. Try to approach differently from others - create a unique analysis

Defining the purpose and plan of the analysis is essential. Most notebooks are "Database name - EDA" analyzes that keep repeating the same patterns (like gender by age). See that despite the fact that there are a lot of such works, they never win prizes in competitions. Instead of starting our analysis without a plan and trying to create random charts, plan ahead in which direction the entire analysis should go. Could it be the way of narration, graphic elements or less known methods. It's a difficult process that requires creativity but well worth the effor!

3. Do research among various sources and quote them

Research should be done on two levels: the topic itself (in this case, the aspects that are asked in the survey, programming languages, e-learning platforms, workplaces, etc.) and notebooks on this or a similar topic, for the purpose of inspiration and making sure that we are doing something that differs from the rest of the work. It's essential to quote the sources - even if we didn't even copy a word or a line of code, the idea is also part of the intellectual property.

4. Think carefully about the methods

The choice of methods influences whether to conduct the analysis correctly. Before choosing, it's necessary to check what data types we have and whether they are really well defined (the appearance of 0-1 is not always a quantitative variable, even if the set was loaded automatically). In the case of this competition, we only have qualitative data (apart from fill time), so we absolutely cannot use methods intended for features on the ratio scale, even if the code doesn't crash an error. No Perason's linear correlation coefficient, histogram, typical scatter plot, linear regression model can appear in this case! We also don't treat the methods used by others as the only possible scope - some people choose incorrect methods or limit themselves to the most popular ones. It's worth describing the methods at the beginning of the analysis, so that the reader understands what and why such methods were used.

5. Transfer simplicity over complicated solutions

Fancy and very unusual and complicated charts look nice on the screen, but usually it's hard to get valuable information from them. Keep chartss simple so that the user without a magnifying glass can immediately understand what's going on. Don't use "reality bending" plots (like pie charts, 3D) - replace them with simple solutions (e.g. bar plots). Let's not worry that they will be too trivial, if they are aesthetic, they can be really interesting an, (above all) well reflect the existing dependencies in the data.

6. Be sure to describe all the results

This is a problem that occurs in a large amount of work. Writing code is of course more interesting, but without description, our analysis doesn't exist. If we don't show the user what our thinking is, what the conclusions are, what we learned during the analysis, what the results really mean, the analysis begins to lose sense. This also applies to the visualization, we should name all axes, give a title / subtitle, describe the legend if necessary. This stage is always boring for me, but I can't imagine leaving any code cells without any comment.

7. Take care of the aesthetics of the notebook

The aesthetic layer is a very important part of the document. These are not only nice charts, but also descriptions and navigation. Colors should be consistent, text that is best aligned, code cells hidden, important elements properly highlighted, prepared table of contents, etc. It doesn't take so much effort to turn an ugly notebook into a user-friendly version that won't close in a few seconds.

Applying these tips requires a lot of effort, time and creativity (I catch myself sometimes ignoring them), but the end result should be satisfactory. I hope my advice will help at least one person. Good luck in competition, can't wait to see some fantastic notebooks! 😊
