Preprocss



Do not throw away frames witout hands!

Use as much info as possible, (hands, lips, eye, nose, pose) , use (x,y,z)

Use more frames, resize to 320 frames for model training.

I used original + normalized + abs position(/1000.) as input feats(total 384 * 2 + 1 = 769). 
normalized feats help converge much faster but I found original feats also helps.


Aug

I followed last competion 1st solution, and found the most important aug are 



time scale (interp1d)

time dim mask
I used heavy mask here which will mask some time seq and aslo will randomly mask 50% frames

affine 
follow preve 1st solution with prob 0.75, for left-right flip only with prob 0.25


Training



I used train data + sup data combined training with sup data weight set to 0.1 for 400 epochs.

batch size 128, max lr 2e-3, lr scheduler using linear decay with 0.1 epochs warmup , adam optimizer

Awp training started from epochs * 0.15, with adv_lr 0.2 and adv_eps 0.

Fintune with train data only for 10 epochs with max lr 1e-4, awp start from epoch 2.  


Postdeal

I used rule for blank index(0)


Model



Squeezeformer  works best, it is a bit faster then conformer. (Code from NEMO)

In order to make net deeper I used 1 down sampling layer to reduce frames from 320 to 160.
This is mainly helpful for adding more encoder layers, and also can allow using complex encoder layers.

Relative pos encoding affect the performance so much, I found ROPE(by Jianlin Su) perform best and super fast. (code from huggingface implementation)

Dropout is super important, I used final cls_drop=0.1 only, no dropout for other layers.

I learned from 1st-place-solution-training that stochastic path is super important to avoid overfit for deep network. So I used it in squeeeze former block for each layer like below(notice the InstDropout and 0.5 skip factor all super important for final performance)

Others



For me (using 4090), torch much faster then tf (3-4 times faster)  

I used tf at first and swich to torch in the last month which help to speedup experiments a lot.    
Speed is only one factor, another important thing is I could easily try opensource code of ASR like NEMO or espnet.

I used nobuco to convert torch model to keras, it works like a charm.  

I still used tf for prorcess/aug and post process and also use tfrecord as input format, I wrote a torch iterable dataset which wrap tfrecord reader.
