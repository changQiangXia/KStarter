Thanks Kaggle and Petfinder.my for this really interesting competition. When I started competing 2 months ago I could'n stop due to the cuttenes of the pets and the level of the challenge posted here. Also this win is very special to me because it's my first solo win in an image competition. FInally, congratulations to all prize winners and medalists because I have a good idea of the amount of time and energy invested here.

So basically the challenge is a regression and we were asked to predict the Pawpularity of each pet given the image and some tabular meta features. I ended using only the competition images and dropped all meta features from my solution. We don’t have much information about how the Pawpularity target is generated, but we have some clues in the description and it may be related to the cuteness meter implemented here: https://www.petfinder.my/cutenessmeter 

Trainset consists of 9912 images of dogs and cats, and testset around 6800 images.

The Pawpularity ranges from 1 to 100 and it is rounded to integers. The target follows that distribution with a mean average of 38.04 and a standard deviation of 20.59, that means if you predict 38.04 for all images then the RMSE score is 20.59. Any model that scores lower than 20.59 is considered to have some predictive power.

So my solution consists of two parts, one tabular based in Transfer Learning and Support Vector Regression(SVR) and one image regression based in Deep Learning images architectures.

PART 1. Transfer Learning + SVR:

The idea consists in extracting features from pretrained architectures to transform the problem into a tabular approach, then fit a model using that data. To extract features from images I used imagenet pretrained models available in timm and OpenAI CLIP libraries. At the moment there are around 575 pretrained models available in timm library and most of them were trained using 1000 classes imagenet images. I found the most useful for this competition were the ones trained in that 1k classes. My hypothesis as to why they are better is that imagenet 1k have some classes of breeds of dogs and cats. Also extracting the features from the top 1k linear head performed better here than extracting the internal embeddings layer (the layer before the linear classification head).
OpenIA CLIP works differently. That architecture is trained using a combination of text and image, see how in: https://github.com/openai/CLIP. This architecture permits you to query an image with a text, for example, you can input the model with a dog image and the text: “is a dog?” and the output would be the score of having a dog in the image. So basically CLIP has two encoders inside, one for the text and one for the image and it outputs two corresponding embeddings vectors that you can use dot product to calculate the output score. For my solution only the CLIP image encoder was used. I prepared a notebook to explain better how to use CLIP here

Each architecture has differences that can be explored by combining multiple architecture into the same dataset (stacking features side-by-side). The diversity between models can be used that way to boost RMSE. So to select the best models to include in the stacking dataset I used a simple forward feature selection with hill climbing. The algorithm is show below:

Features = [‘tf_efficientnet_l2_ns_475’] # Start using only 1 model
Best_feat = None
bestRMSE = np.inf
currentRMSE = 0
while currentRMSE &lt; bestRMSE: # Keep adding models while rmse decreases
    bestRMSE = currentRMSE
    Features.append(best_feat)
    rmse_scores= [compute_SVR_RMSE(Features + [feat]) for feat in all_pretrained_models]
    currentRMSE = np.min(rmse_scores)
    best_feat = np.argmin(rmse_scores)


So the algorithm keeps incrementally adding model features while RMSE keeps decreasing. RAPIDS SVR is an important key in this process, because in the end its necessary to run thousands of SVR folds in order to find the best combination of features. Without the speedup given by cuML SVR it wasn't possible before or it would have taken more time than the full competition time span. 

By running that algorithm multiple times using a different starting model I ended with three subsets of pretrained features that scored very well in terms of RMSE:

For training procedure I used CosineAnnealingWarmRestarts scheduler and around 16 to 48 epochs per fold, scoring validation set 6 times per epoch to pick the best validation score.

Those models were chosen using feature selection from a set of around 25 valid models built during the competition. As submission is limited to 9h and the SVR part of solution consumes aprox. 4h submission time, I had to choose a subset of all models available for the final submission. Loss function used in all models was BCE, inline with what others found during the competition.
TTA worked for me, but gave very small improvement in CV/LB, around 0.0005
During submission scoring I decided to use only hflip TTA, so I selected 3 out of 5 models to score using horizontal flip. TTA works better when hard augmentations are used during training. 
Ensemble CV of image based models: 17.029 / Public LB: 17.87 / Private LB: 16.92 (Top10 private)

Final weighted average:
0.1224SVR_A + 0.0011SVR_B + 0.4556SVR_C + 0.4446ImagesEnsemble

CV: 16.81, Public LB: 17.72, Private LB: 16.82 (winner submission).

Things that didn't work for me:



Adding competitions meta features to models.

Semi supervised learning using PET 1 images.

Pretraining models on PET 1 meta features.

Mixed Multiples heads on DL models.

Finetuning on CLIP models.

CNN worked much worse than vision transformers here.

Interactive labelling using Pet 1 images + transfer learninig + cuML SVR.

XGBoost or RandomForest on transfer learning features.

RMSE loss

Multiclass loss

Removing outliers

Cliping targets to [1, 85] for image models.

Adding too much regularization in image models.
