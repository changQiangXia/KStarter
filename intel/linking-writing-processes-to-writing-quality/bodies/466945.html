Feature Engineering
Shout out to my teammates @sid00733 and @kanbehmw for brilliant feature engineering 🏅🏅🏅

  • Volatility features - change of % in activity over time.
  • P-Burst - (R-burst didn’t work)
  • Count vectorizer features
  • TF-IDF features with characters and ngram(4,4) i.e. 4 character words
  • Essay features - word level, bigrams, trigrams
  • Sentence, paragraph features with essays
  • IDF features for activity, events and text changes
  • Sequential features for Input, Non-Production and Remove/Cut activities
  • IKI features (IWI features didn’t work)
  • KeyStrokes features
  • Change in Typing Speed Features(WPM)
  • Feature selection using BorutaPy only on TF-IDF and CountVectorizer features

NN Models
In our neural network pipeline, we've implemented a multi-faceted approach for processing a dataset with 1356 features, incorporating different types of feature scaling and complex neural network architectures:

Feature Scaling:
For float columns, we applied three types of scalers: Robust Scaler, Standard Scaler, and Power Transformation Scaler, each tailored to normalize the data considering different aspects of distribution.
For integer columns, MinMaxScaler was used to ensure the values are within a specific range.

Neural Network Architectures:

  • First NN Model: It's a hybrid model combining a 1D CNN with LSTM, GRU, RNN, and a Transformer encoder. The output is a weighted average from these models, aiming to capture both spatial and temporal relationships in the data.
  • Second NN Model: This layer employs LSTM and RNN with a self-attention mechanism. It starts by embedding the sequences, then processes them through bidirectional LSTM and unidirectional RNN, applying self-attention to each before integrating the results.
  • Third NN Model: Similar in structure to the second layer but replaces the RNN with a unidirectional GRU, again using self-attention and integrating the outputs.
    The different configurations achieved a cross-validation score of 0.590 locally and 0.568 on a private leaderboard.

Ensemble:
We picked weights manually. We tried NelderMead as well as stacking with Ridge, but our final selection was hand picked weights. One of the reasons ensemble with Ridge/NelderMead didn’t work is because of disparate models and their scores. NN models had low cv but high public LB whereas LGBM models had comparable (to NN) or higher CV but much better public LB. Ridge/NelderMead would assign higher weight to NN models (with lower cv) which didn’t work on public LB.
Since public LB was 50% of test set, we manually picked weights - 65% for LGBM models and 35% for NN Models

Post processing
We rounded values in range (3.95,4.05) to 4.0 and (3.45,3.55) to 3.5 . Other possibilities of rounding didn’t work. Also clipped predictions to (0.5,6.0)
