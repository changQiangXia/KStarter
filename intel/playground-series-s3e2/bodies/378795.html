Data and Feature Engineering

In addition to the synthetic data, I added stroke observations from the original dataset to help improve upon the imbalanced dataset. I consistently saw improvements in my CVs and performances on the Public LB when I did this regardless of model type. I did 10-fold CV using StratifiedKFold. [1]

The trick, however, is that all of my CV calculations used only the synthetic dataset. I included the original stroke observations in each CV fold, but did not use them to calculate CVs. Given the differences in distributions of some features and some inter-feature correlations, I believe monitoring only the synthetic set avoided over-training to the original dataset. [5]

One-hot encoding

Categorical features were one-hot encoded. [2] I opted for sparse or k-1 class encoding to reduce the total number of features and to prevent perfect correlations between features.

Impute BMI

Some observations from the original dataset did not have BMI values. KNeighborsRegressor was used to impute BMI for those observations. [6]

Total risk factors

I though computing clinical risk factors [4] was a great idea and included this in my feature engineering. Compared to my baseline model (simple logistic regression), including risk factors gave me an improvement of only 0.0008. I did not compare to a baseline for other model types, however.

Center and scale

Continuous features were centered and scaled.

Modeling

Model Tuning

The first place model was a simple XGBoost model. I tuned hyper-parameters using a randomized search over a hand-coded set of ranges. I performed 500 iterations of random hyper-parameter samples, and did 10-fold CV for each iteration. Predictions were made for the test set in each CV fold for each model.

Ensemble

The final ensemble was developed by simply averaging all the test set predictions for the 5 best models (ranked by average CV AUC) for a total of 50 predictions in the ensemble.

Other things I tried

  • I performed this exact same process of tuning and ensembling using LogisticRegression (0.89209 on Private LB), CatBoost (0.89799), and a simple NN (0.89423). All of them did quite well with very small separation in scores. Obviously the non-linear approaches performed best.
  • I also tried blending all the approaches mentioned above, using either the best model or the best 5 models for each model type - this included the XGBoost predictions in the winning submission. Using the best single model (10-fold cv predictions for each, so 40 predictions), gave a Private LB score of 0.89975, and using the best 5 models for each (200 total predictions!) gave a Private LB score of 0.89879. Both would still have been in the top 10.
  • I tried ranking my scores [3] but I did not see any improvement in my CVs nor LB standings.
  • I ran TPOT to do some exploratory modeling early on. Even running it multiple times with multiple settings, XGBoost was always the best model found.
