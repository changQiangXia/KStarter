Here, we aim at segmenting cells, such task can be divided in two steps :

  1. Detecting individual cells
  2. Correctly predicting their boundaries

I'm focusing here on the 2nd step :
The mAP IoU evaluates the correctness of the boundaries by penalizing low IoUs using different thresholds (0.5, 0.55, 0.6, 0.65, 0.7, 0.75, 0.8, 0.85, 0.9, 0.95).

However, I think this is a mistake, let's take two cort cells as example, this also works with shsy5y cells.

  • Cells are small : about 10x10 px each, because of the resolution the data is acquired at
  • Annotations are not pixel perfect : there is a lot of ambiguity on where the cell actually stops, sometimes the brighter pixels are included, sometimes excluded
  • Lets say such ambiguity results in a ~20px variation : this will result in a ~0.2 IoU variation for the same prediction
  • Which means reaching the 0.8, 0.85, 0.9 and 0.95 thresholds is basically luck. I.e 40% of the evaluation metric is random
  • The two predictions here score IoU 0.76 and 0.79 which only gives a 0.6 mAP despite them being decent enough to be considered as good as the labels

Conclusion : because cells are smalls and labels not pixel perfect, the metric fluctuates a lot.
It makes no sense to evaluate the IoU at high thresholds for small cells.

An easy fix would be to consider the mAP at thresholds ranging from 0.5 to 0.75 (or 0.8).

A more complicated (but better) fix would be to choose threshold according to the ground truth size, for instance :

  • < 200 px cells should use 0.5 -> 0.75
  • < 400 px cells should use 0.5 -> 0.85
  • >= 400 px cells should use 0.5 -> 0.95

High thresholds are useful to make sure boundaries are correct on big cells (astro) as well.
