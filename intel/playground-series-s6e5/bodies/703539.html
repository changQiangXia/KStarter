Overview

My final solution was what I called an L5 ensemble.

By L5, I mean that I first built several L4 ensembles under three different split settings, and then averaged those three L4 ensembles. The three split settings were:

The reason I used three different split strategies was partly because I wanted to generate many diverse solutions, and partly because I wanted to observe how different split designs affected the CV-LB relationship.

I also wanted to reduce the overfitting risk of relying too much on one stacked ensemble. A stricter way to estimate the score would have been nested CV, but because of computational cost, limited resources, and my desire to run many experiments, I did not use nested CV. Therefore, the CV scores shown below are probably optimistic. I mainly used the Public LB to check whether the CV was becoming too optimistic.

Main idea

The key idea was to create diversity from two directions:

  1. Different split settings

    • 5-fold
    • 7-fold
    • 10-fold

  2. Different ways of using the original data

    • Using the original data as additional rows.
    • Using the original data to create column-level features, such as target encoding or anchor-style features.

These two directions seemed to capture different signals. The gain from ensembling models trained with these different feature engineering policies was quite large.

Stacking / distillation structure

The stacking structure was roughly:

  • L1: Existing OOF/test prediction files from many base models.
  • L2: Meta models trained on prediction-level features, and also models trained on meta features plus original features.
  • L3: Low-degree-of-freedom Logistic Regression on logit-transformed L1/L2 predictions.
  • L4: Self-distilled student models using L2/L3 teacher OOF predictions.
  • L5: Average of three different L4 ensembles from different split settings.

For L2 meta features, I used not only raw predictions but also transformations such as logits, ranks, summary statistics, pairwise differences, and AUC-weighted blends.

A simplified version of the final blend logic was:

def make_blend(preds, weights=None, logit_space=False):
    if weights is None:
        weights = np.ones(len(preds)) / len(preds)
    else:
        weights = np.asarray(weights)
        weights = weights / weights.sum()

    if logit_space:
        z = sum(w * logit(p) for w, p in zip(weights, preds))
        return sigmoid(z)
    else:
        return sum(w * p for w, p in zip(weights, preds))

In several places, I used both probability-space averaging and logit-space averaging. I also used conservative blends to avoid relying too much on the highest-CV stacked model, because final Logistic Regression or higher-level stacking can easily overfit when many correlated OOFs are used.

What worked well

1. RealMLP was the strongest base model

RealMLP was clearly the most important model family in my solution. The public notebook by @yekenot was the foundation of my modeling, and the best single-model CVs came from RealMLP.

Different RealMLP parameter settings also blended well with each other. This was one of the main reasons I used top-3-parameter averaging.

2. Original-row and original-column approaches gave different signals

One important observation was that using the original data as extra rows and using the original data for column generation were not equivalent. They seemed to capture different types of signal.

Because of this, models based on “orig row” and “orig col” approaches blended very well.

3. Many weak-but-diverse models were still useful

Some models were not strong as standalone models, but still contributed to the final ensemble because their errors were different.

Examples include:

  • TabPFN
  • Fine-tuned TabICL
  • RealTabR
  • Trompt
  • ModernNCA
  • FFM
  • LNN
  • FTT

The final score was not achieved by a single clever model, but by accumulating many slightly different perspectives.

4. Conservative stacking was important

Higher-level stacking can improve CV, but it can also overfit very easily, especially when many OOFs are highly correlated.

Therefore, I did not simply trust the best CV stack. I also used conservative blends that mixed:

  • final Logistic Regression stack
  • L3 stack
  • teacher blend
  • AUC-weighted L2 blend

This helped keep the final prediction more stable.

Final result

The final submission was the average of the three split-level L4 ensembles.
