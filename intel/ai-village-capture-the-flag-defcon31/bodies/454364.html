Granny 1/2

I chose to reverse engineer the model, once this is done, both problems are simple adversarial attacks. The model is the torchvision one (you could figure this out with the class names!), as available here. But scores still don't match so we need to figure out what changed in the preprocessing.
To reverse engineer the preprocessing few things could be done:

  • Submitting a 768 image and a 256 one gave the same output (resizing is the same !)
  • The pixels on the sides do not impact the result (cropping is the same)
  • Finding the normalization parameters by gradient descent: did not work, something else changed
  • Check other weights! With the right torchvision version you have access to MobileNet_V2_Weights.IMAGENET1K_V2 weights, with which the API results were matched up to 1e-5

Granny 3 is another story. I realized after one day of work on it that it was most likely not doable. Input of the model is 224x224 so you have a search space which is not that huge (224x224xrgb) but in which there is most likely a solution.
However, you submit a 768x768 image, which is downscaled by 3 using linear interpolation. This means that the maximum variation you can have in your resized image is +/- 20 – which seems too small to get a working attack.

Passphrase

It took me 2 weeks to solve passphrase, and I probably spent more time on it than all the other challenges together.
There are two things to consider:

  • Which score are we trying to reach?
  • Which additional constraint must be respected for the flag to be returned if the score is reached?

Which scores to reach ?

First one is already a huge gamble, good candidates are:

  • [0.3333, 0.3333, 0.3333] since everything is equivalent
  • [0, 0, 1] since we need to charm the model
  • Scores given by sentences in the challenge prompt
    • “this notorious sauce” since we need to decipher the sentiment score of it
    • “everything” (everything is equivalent…)
    • The score of the benchmark output - My secret sauce is the best! = [0.0022, 0.0325, 0.9653]

I implemented hill climbing techniques with diverse word transformations, to give a few:

  • Replace a word with a random or similar (using embeddings) one
  • Add some emojis, or random characters
  • Swap / append / remove words or characters

Now, it turned out that it’s really hard to reach specific scores that are not in the model output "usual" distribution. Of all the above, I could only reach consistently the benchmark output scores, which led me to focus on reaching [0.0022, 0.0325, 0.9653]. This is a reasonable hypothesis, but it does not account for the “sentence where everything is equivalent” part of the prompt.

Equivalence

I considered some ideas:

  • Use a sentence where the words are the same length as the input sentence (made a lot of sense but didn’t work)
  • Use an anagram of the input sentence (made sense but quite far fetched, I couldn’t reach the target score)
  • Words starting with @ were replaced in the server preprocessing! So, I found a sentence with @xxx at the start but not flag
  • Words of the same length, this was my last idea and it worked !

I initialize the search space with the following string: very cool best sauc. The first 3 words are very polarized and it scores quite close to the target we are trying to reach. The last word is replaced with all the 4 letter words in nltk, until the target score is reached. Implementation is simple, but initializing the search correctly is key.
