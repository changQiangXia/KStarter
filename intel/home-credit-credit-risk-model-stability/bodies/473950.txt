There are 32 files in train csv_files folder. The same files provided in .parquet format in the respective folder. So the competition data might be confusing for some of us. Some csvs are greater than 2 GB in size. train_base.csv has 1526659 unique case_id which equals the length of this file.

Explanation and schema

There are 465 features and 436 respective descriptions in feature_definitions.csv. There are no missing descriptions so it means some feature might have same descriptions (for example description Number of tax deductions for features: pmtcount_4527229L, pmtcount_4955617L, pmtcount_693L).

We are going to use case_id to merge underlying tables. We got internal and external data sources and this is how the schema looks like:



We got tables classified by depth, where:



depth=0 - These are static features directly tied to a specific case_id.

depth=1 - Each case_id has an associated historical record, indexed by num_group1.

depth=2 - Each case_id has an associated historical record, indexed by both num_group1 and num_group2.


Various predictors were transformed, so to have the following notation for similar groups of transformations: P M A D T L

Train File sizes and Null Values



How to read it:



The sizes of squares are scaled across all train files, where the biggest area is the biggest file;

Red squares are normalized total counts of all records across all columns in the respective train file;

Black squares are normalized total counts of null records across all columns in the respective train file.


For example, It means the train files are  &gt;30% empty on average. The credit_bureau files are the biggest ones.
