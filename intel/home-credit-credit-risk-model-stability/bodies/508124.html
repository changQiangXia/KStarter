My initial sub-goal was to create a good enough diversity of models and datasets for the final ensemble. It's a common approach and I worked on it during the whole competition. Unfortunately, I didn't spend enough time on metric hacking, so my final position is not so good (only 62nd), although I was in top-10 before starting metric hacking.
My final ensemble without metric hacking has a score of 0.528. The public metric hacking approach with adv classifier simply didn't work for PrivateLB.



What helped improve the models:

  1. Sorting by numgroups before aggregations - at least it worked for "first" and "last" aggregators. For some models it was used with combination of aggregation by numgroup2 and then by numgroup1 (after that some tables can also be concatenated, for example applprev, credit_bureau_a, credit_bureau_b).
  2. Using a 10-fold meta-classifier (LinearRegression) instead of a simple weighted ensemble improved the score to about +0.002. Also, while training meta_cls, I added some noise to the OOF predictions of some models to match the LB scores.
  3. Models using datasets without date columns - the scores of these models weren't as big, but they complemented the ensemble well enough.
  4. Using "Coefficient of Variations" aggregator - it helped a lot to improve the score of the CatBoost model.
  5. LAMA-MLP model improved initial ensemble in early stages of competition, and I spent some time to select features to overcome OOM errors and overfitting.
  6. One place where I directly incorporated the stability approach was using the metric for ReduceLRonPlateau for training MLP and 1DCNN models.
  7. Count encoding of categorical columns (from public notebooks)
  8. Filtering of correlated columns (from public notebooks).
  9. Collapse rare categories in one group.
  10. To overcome OOM errors, creating separate datasets and then merging them helped. Also memory issue was a big problem for 1DCNN model, but I overcame it by training model on TPU and then inferencing on GPU. Also TPU was used for permutation importance.
  11. CatBoost model has best private and public scores among other models. Also in one of the experiments 5-fold CatBoost achieved score 0.520 (difference was on using early stopping 100 and lambda 10) but unfortunately I didn't include that model in the final ensemble (LB was the same and CV I didn't know because that was inference training).
  12. Tuning some models using Optuna.
  13. The inclusion of the XGB model was relatively important. I also had problems training this model, because (as I understand later) it is not so good at categorical features (unlike LGBM and CatBoost), and preprocessing was critical for this model. More specifically, after using TargetEncoder (and then CatBoostEncoder), the XGB score increased to good enough values. The same approach was also used for 1DCNN model.
  14. Using slightly different features for all the models (some tables, aggregators, types of columns, filtering approaches were not included for all the models).
  15. Replacing NaN in num columns with 0 helped for 1DCNN model.
  16. Aggregators used: max, min, first, last, mean, var, sum, std plus coef_var (distributed differently among all models, column types, or used only for certain columns).



What didn't work (at least in my experiments):

  1. Feature selection based on adversarial validation (within train ds), permutation importance (including stability metric).
  2. I tried to create some loss functions (based on functions simpler than initial metric - from topics about metrics; incorporating weights and so on) for GBDT models, but without improvements.
  3. CV strategies based on splitting train ds on week numbers using distributions of some statistics.
  4. Tuning GBDT models using some specific parameters like dart for LGBM, ordered boosting_type for CatBoost and so on.
  5. Using IsolationForest with SMOTENC
  6. Different scalers for 1DCNN model like PowerTransformer, QuantileTransformer. Finally I used Log1p transformation only for columns with max_min-mean ratio greater than 100.
  7. Replace nums NaN with mean (or constant values like -99). BTW LAMA pipeline uses this approach, and I tried to use 0s, but LB didn't improve and I rejected this idea, but after deadline I saw that private score was improved for that submission.
  8. Compress some categories (e.g. by template P0_111_121 to P0 or P0_111)
  9. Some non-standard, custom aggregators such as entropy, mean-to-max, zero frequency, normalization within group, and so on. The goal was also to find aggragators with relative, not absolute, values.
  10. Additional feature engineering like ratios between some columns didn't improve models. As I understand after first competition was created very good features and squeezing out from dataset additional gains was not so simple task.
  11. By the results of previous competition I tried Regularized Greedy Forest (FastRGF version) but it has very poor performance and worsened final ensemble. Another idea from that competition was to train MLP only on some group of tables, but again without any results, so I discarded this idea as well. I also experimented with other models like DAE, TabTransformer, NN-cat_embeddings, packages like pytorch_tabular, but also I can't train them to good enough results.
  12. Combining some categorical features (similar to how CatBoost works).
  13. Balancing classes using parameters like scale_pos_weight.
  14. Include 1DCNN in the final ensemble. I struggled a lot to overcome the overfitting of this model, but eventually it is worsening the final ensemble from 0.529 to 0.528. Some variations of this model (with another ds) has relatively good private score (0.485) but LB was not so good (only 0.555), so I didn't include the best and maybe was digging in the wrong direction. Besides, without metric hacking this model will not contribute much to the final ensemble/position.
  15. Include some additional data such as FedFunds.
  16. Filter some weeks.



Of course ideas from the community, discussions, public notebooks helped a lot.
