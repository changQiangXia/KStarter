TL;DR

This post summarizes winning solutions from multiple Kaggle multi-class and multi-label classification competitions, extracting key strategies that consistently deliver strong results.

Key Takeaways:

  • Ensembling Works: Blending multiple models (e.g., XGBoost, LightGBM, Neural Networks) is a common winning approach.
  • Feature Engineering Matters: Techniques like BMI calculations, symptom logic, distance metrics, and GMM clustering often make the difference.
  • Stacking and Meta-Models: Using stacking frameworks and meta-learners (especially XGBoost) helps capture complex patterns.
  • Cross-Validation Discipline: Repeated Stratified K-Fold, Out-of-Bag (OOB), and multilabel cross-validation ensure generalization.
  • Threshold Optimization: Tuning classification thresholds globally or per class improves predictive performance.
  • Advanced Techniques: Earth Mover's Distance, pseudo-labeling, AutoML tools, and genetic algorithm-based ensembles were selectively used.
  • Leak Exploitation: Carefully identifying and leveraging dataset flaws or leakage (as in Playground Series Feb 2022) can result in significant gains.

These strategies provide a practical guide to tackling complex classification challenges in Kaggle competitions.

Multi-class classification problems are common in machine learning competitions, each presenting unique challenges and learning opportunities. I analyzed top-performing solutions from several popular Kaggle competitions to highlight key strategies and insights.

Digit Recognizer

Goal: Identify handwritten digits (0-9) using the MNIST dataset.

  • How to score 97%, 98%, 99%, and 100% by @cdeotte
    • Emphasis on progressively complex methods: starting with logistic regression (~92%), advancing through non-linear methods like kNN and Random Forest (97%), SVM and fully connected neural networks (~98%), and finally CNNs (99%+).
    • Recommended CNN design: convolutional layers, followed by pooling, more convolutional layers, and dense layers with dropout and batch normalization.
    • Warned against using full original MNIST data, as it includes Kaggle’s test set, artificially inflating scores to 100%.

Multi-Class Prediction of Obesity Risk

Goal: Predict obesity risk classes based on various health-related features.

  • 4th Place Solution: Stacking with XGB + Pseudo labeling by @kirderf

    • Used stacking with XGBoost as a meta-model, incorporating predictions from AutoGluon, AutoXGB, LightAutoML, and custom XGB/LGBM.
    • Implemented advanced feature engineering, including polynomial features, age group encoding, and BMI calculation.
    • Leveraged threshold optimization to enhance final accuracy.

  • 6th Place Solution: Ensemble + Neural Network by @nirmalfalzoni

    • Combined classic tree-based ensemble models with a neural network optimized via Optuna.
    • Ensemble weights fine-tuned through grid search, enhancing stability and overall accuracy.
    • Prioritized robust local cross-validation results over leaderboard performance for model selection.

  • 19th Place Solution: Optimized Thresholds & CV by @samlakhmani

    • Optimized thresholds individually per class using Optuna, significantly improving accuracy.
    • Compared different cross-validation strategies, ultimately selecting 5-fold CV as optimal.
    • Explored the impact of appending original dataset entries multiple times to enhance training robustness.

Explore Multi-Label Classification with an Enzyme Substrate Dataset (Season 3, Episode 18)

  • 1st Place by @nihilisticneuralnet
    • Feature Engineering: Extensive numerical feature engineering using Gaussian Mixture Model (GMM) clustering. Created additional features by combining categorical and numerical columns (ratios, products, and statistical measures).
    • Models: XGBoost and LightGBM classifiers with custom parameters. MultiOutputClassifier wrapper for multi-label prediction.
    • **Validation: Repeated Multilabel Stratified K-Fold cross-validation. ROC-AUC used as evaluation metric, averaged across folds.
    • Ensembling: Averaged predictions from XGBoost and LightGBM models for robust final submission.

Classification with a Tabular Vector-Borne Disease Dataset (Season 3, Episode 13)

  • 1st Place by @mufathurrohman

    • Models: LightGBM, Neural Network, Autoencoder
    • Technique: Simple ensemble averaging probabilities from three models
    • Feature Engineering: None, standard scaling only
    • Key Insight: Ensemble of basic models can outperform individually complex models

  • 2nd Place by @rjzhang97

    • Model: XGBoost with StratifiedKFold
    • Feature Engineering: Clustering symptoms by categories. Logical combinations (AND, OR, XOR) to generate ~6000 new features
    • Key Insight: Complex feature combinations captured variations in symptom presentation effectively

  • 3rd Place by @unworried1686

    • Models: Ensemble of SVC, XGBClassifier, LGBMClassifier, BernoulliNB, NuSVC
    • Feature Engineering: Grouped symptoms by keyword (pain, loss, inflammation). Polynomial interactions between pairs of features
    • Validation: Repeated Stratified K-Fold (10 folds, 10 repeats)
    • Key Insight: Robust validation and selective polynomial features boosted performance significantly

  • 4th Place by @mateuszgrzybpl

    • Model: RandomForest with Out-of-Bag (OOB) scoring (no CV splits)
    • Optimization: Hyperparameter tuning with Optuna
    • Key Insight: OOB validation effectively prevented overfitting in a dataset with small sample size and many target classes

  • 5th Place by @zhukovoleksiy

    • Models: Ensemble of XGBoost, LightGBM, CatBoost, RandomForest, BalancedRandomForest, SVC, LogisticRegression
    • **Feature Engineering: Grouped similar symptoms, disease-specific clusters. Used feature aggregation and dimensionality reduction methods (UMAP, PCA)
    • Optimization: Ensemble weights optimized via Optuna
    • Validation: Extensive K-fold cross-validation
    • Key Insight: Combining extensive feature engineering, dimensionality reduction, and weighted ensemble improved consistency across public and private leaderboards.
