Solution summary



train the gemma2-9b-it using the  lmsys-chat-1m pseudo label data. 

ensemble with llama3 model


chat-1m pseudo label data




remove useless row  
df = df[(df.language == "English") &amp; (~df["redacted"])]


I extract unique prompts and randomly sample two responses generated from different models for each prompt. I only sample two responses to reduce the data volume while still including as many prompts as possible. This creates approximately 45k additional training data.


LB progress

LB refers to the one before the leak.   



Train single gemma2 model and perform response swap TTA  
→ LB : 0.890

Instead of TTA, I train another gemma2 model with response swap data and ensemble it.
→ LB : 0.887

Train both model in the same way as 2. by adding chat-1m pseudo label  
→ LB : 0.881 (private LB: 0.9859)

ensemble with single llama3 model without TTA (LB: 0.899 with TTA)
→ LB : 0.881 (private LB: 0.9828)


Solution details

Dataset

input



kaggle train data  

33k data (https://www.kaggle.com/competitions/lmsys-chatbot-arena/discussion/500973)

lmsys-chat-1m (used only in pseudo label)


prompt





response_a: last response of model A  

response_b: last response of model B  

context: all user instruction and response (but the response include only one model) except response_a and response_b  


tokenizer



truncation_side = "left"

max_len


train: 256 * 6

inference: 256 * 7


Model




gemma2-9b-it



all linear for lora

r=32, lora_alpha=64

epoch=1

lr=8e-5

learning scheduler=linear

no warm up step

global batch size=16


llama3-8b



I used the pretrained weights of the reward model which allow two different model responses to be included in the prompt instead of llama3-8b-instruct.


used pretrained weight: https://huggingface.co/RLHFlow/pair-preference-model-LLaMA3-8B  

all linear for lora

r=128, lora_alpha=128

epoch=1

lr=5e-5

learning scheduler=linear

no warm up step

global batch size=16


Inference Tips



Due to notebook time constraints, it was difficult to infer two gemma2 models and one llama3 model, so the llama3 model was only inferred for samples with token counts of 512 or less and 1500 or more.

For speedup


use 8bit quantization model instead of 4bit. 

merge_and_unload()


In the case of 8-bit quantization, no decrease in score was observed.

Dynamically change batch size based on token length
