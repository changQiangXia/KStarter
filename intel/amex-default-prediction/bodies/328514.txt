Topic #328514: Integer columns in the data - here you go!
  Author: raddar
  Posted: 2022-06-01 16:04:05.623000
  Votes: 834  Comments: 116

As it is already clear - all float type columns have random uniform noise of [0,0.01] added to each column. Having this information it is clear that it is very easy to spot integer type columns in the raw data. This calls for detective work, which I really love and have done many times in previous competitions :) 

It took me a couple of days, but I have it ready for you all to use!

So, what's in it?



originally we had 188 float/categorical type features. These were transformed into


95 np.int8/np.int16 types

93 np.float32 types

Most float columns with [0, 0.01] and [1, 1.01] have these values rounded up at 0 and 1 respectively. This was done to ensure no data loss, as not all features could be rounded up safely.

saved in parquet format (only 1.7GB training data!)


Hopefully, this opens the door for many people to access this competition, as less RAM is required. 

Also more interesting feature engineering will be available as it is much easier to work with integers (my experience).

The cleaned dataset can be found as a dataset:
https://www.kaggle.com/datasets/raddar/amex-data-integer-dtypes-parquet-format

Notebooks used to transform the data:
https://www.kaggle.com/code/raddar/amex-data-int-types-train
https://www.kaggle.com/code/raddar/amex-data-int-types-test
