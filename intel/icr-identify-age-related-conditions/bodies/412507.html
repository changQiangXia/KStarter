This competition's metric is balanced log loss. Therefore it is important to balance the classes during training. There are at least 4 ways to balance the classes

Method 1 - Add Class Weights

The first way to balance classes is to add weight to the positive class. In this competition's train data, the positive class is only 17%. Therefore when we train our models we can give the positive class 4.7x weight so that the positive class has the same importance as the negative class. (Try different weights to see what works best).

Method 2 - Downsample Negative Class (Or Upsample Positive)

A second way to balance the classes is to train with all the positive samples and only a fraction of the negative samples. This is called downsampling. Since we are not using all the negatives during training, we should train many models with different downsample each time. (i.e. bagging)

Here is some example code provided by Ganzy:

from imblearn import RandomUnderSampler
NUM_POS = df()
sampler = (sampling_strategy={: NUM_POS, : NUM_POS})
X_train, y_train = sampler(df, df)

I also provide an example of "downsampling" in my RAPIDS SVC notebook here. The CV 0.44 => CV 0.35 and LB 0.35 => LB 0.27

Method 3 - Post Process

A third way that has not been shown in public notebooks yet is post process. It works like this. If you train a model without adding more weight to the positive class, then you can boost the positive class as post process afterwards with the following code:

 =  
 = boost * preds / (-preds)
 = odds / (+odds)

Here the variable preds is a NumPy array of your preditions for class 1. We convert the probabilities into odds then scale the odds to make the class 1 more important. Finally, we convert odds back to probabilities.

Method 4 - Use Balanced Log Loss

A fourth way suggested by Björn in the comments is to use a balanced log loss function instead of using basic log loss function during training. Then we can leave all the original data as is with class weight equal one. (Note we are referring to the loss function (i.e. GBT objective) not early stopping metric function)

Cross Validation

We can evaluate the effect of the above 4 methods by trying each and computing our OOF CV score. Then we can use whatever works best!
