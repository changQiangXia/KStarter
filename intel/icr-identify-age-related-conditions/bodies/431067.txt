Sliding Time CV Scheme

First we sort all the train data by date. Next we assign a random date to the train samples without a date. Afterward we slide a window with indexes START and END. Then our validation data each fold are all rows from START to END

Why Use Time CV?

The purpose of a local validation is to mimic the relationship between train data and test data. In this competition the host tells us that all the test data occurs after (in time) of the train data. In other words, we must train a model on data from one time period and predict data from another time period.

Normally i would not think that time would influence what the model learns about medical diagnosis, however in this competition if you train an XGB model with time as a feature column it becomes the most important feature even after fillna() with random dates for the train data without dates. 

This means that the data is changing. Perhaps the data is collected in one location on set of machines during one time period and later collected by different machines that are calibrated differently. For some reason, the relationship between features and targets is changing over time!

OOF Validation Scores

We observe that different time periods have different difficulty when predicting. Notably easy time periods have a OOF validation balanced log loss of 0.15 whereas difficult time periods have 0.40. Since the host said this was a difficult problem, we can deduce that public test is easy time and private test is hard time:



CV vs Public LB vs Private LB

My time-CV model has an average local CV = 0.27 and public LB = 0.17 and private LB = 0.39. See notebook here. When using time CV improvements in CV lead to improvements in public and private LB.

Analyze "Risky" Post Processing

Once we have a local validation that mimics the LB, we can analyze PP. For each of the 25 OOF folds, we can find the best Top and Bottom thresholds and plot them. We notice that during some time periods, thresholding works and during others it does not. If we pick the median bottom threshold (i.e. pred[pred&lt;median_bottom]=0), then CV informs us that we have a 50% chance of it working if private test is a "random time period". 

Note to find thresholds for private LB, we must redo the plot below using the size of private LB which is around 200 samples. Plot below is for 120 samples per validation fold and comes from my notebook here. The Yellow line is the best top threshold for each fold (i.e. time period). The Green is bottom. The Blue line is the validation fold balanced log loss metric. And the Red line is how much better each fold can become using the optimal thresholds. We note that the best validation fold with PP achieves 0.06 just like the public LB. And we note that the worst validation fold does not improve from PP just like private LB.

Post Competition Fun Fact

After competition ended, I was curious why the private test is harder than public test and train data to predict. All three have approximately 17.5% target=1 which makes them seem similar. 

First I checked categorical feature EJ (which equals A or B) and found that train, public, private have 64%, 62%, and 50% of EJ=B respectively. Next I checked NAN and found that two additional test columns EH and FD have a few NAN whereas train has no NAN in these columns. This NAN discrepency most likely caused many submission errors but neither of these two discoveries makes a big difference in model accuracy i think. (i.e. I did not find any weird test columns with 100% NAN or something crazy like that).

Next using probing techniques in notebook here we see that private test has more of the difficult Alpha = D type of target=1 Class 1. I think this helps explains what changed over time to make private test more difficult than public test and train data.
