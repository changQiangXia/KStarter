Smart Baseline Submission


This is a good place to start if you want to see how to submit to this competition

The SMART part is because we are not just submitting empty RLEs… we find an example from the training data that matches the metadata of a given test example and submit THAT RLE instead.

This works because, for instance, some slices will never contain any segmentation masks, while others contain only segmentation masks in some places.

DeepLabV3+ w/ Atrous Spatial Pyramid Pooling and Squeeze Excitation Blocks


Atrous Spatial Pyramid Pooling (ASSP) is a semantic segmentation module for resampling a given feature layer at multiple rates prior to convolution.

See the paper here






Squeeze Excitation (SE) Block


The Squeeze Excitation Block is an architectural unit designed to improve the representational power of a network by enabling it to perform dynamic channel-wise feature recalibration. The process is:


The block has a convolutional block as an input.

Each channel is "squeezed" into a single numeric value using average pooling.

A dense layer followed by a ReLU adds non-linearity and output channel complexity is reduced by a ratio.

Another dense layer followed by a sigmoid gives each channel a smooth gating function.

Finally, we weight each feature map of the convolutional block based on the side network; the "excitation".

See the paper here






This implementation is heavily based on this implementation by Nikhil Tomar here and the previously mentioned tutorial.

This model achieves a Public LB Score of 0.817 with an image size of 224x224x3 and no augmentation after only 7 epochs

This was also framed as a multiclass semantic segmentation problem (same as the previous notebook)






GENERAL FINDINGS





What is the problem?


This is multilabel, 3 class, semantic segmentation problem

How do the cases work? Days? Is there 3d in there somewhere?


Images are slices

There are either 144 (common) or 80 (rare) slices/images taken whenever a patient gets imaged

A case is made up of 1-5 days worth of images for a given patient

This means that a particular case is made up of between 144 - 720 images

For a given case's day's images, the slice number along with the pixel width/height imparts a 3-dimensional aspect to the images… 

i.e. slice 1 will be the bottom-most image  

i.e. slice 144 will be the top-most image (in cases where there are 80 images it will be slice 80)

The slices will be spaced according to the pixel spacing information

All of this said, you could frame this as a 2D or 3D segmentation problem fairly easily.

General Findings


All images are close in size but there are 4 unique shapes (3 square and 1 rectangular)

The images are relatively small

The resolution within a case-id&gt;day image group is fairly tight

Some slices never contain masks (first 1 and top 8 or so slices I think
