Based on the experimental results, I hypothesize that the scores from the two data sources are collected in different ways, thus not “compatible”. Mixing them together for training affected the model's fitting capability.

Assumption: All Test Samples are Non-Persuade

In the discussion Adversarial Validation Probe (Train vs Test), the AUC is between 0.65 and 0.675.
I conducted local tests with a proportion of 51% persuade samples + 18% non-persuade samples as train, and 31% non-persuade samples as validation, resulting an AUC of 0.66x.

Additionally, a probing discussion suggested that the test set contains almost only five prompts, which is consistent with non-persuade samples in train.csv.

Based on the discussions, I believe all test samples are non-persuade.

Modeling

Knowing these key points, the modeling process is straightforward.

During training:

  1. Add tags to inputs to distinguish data sources.
  2. Add a data source classification head to ensure the model's output features can differentiate between data sources.
  3. Use different classification heads for different data sources in some models.
  4. Use early stopping based on the scores of non-persuade samples.

During submission:
Assume all samples are non-persuade.

Additionally, I tried swapping tags for pseudo-labeling and distillation, which seemed to provide a slight improvement. I hope this will be useful for the efficiency challenge, though I didn't manage to submit it in time.

Final Submission

My final submission was a large ensemble (average of 45 predictions):

  1. 3 models: microsoft/deberta-large, microsoft/deberta-v3-large, Qwen/Qwen2-1.5B-Instruct
  2. 5 folds
  3. 3 runs (different random seeds)

Thresholds were searched on out-of-fold predictions.

OOF score is 0.818 for non-persuade samples, 0.827 after threshold searching.

Some Useful Tips

I used a few tricks to speed up training and inference, which you can find in my notebook.

Dynamic Micro Batch Collation

Since text lengths are variable, to reduce the impact of padding, I split a batch into micro batches with a limit of total number of tokens. This makes training faster and memory usage stable.
The gradient accumulation training loop looks like this:

 batch  dataloader:
    optimizer.zero_grad()
    total_batch_size = (micro_batch[]  micro_batch  batch)
     micro_batch  batch:
        micro_batch = to_gpu(micro_batch)
        loss = model(micro_batch)
        scale = micro_batch[] / total_batch_size
        (loss * scale).backward()
    optimizer.step()
