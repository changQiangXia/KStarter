Sharing some of my guesses for what the winning solutions might look like for this competition

General Framework
First, It is probably safe to say that the top solution will refuse to use any public prediction (submission file) or notebook as is. not any "Pretrained Model" for their ensemble. This is mostly the case in every competition: Winning solutions train their pipeline end2end on their own [even if parts of it are derived from public sharings]. 



**The obvious **



There probably will be much ensembling and stacking of some basic predictors (LightGBM, XGBoost, Catboost, Hist Gradient Boosting, Generalized Additive Models, FC NNs, 1D NNs, 2D NNs, Tabnets, Transformers, KNN, etc…).
At the moment, the competition still runs and we can already see that on this dataset: NNs work better out of the box. There may be many reasons for this, it might be interesting to discuss this, anyhow this is irrelevant for the public leaderboard score. NN should be a baseline result at the moment.


Everyone's main goal at this moment should be getting the best single model they can to later on ensemble it.

In general, I am a huge fan of pushing a single model as far as possible, many of my past solutions focus on single models. I think this will work surprisingly well in this competition. However, getting back to reality: most of the winning solutions are going to be just insane ensembles. no way around it.. So the choice is yours for what you want to focus on.



Hyperparams
Speaking of pushing a single model: There might be some sort of fancy hyper-parameters tuning trick [combination of multiple optimizers like Bayesian, hyperopt, optuna.. different methods for different model types..], the majority of top solutions will often use simple hyper-parameter optimizers but will do so in a slightly better way. The pattern here is simple and is repeated again and again: Many winning solutions don't have a "nuke trick" that destroys the leaderboard on their own. Many winning solutions just utilize the same methods better: they are organized, cleaned out of any unneeded code, and most importantly: They are the end result of millions of tiny incremental steps. 
So, we can all understand from this that: If we want to win, we simply need to take small steps - one at a time: experiment -&gt; evaluate -&gt; experiment.. get a slightly better CV score on each step.

Tips for better hyperparameters optimization:




Bayesian optimization or grid search are good choices for hyperparameters optimization. 


Start optimizing just a few parameters like num_leaves, feature_fraction, and bagging_fraction with const learning_rate and use early stopping. When this is over, play with other parameters, over time you get some intuition about what is a good value for some of the parameters.


Search over only 1 fold and start with a small grip search. When it is done, you should have a good idea for good parameter sets. This is the time to move over the search to be using all folds (again with early stopping). Just make sure to use the ranges found on the prior grid search. 


At the top end of the leaderboard most hyperparameters optimization needs to be manual at that point. A hyper-parameter optimizer can give you an initial idea of the search space while you leave it running.

Stacking

Usually, linear models workes best (L1, L2, Elastic Net regression) since they overfit less. 
Oftentimes, Elastic Nets seemed to have the best scores because they are "a bit more" generalizable because of their regularization. This is not a "law of nature" by any sort but it is worth trying them out. Just be careful not to overfit and have a strong CV to back you up. 

An important tip about stacking: 

How not to be an Idiot like me:

Before we are done, let's talk about a common mistake. I overfitted a bit in the past when trying to get a stacking system to run during a kaggle competition. so if you don't want to make the same mistake as me, read along:

A common mistake is using early stopping per fold. While it is a good way to get a baseline model, you still overfit a bit each fold. This kind of OOF prediction doesn't work well if you plan to perform a stacking later [This single mistake cost me a full month]

The best way to avoid overfitting is performing early stop on all folds per round. Meaning, you find a "good number" of iterations you should perform [For NN: epochs, for GBMs: n_estimators].
After you got the "ideal" number of rounds that perform well on the test set, you use the same number of rounds for ALL folds. This makes it possible to use stacking later on those OOF predictions. 
[Note: This also works well when training a model to use all the datasets]



Optimizing Ensemble Weights

Some solutions will find the optimal weights by using some black-box optimizer, like scipy.
Here is how to use scipy to find the optimal weights for a weighted average between the predictions of your models: 

from scipy.optimize import minimize
scores = []
weights = []
for y, lgb_pred, xgb_pred, ctb_pred in zip(y_valids, lgb_train_preds, xgb_train_preds, ctb_train_preds):
    preds = []
    preds.append(lgb_pred)
    preds.append(xgb_pred)
    preds.append(ctb_pred)
    def log_weight_loss(weights):
        weighted_pred = (weights[0]*preds[0]) + (weights[1]*preds[1]) + (weights[2]*preds[2])
        return log_loss(y, weighted_pred)
    starting_values = [0.3]*len(preds) 
    cons = ({'type':'eq','fun':lambda w: 1-sum(w)})
    bounds = [(0,1)]*len(preds) 
    res = minimize(log_weight_loss, starting_values, method='Nelder-Mead', bounds=bounds, constraints=cons)

    weights.append(res['x'])
    print(res['fun'])
    scores.append(res['fun'])


And then combining the final predictions in a simple non-weighted average to generate the final predictions:

final_weights = sum(weights)/folds
weighted_preds = np.array((final_weights[0] * sum(lgb_test_preds)/folds)+(final_weights[1] * sum(xgb_test_preds)/folds)+(final_weights[2] * sum(ctb_test_preds)/folds))


Psuedolabelling

For those that don't know: Psuedolabelling means using a model to label the test then using the labeled test as training data for another model. This boosts performance slightly but sometimes this is the only thing you need for a medal.

Something I want to see is the use of self-supervised learning (clustering, auto-encoder, GPT like learning for predicting partial input from other partial input of both train+test). This is something that is high-risk high-reward - very hard to get right but if you do, you might just win overall.  (something somewhat similar was used on the open-vaccine competition a year ago. 

Metric Learning
Something that might work well, it works from time to time: try some metric learning tricks on a tabular network.

Adversarial Learning
