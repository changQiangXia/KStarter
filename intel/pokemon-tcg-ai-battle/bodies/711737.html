There has already been a discussion about whether the actual game engine source code will be made available, but as far as I can tell there has not yet been an official response from the host.

Having a local, inspectable game engine is a crucial factor for both RL and tree-search based approaches. It is important not only for understanding the rules precisely, but also for accelerating simulation, which can become a major bottleneck in training and search.

At the same time, I understand that this may be an IP-sensitive issue. Releasing the full engine source code could potentially raise concerns such as facilitating unofficial or pirated implementations of the game, or other issues that the host and The Pokémon Company may need to consider. So I am not necessarily asking that the source code must be released. What I would like to ask for is an explicit ruling early in the competition, because this is a strategy-critical point for many participants.

Could the host please clarify the following points explicitly?

  1. Will the source code of the game engine be released, or will participants only have access to the provided binary and wrapper?

  2. If the source code will not be released, are participants allowed to reverse engineer, decompile, disassemble, or otherwise reproduce the behavior of the provided .so / .dll files in order to build their own game engine?

  3. If reverse engineering or reimplementation is allowed, is the host aware that this may become a major competitive advantage?

    I strongly expect that some top teams will attempt this for faster RL training or faster search. In the RL case, the reimplemented engine may only be used privately for training and may never be shared. In the tree-search case, however, if a team uses its own engine during actual gameplay, then publishing the final submission code may effectively expose that self-built engine. Is this intended and acceptable?

  4. If the official source code will not be released, are participants from multiple teams allowed to collaborate publicly on a shared open-source game engine, for example in a public GitHub repository?

    There have been somewhat similar community efforts in previous Kaggle competitions, such as participants jointly investigating leaderboard/test-data behavior: https://www.kaggle.com/competitions/jigsaw-agile-community-rules/discussion/607118

    If there is no official clarification on this point, participants may reasonably assume that public community-driven reimplementation is allowed unless explicitly prohibited. In that case, I may consider creating a public GitHub repository for a community-built engine, so I would really appreciate an explicit ruling before people start investing time in that direction.

  5. If the host wants to allow some forms of reimplementation but restrict others, could you clarify the boundary?

    For example, there may be reasonable middle-ground options: allowing teams to develop their own internal engine for training/search, but prohibiting public cross-team collaboration on a shared engine; or asking participants to exclude engine-reimplementation details as much as possible from public solution code or writeups. I think several compromises may be possible, but the important part is that the rules are stated clearly.

The main concern is that if there is no official clarification, this competition may partially turn into a reverse-engineering competition, and different teams may make different assumptions about what is allowed. A clear ruling would help participants decide whether to invest time in building a game engine, and would also make the competition fairer and less ambiguous.

Thank you.
