Stacking using scipy.minimize thanks @pourchot 

Multistart the NNs to mitigate noise.

Post processing by adding little values to predictions above and below 0.5. Always trusting the CV to select the positive and negative delta. Earlier in the competition EDA notebooks shown that models had more troubles to classify negative labels.

Trust your CV its easy to overfit

Swish and Mish for activation functions.

Boltzmann ensemble, we didn’t go deeper after the first couple of iterations

Geometric mean, similar to Boltzman.

Residual blocks (a simple neural network was enough)

The brief description of the solution

I've spent some time to find the best models among the 5000 provided. I've used two features selection method that gave me nice results on CV:

CatBoost FE based on LossFunctionChange

For each feature, LossFunctionChange represents the difference between the loss value of the model with this feature and without it.

https://catboost.ai/en/docs/concepts/python-reference_catboost_select_features

I've explored 1000, 500, 275, 250, 200 features. Best results was for 250.

Null importance FE with 100 runs

Shuffle the target randomly and compute features importance, run this process many times (100) to get importance distribution. 

Compare with importance without shuffle (i.e. the problem we want to solve), if such importance is mixed within the ones with shuffle 

then it means this feature does not matter for our problem. We keep only the ones that matters

https://www.kaggle.com/code/ogrellier/feature-selection-with-null-importances

At the end of this process I've selected 350 features

I've trained models based on these FE. Best CV (5 folds) was for classic LightGBM/GBDT, CatBoost and NN was not bad.

3 LightGBM/GBDT models with 250, 275, 350 features

### Understanding Ensemble Learning, Blending, and Stacking Generalization

来源：https://www.kaggle.com/competitions/tabular-playground-series-nov-2022/discussion/363968

Ensemble Learning

Essentially, ensembling takes the predictions from multiple models and combines them to create a more accurate single prediction. Ensembling is relevant to this competition because instead of getting raw data, we are given multiples models predictions, so we need to ensemble these predictions.

There are 3 main ways to go about ensemble learning for a kaggle challenge:

basic mean - just a simple average of multiple predictions

leaderboard probing - weighted average of predictions with weights selected by hand based on the optimal score from the public leaderboard

cross validation tuned - the best technique, uses the training data to tune weights or a meta model to merge predictions

[图 1: inbox%2F6537187%2F7198cd46eb4ccb2a4f1992a83ce9bfdc%2Fbasic_avg.PNG]

Blending and Stacking are types of ensembles.

Blending

Since we are given a bunch of prediction files, the easiest thing to do is to start with a blend. 

Here is what to do:

Define a Meta-Model - this will be a machine learning model used to merge the predictions from other models. I like to start with sklearn's LogisticRegressionCV (LassoCV or RidgeCV for regression) because the are pretty decent models with built in cross validation, so it is easy to set a baseline. Anyway, feel free to use any model you like though (xgb, lgbm, svm, neural net, etc).

Since we already have prediction files, preprocess the data so each prediction column is its own feature ready to be inputted to train the meta-model.

Train the model like any normal tabular task and have the model output your new meta predictions that you can submit.

[图 2: inbox%2F6537187%2F0bdbd842cfc7ee0e44281dd4b747298d%2Fblend.PNG]

Stacking

Stacking generalization is similar to blending, but it has multiple layers and a more complicated cross validation system.

Setup the prediction files as features the same way you would do for blending.

Define and train multiple complicated models (e.g. 1 xgb, 1 lgbm, 1 nn, etc) and train each of those models for n folds. 

Define a more simple meta-model (e.g. logistic regression or ridge regression) to take a weighted average of all those predictions to produce your final predictions.

[图 3: inbox%2F6537187%2Fea8cf497e5a8b5d4e38bb14eefac0d3b%2Fstack.PNG]

note you can also take blends of blends and stacks of stacks and keep repeating this process until the accuracy converges and you can improve no more.

### The overlooked piece of information

来源：https://www.kaggle.com/competitions/tabular-playground-series-nov-2022/discussion/364013

The competition description contains a piece of information which seems to be neglected in many public notebooks and discussion posts:

 
In this competition, you are given a folder of submissions that contain predictions for a binary classification task.

They say predictions rather than features, yet everybody is throwing the usual machine learning algorithms at the data. How can we exploit the fact that we are given predictions rather than features, albeit the predictions are of dubious quality?

[图 1: LmbDMLT.png]

Let's try some reverse engineering! The diagrams clearly show that the model predicts probabilities which are too high. How can this happen? I assume that the model was trained on data that has the same distribution as the competition dataset, but during training, the positive samples were weighted higher. Maybe the positives were oversampled, the negatives were undersampled, or the model was simply trained with a wrong class_weight parameter.

If this hypothesis is true, the predictions can be corrected by subtracting a constant from the logits:

x = scipy.special.expit(scipy.special.logit(x) - 1.17)

Equivalently, one can fit a logistic regression model to the logits:

LogisticRegression.fit(scipy.special.logit(x), y)

In a previous post, I showed how predictions can be calibrated with isotonic regression. Isotonic regression improved the cv score of a single model (0.6475577136.csv) from 0.6476 to 0.5286. Shifting the logit improves the same model's cv to 0.5281. We get this improvement because isotonic regression overfits a step function whereas logistic regression fits only one parameter to compensate for the wrong class_weight.

[图 2: CPjhO08.png]

The real improvement, however, doesn't show up in the single model, but when we use the whole dataset. Logistic regression on the original dataset gives a cv score of 0.5318; logistic regression on the logits improves the cv to 0.5258.

Lessons learned

Recommendation: replace the whole dataset by its logit before feature selection, dimensionality reduction and modeling.

Always look for pieces of information that haven't been exploited yet.

Source code is in the EDA which makes sense, and by the way, @siukeitin had the same idea at the same time.
