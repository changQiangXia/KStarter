### 1st Place Solution Details

来源：https://www.kaggle.com/competitions/playground-series-s3e2/discussion/378795

Thanks to everyone for the great competition, great discussions, ideas, code, and helping me achieve my first first place! None of it would have happened without all the discussion and sharing of thoughts and ideas. Also thanks to the Kaggle team for organizing this and so many other fun and exciting competitions, tutorials, and experiences.

The notebook can be found here: XGBoost PlayS03E02 First Place

Data and Feature Engineering

In addition to the synthetic data, I added stroke observations from the original dataset to help improve upon the imbalanced dataset. I consistently saw improvements in my CVs and performances on the Public LB when I did this regardless of model type. I did 10-fold CV using StratifiedKFold. [1]

The trick, however, is that all of my CV calculations used only the synthetic dataset. I included the original stroke observations in each CV fold, but did not use them to calculate CVs. Given the differences in distributions of some features and some inter-feature correlations, I believe monitoring only the synthetic set avoided over-training to the original dataset. [5]

One-hot encoding

Categorical features were one-hot encoded. [2] I opted for sparse or k-1 class encoding to reduce the total number of features and to prevent perfect correlations between features.

Impute BMI

Some observations from the original dataset did not have BMI values. KNeighborsRegressor was used to impute BMI for those observations. [6]

Total risk factors

I though computing clinical risk factors [4] was a great idea and included this in my feature engineering. Compared to my baseline model (simple logistic regression), including risk factors gave me an improvement of only 0.0008. I did not compare to a baseline for other model types, however.

Center and scale

Continuous features were centered and scaled.

Modeling

Model Tuning

The first place model was a simple XGBoost model. I tuned hyper-parameters using a randomized search over a hand-coded set of ranges. I performed 500 iterations of random hyper-parameter samples, and did 10-fold CV for each iteration. Predictions were made for the test set in each CV fold for each model.

Ensemble

The final ensemble was developed by simply averaging all the test set predictions for the 5 best models (ranked by average CV AUC) for a total of 50 predictions in the ensemble.

Other things I tried

I performed this exact same process of tuning and ensembling using LogisticRegression (0.89209 on Private LB), CatBoost (0.89799), and a simple NN (0.89423). All of them did quite well with very small separation in scores. Obviously the non-linear approaches performed best.

I also tried blending all the approaches mentioned above, using either the best model or the best 5 models for each model type - this included the XGBoost predictions in the winning submission. Using the best single model (10-fold cv predictions for each, so 40 predictions), gave a Private LB score of 0.89975, and using the best 5 models for each (200 total predictions!) gave a Private LB score of 0.89879. Both would still have been in the top 10.

I tried ranking my scores [3] but I did not see any improvement in my CVs nor LB standings.

I ran TPOT to do some exploratory modeling early on. Even running it multiple times with multiple settings, XGBoost was always the best model found.

Hi all,

It seems there was quite a good shake up given that dataset was highly imbalanced and AUC can vary a lot depending the number of samples. I realized there was a good difference between by OOF AUC and the leaderboard so I decided to trust only my CV (10 StratifiedKfold).

Tricks that worked

Fill unknown category form smoking status as never smoked. The ituition was given on my EDA where you can see that unknown class has the lowest probability of stroke.

Fill other class from gender as male. I spotted a boost on CV when filling that record in synthetic dataset. I didn't probe the leaderboard to validate this on test.

Ensemble using gradient descent and ranking the predictions.

Concat original stroke dataset and use StratifiedKfold where validation only has synthetic data.

Feature selection using RecursiveFeatureElimanation. Additional features I tried:

Things that didn't work

Use forward selection taken from this notebook. This was my second submission and scored 0.89941 on private leaderboard. I think It didn't worked because the final ensemble was only composed of XGBoost models while my best submission has a wide variety of models.

MeanEncoder, WoEEncoder and CountFrequency encoder. Neither of those provided better solutions that OneHotEncoder.

### CatBoost+XGB+LGBM+Lasso mix for 88th place

来源：https://www.kaggle.com/competitions/playground-series-s3e2/discussion/378879

I trained 5 CatBoost, XGB, LGBM, and Lasso classifiers with StratifiedKFold (k = 5) and submitted two blends. First with equal weights, second with Lasso having double weight compared to the rest. Even weights performed better.

Code: https://www.kaggle.com/code/vjpkaggle/stroke-prediction-playground-s3e2

After finding suitable parameters for the boosters, I added a small grid search for each fold to allow slight variation in the parameters across the models. This ended up increasing private scores by only ~0.0002 in both cases. This mix was also slightly better than my submissions with any of the individual models, although LGBM alone got within 0.0002.

From all the blends that I tested and submitted, the best performing one gave CatBoost twice as much weight as any of the others.

For preprocessing, I tried adding the discussed rick factor count, but in quick testing it did not improve CV scores so I did not include it in the final model.

I also ordinal encoded smoking_status instead of one-hot encoding it after testing both and finding a slight improvement in CV scores with ordinal encoding.

For more details, check out the notebook.
