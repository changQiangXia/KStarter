Atrous Spatial Pyramid Pooling (ASSP) is a semantic segmentation module for resampling a given feature layer at multiple rates prior to convolution.

Squeeze Excitation (SE) Block

The Squeeze Excitation Block is an architectural unit designed to improve the representational power of a network by enabling it to perform dynamic channel-wise feature recalibration. The process is:

The block has a convolutional block as an input.

Each channel is "squeezed" into a single numeric value using average pooling.

A dense layer followed by a ReLU adds non-linearity and output channel complexity is reduced by a ratio.

Another dense layer followed by a sigmoid gives each channel a smooth gating function.

Finally, we weight each feature map of the convolutional block based on the side network; the "excitation".

See the paper here

[图 2: Screen-Shot-2022-04-19-at-5-53-37-PM.png]

GENERAL FINDINGS

What is the problem?

This is multilabel, 3 class, semantic segmentation problem

How do the cases work? Days? Is there 3d in there somewhere?

Images are slices

There are either 144 (common) or 80 (rare) slices/images taken whenever a patient gets imaged

A case is made up of 1-5 days worth of images for a given patient

This means that a particular case is made up of between 144 - 720 images

For a given case's day's images, the slice number along with the pixel width/height imparts a 3-dimensional aspect to the images… 

i.e. slice 1 will be the bottom-most image 

i.e. slice 144 will be the top-most image (in cases where there are 80 images it will be slice 80)

The slices will be spaced according to the pixel spacing information

All of this said, you could frame this as a 2D or 3D segmentation problem fairly easily.

General Findings

All images are close in size but there are 4 unique shapes (3 square and 1 rectangular)

The images are relatively small

The resolution within a case-id>day image group is fairly tight

Some slices never contain masks (first 1 and top 8 or so slices I think

### 3rd Place Solution

Summary

My overall solution is similar to the 2nd place solution, but without 3D models. My solution is to use the detector to detect the main area, then use the classifier to judge whether it needs to be segmented, and finally segment the image that needs to be segmented, and only keep the segmentation results that the classifier judges as positive samples.

Detail

5 Fold cross validation by group spliting case

Only 2.5D Models (slice=3 and slice=5)

Pre-processing(crop with a detection model), refer to [bestfitting], [Guanshuo Xu]

My training pipeline (cls + seg method and swa for models) is based on our siim acr solution (SIIM-ACR Solution)

Models

Pre-processing

EfficientDet-D0, size=256, epoch=5, all other parameters use default parameters. This is a very easy task for the model to learn. I generated some training samples using image preprocessing and relabeled the bad bounding box.

Cls part

Only use Unet(Smp-Unet and Timm-Unet) with different backbone and classification branch,Timm-Unet refer to selimsef's xview3_solution, Thanks for his sharing, Then I made some modifications to the network for this competition.

Cls branch loss: bce loss 

Seg branch loss: bce loss

Using ema (refer to DungNB) and swa

Epoch=35(7 cycle)

Init lr=3e-4 or 5e-4

Data: use all data

Metric for select model: TP / (TP + FP + FN) and Dice score

models

Seg part

For the classification model, I mainly focus on the accuracy of the classification. For the segmentation model, I hope to obtain a better and better segmentation effect, so I train the segmentation model separately.

Cls branch loss: bce loss 

Seg branch loss: ComboLoss({'bce': 0.5, 'dice': 0.5, 'lovasz': 1}

Data: All positive samples

Metric for select model: Dice score

Timm-Unet efficientnet-v2-l-1 and Timm-Unet efficientnet-v2-l-2 use different scale pretraining adjustments

models

### 1st place solution for 2.5d parts

来源：https://www.kaggle.com/competitions/uw-madison-gi-tract-image-segmentation/discussion/337217

2.5D method Overall pipeline

The overall pipeline of our 2.5D solution is divided into two stages: the classification stage and the segmentation stage. The former one is responsible for determining whether there are targets in the image, while the latter one segments the targets in the image. By analyzing the classification stage to control the target segmentation in the image, the classification and segmentation stage are both model-weighted fusion to enhance the robustness of our 2.5D, and the pure 2.5D model can achieve a score of 0.889 on the public leaderboard.

The details are presented below ↓

Data

For data production, we refer to @awsaf49 's data production method, set the stride size to 2, and take a total of three to produce 2.5D data. https://www.kaggle.com/code/awsaf49/uwmgi-2-5d-stride-2-data

Traing & test time augmentation

We tried 640*640 and 512*512 image resize resolution. where in the case of 640*640 resolution, we used RandomCrop method to randomly crop down the target of 448*448 resolution during training. We also used random flip, elastic transformation, grid distortion and optical distortion, the specific parameters are

dict(type='RandomFlip', direction='horizental', p=0.5)
dict(type='ElasticTransform', alpha=120, sigma=6.0, alpha_affine=3.6, p=1)
dict(type='GridDistortion', p=1)
dict(type='OpticalDistortion', distort_limit=2, shift_limit=0.5, p=1)

When it comes to test time, we use horizental flip method to preduce a new image and use weighted fusion to get the output mask. TTA can boost our score for 0.001 ~ 0.002 approximately.

Backbone

The algorithm is based on Unet, the backbone network we tried efficientNet b4 ~ b7, single model can reach about 0.883 on the public leaderboard, and model fusion at submission can reach about 0.889. And for the deep learning framework, we use our teammate @CarnoZhao 's work https://www.kaggle.com/code/carnozhao/uwmgit-mmsegmentation-end-to-end-submission

Training and inference tips & loss function

The classification network is trained for full data, which contains empty pictures as well as images with mask. The segmentation network is only responsible for segmenting the target images, and the segmentation network is trained on full data with mask images only. The classification network is trained with a single BCELoss, and the segmentation network is trained with a BCE and Dice weighted loss function with a 1:3 loss function ratio. 

Besides, we use fp16 traing method to make our training more faster and it can save about 50% gpu memory, which allowed us to use bigger batch size.

TL; DR

We used three groups of models in our solution, named CLS group (gray boxes), SEG group (blue boxes) and 3D group (yellow boxes). CLS group is used to classify whether the prediction of a slice should be empty or not. SEG group and 3D group are used to do segmentation for slices that should be predicted.

notebook

Our submission notebook is for referencing only. Model weights will not be released.

github

Here is my github repo for this solution.

1. CLS group

1.1 Data

Models were trained with the whole dataset, instead of folds. 

Some models were trained without wrong annotated cases (mentioned in discussion).

1.2 Model

4 unets, with efficientnet b4, b5, b6, b7 backbones.

1.3 Training

Public mmsegmentation pipeline.

1.4 Usage

We computed prediction result of each slice of test data, using 0.6 threshold to binarize sigmoid probabilities. If the number of positive pixels if larger than 12, the slice is defined as "positive slice" (#pixels check arrow). Otherwise, the slice is defined as negative, which will skip further computation, and generate zero masks only.

2. SEG group

2.1 Data

Efficientnet-Unet models were trained with annotated slices (green arrow) in the whole dataset, which means, slices that have no annotation will not used in this step. 

ConvNeXt-UPernet models were trained with all slices in the whole dataset, except 5 slices following the end point (orange arrow) of large-bowel and small-bowel. We believe these slices' annotation will introduce ambiguous supervision.

Some models were trained without wrong annotated cases (mentioned in discussion).

2.2 Model

5 unets, with b4, two b5, b6 and b7 backbones.

2 upernet, with convnext-base and convnext-small backbones.

2.3 Training

Public mmsegmentation pipeline.

2.4 Usage

We computed logits prediction result of each positive slice of test data.

3. 3D group

3.1 Data

Public MONAI pipeline data preprocessing

3.2 Model

3 SegResNets, with init_filters = 12, 20, 32, PRELU activation and batch norm.

3.3 Training

Public MONAI pipeline training.

3.4 Usage

We computed logits prediction result of each volume of test data. The 3D logits and 2.5D logits were merged using 0.4/0.6 weights, then binarized using threshold 0.4.

4. Hyperparameters

All hyperparameters will be listed in config files. The dataset of all config files will be released soon.

In short, for CLS group and SEG group, we used dice-ce, ce, dice loss for different models. We used elastic transform, grid distortion and optical distortion, with default flip, rotation in data augmentations.

For 3D groups, we used default trained pipeline as public MONAI dataset in first stage training. And we used cosine annealing, 1e-4->1e-6 learning rate, 20 epochs in second stage training.
