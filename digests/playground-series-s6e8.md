### 14th Place - 278 Shared OOF Sets + 36 Own Models, All Judged on a Sealed Fold

来源：https://www.kaggle.com/competitions/playground-series-s6e8/discussion/739004

Congratulations to the winners, and thank you to everyone who published OOF and test predictions during this competition. My own models did not get me to 14th place. My best own-only submission scored Private 0.97063. The final submission that scored 0.97109 is a stack of 36 of my models and 278 prediction sets that other participants shared as Kaggle datasets and notebook outputs. The full credit list is in the section "Who the 278 columns came from", and I would ask anyone reusing this approach to keep that list with it.

What is mine is the procedure: the checks a shared prediction had to pass before it could enter, the sealed-fold judgment behind every ensemble decision, and the 36 models that gave the stack something the shared sets did not have.

TL;DR

StratifiedKFold(5, shuffle=True, random_state=42) generated once, committed, never regenerated. Every own model is a 3-seed average (42, 43, 44) on those folds.

Own pool of 36 models, best single OOF AUC 0.96941 (a Lookup-Transformer variant). Own-only stack: nested OOF 0.96981, Private 0.97063.

278 shared OOF/test pairs admitted after an integrity check: row counts, finiteness, re-scored AUC within 1e-5 of the declared value, hash dedup, fold evidence, leakage review.

Combiner: L2 logistic regression on standardized rank and logit of every column. C and a shrinkage factor toward the plain rank mean chosen inside the outer training folds. Final C = 0.03, shrinkage 1.0 (no rank-mean mixing), negative weights allowed.

Every pool change judged by nested OOF: seal one fold, choose everything on the other four, score the sealed fold, repeat five times. Adoption needed a pre-set delta and a positive sealed-fold delta in 5/5 folds for late changes.

Nested OOF ladder: own 35 at 0.96981, plus 207 shared columns 0.97029, plus 71 more and minus 120 harmful ones 0.97035, C selection 0.97036, final 314 columns 0.97038.

Public LB was never used for any decision.

Validation

Fixed folds, OOF, gates

I made the folds once and committed them as a parquet file. Everything that touches the target (target encoding, imputation models, vocabularies and rank-gauss quantiles for the transformers) is fit inside the training part of each fold. All numbers below are OOF AUC on those folds, averaged over seeds 42, 43, 44, unless stated otherwise.

Two rules ran from the first week.

A placebo feature is always present. A new feature is accepted only if its fold-averaged gain importance beats the placebo. Non-tree models convert their own importance to the same scale so the gate applies everywhere.

Screening happens on fold 0, seed 42, against the current champion on the same fold. A candidate that loses on fold 0 is dropped without a full run. Champion replacement always requires the full 3-seed confirmation.

Nested OOF for every ensemble decision

An ensemble chosen by comparing many combinations on OOF is optimistic, because the choice already looked at those labels. So every ensemble judgment used a sealed fold.

[图 2: inbox%2F940278%2Fccb9aeabc2795d99c892bd0ee643fbf9%2Fwriteup-nested-oof.png]

Seal fold k. Take the OOF rows and labels of the other four folds.

Choose members, combiner weights and combiner hyperparameters on those rows only.

Apply the frozen combiner to the OOF rows of fold k.

Repeat for k = 1..5, concatenate in the original row order, score ROC AUC.

No model is retrained in this loop and there is no inner re-splitting, so it is not a full double CV. It only removes the optimism of selecting the ensemble on the rows you score.

Each candidate had to answer two questions: is it good alone (its own OOF AUC), and does it help together (nested OOF delta when added to the current pool)? A weaker model stayed if it was wrong on different rows than the pool, and a stronger one was dropped if it was wrong on the same rows. Duplicate rule: Spearman rank correlation above 0.998 with any existing member.

Adoption gate

I adopted a pool change only if both conditions below held, and both were fixed before I looked at the result.

Nested OOF delta above a threshold (+0.00002 for late pool changes).

Sealed-fold delta positive in at least 3/5 folds early on, 5/5 for the final pool.

Two examples: Replacing five own members with missingness-augmented versions: +0.0000469, positive on 5/5, adopted. Widening the final stack from 314 to 327 columns: +0.0000047, positive on 3/5, rejected. I submitted the 327 version anyway for the record and it scored Private 0.97108 against 0.97109 for the 314 version.

Own models

Data observations that drove the features

The numeric columns are not continuous. Values sit on a small set of exact numbers, and the target rate is stable within each exact value, so exact values work as keys. There is also a budget relation: daily_screen_time_hours is roughly social_media_hours + gaming_hours + work_study_hours + something else. The residual and the part-to-total ratios were useful features and also bounded the imputations.

Features

Counting feature providers across the final 36 configs: derived features 30, constraint-based imputation 27, target encoding 18, XGBoost-based imputation 14, exact-value categorical copies 3, frequency encoding 2, lattice pair target encoding 1, and five configs with original-dataset proxies.

Exact-value categorical copies. Keeping the 9 numeric columns and adding 9 categorical copies (same value = same category) moved LightGBM from 0.96276 to 0.96605. Converting everything to categorical and dropping the numeric columns went to 0.95859. The model needed order and distance as well as the exact-value view, so the categorical copies had to sit next to the numeric columns rather than replace them.

Same LightGBM settings for all three (num_leaves=255, learning_rate=0.05, early stopping 200, seed 42).

Screen-time budget. other_screen = daily - (social + gaming + work) (NaN if any part is missing), screen_slack = daily - sum of observed parts (NaN only if daily is missing), part-to-daily ratios, weekday/weekend differences, weekend - slack, and a count of observed parts.

Imputation as auxiliary columns. Raw columns were never overwritten; imputed values went into <col>_recon columns next to them. Constraint-based: an IterativeImputer fit on the training fold, with screen-time estimates clipped to the interval allowed by daily >= social + gaming + work. XGBoost-based: per-column XGBoost imputers fit on the training fold, plus compositions on the imputed values (fractions, awake-time screen fraction, weekend minus daily, and so on).

Target encoding. Exact-value target encoding, fit with an inner split inside each training fold, in half the pool. One config used a lattice of pairwise exact-value target means. The placebo gate earned its keep on the composition features over the imputed matrix: twelve of them passed the AUC gate as a group (+0.00019), but seven had lower gain than the placebo, and only the five that beat it went into the champion.

Original dataset proxies. Five configs used the public Smartphone_Usage_And_Addiction_Analysis_7500_Rows.csv as a proxy for the generator's source: nearest-neighbour features, prior means, class-conditional CDF differences, and a first-stage prediction trained on it. They were modest on their own but wrong on different rows than the rest of the pool.

Missingness augmentation. Six of the final 36 members trained on 3x rows: the original training fold plus two copies where each observed cell was masked with probability 0.25. Existing NaNs stay NaN, copies inherit fold and label, all preprocessing state is fit on the original rows only. A version that copied empirical row-level mask patterns from train and test instead of independent masking did not pass the gate, so the gain came from mask diversity rather than from realistic missing patterns.

Lookup-Transformer. A port of tamerlanomralinov's public notebook, with vocabulary and rank-gauss quantiles fit on the training fold only. Each column is one token: an exact-value lookup embedding (the repeated keys) plus a PLR embedding of the rank-gauss value (the smooth trend). Values seen only in validation or test map to a per-column UNK id, distinct from NA. 4 layers, width 128, 8 heads, CLS head. 32 epochs, batch 2,048, OneCycle with peak LR 2e-3, EMA, value dropout. The best variants used Muon instead of AdamW, averaged several initializations per fold, and added five PLR-only composition tokens on the imputed screen-time columns. The first version scored 0.96892 against a champion of 0.96854, its highest Spearman correlation with any pool member was 0.98149 (an XGBoost), and adding it gave +0.00025 to the ensemble. Seventeen learning-rate, schedule and optimizer variants after that all lost on fold 0.

The RealMLP dtype bug. The largest single-model gain of the competition was a bug fix. My RealMLP port also used numeric columns as exact-value categories. The vocabulary was built from float64 values, but the encoding step cast to float32 before the lookup, so any value with a fractional part missed the vocabulary and the categorical channel for 6 columns was effectively dead.

Combiner

For each column, compute the empirical rank and the logit of the raw probability, standardize both, and fit an L2 logistic regression over all columns. Negative weights are allowed. The output rank is shrunk toward the plain rank mean of the members with a factor lambda.

C in {0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1.0} and lambda in {0.25, 0.5, 0.75, 1.0} are chosen by leave-one-fold-out inside the outer training folds, so they are part of what the sealed fold judges. Ties go to the smaller C, then the smaller lambda. On the final full-OOF fit: C = 0.03, lambda = 1.0, so the plain rank mean was not mixed in at all.

For the test prediction the combiner is refit once on the full 314-column OOF matrix and applied to the test matrix in the same column order. Own members' test predictions come from full-train refits using the training length observed in CV. Shared members' test predictions are whatever the author published, normally a fold average. The combiner works in rank space per column, so the scale mismatch does not matter.

Part 4: My Advice

I want to share a few methods that worked for me.

4.1 - Practice Old Competitions

If you are still struggling to reach the Top 500, do not just jump into new competitions. Try finished competitions first.

For AUC competitions, you can practice on: S5E8, S5E11, S6E3, S6E5.

This helps you understand:

What kinds of feature engineering are repeatedly useful

Which blending methods are more stable

How OOF, Public LB, and Private LB are related

Once you have your own stable pipeline, you can have a much better start in a new competition.

4.2 - Make Sure Your Model Is Good Enough

If someone has already shown that LR can reach around 0.960 and XGB/LGB can reach around 0.966 without much feature engineering, but your tuned model is still far below that, your pipeline probably has a problem.

Small changes may not help much, and restarting with a simple baseline may be more useful.

One for different feature engineering

One for Optuna search

One for different seeds / folds / learning rates

One for testing a new idea

I do not put everything into one notebook, and I do not draw a conclusion before trying different combinations.

You will often see people jump 100 ranks or drop 100 ranks in a row. This happens in AUC competitions.

For example:

Suppose my good model has a true score of 0.97125.

By blind blending on Public LB, I may find one submission at 0.97130 and suddenly jump 100 ranks.

But the true performance of that submission could be only 0.97120 because I overfit the Public LB.

Another model with a true 0.97125 may finally beat me on the Private LB, even if its owner does nothing.

So I mainly trust my OOF, and Public LB is just a check of whether my OOF improvement also behaves reasonably on the test data.

### 248th Place Solution — Rank-Aligned Fusion and Risk-Conditional Blending

来源：https://www.kaggle.com/competitions/playground-series-s6e8/discussion/738626

Predicting Smartphone Addiction, Playground Series S6E8

Final rank: 248 / 3,532 teams (Top 7.0%)

Public / private ROC AUC: 0.97126 / 0.97100

Thank you to Kaggle and to everyone who shared notebooks, OOF predictions, and
experiments during the competition. This solution was built on a strong public
ensemble and focused on making its validation and inference paths consistent,
then applying a small risk-conditional blending layer.

Context

Competition overview: https://www.kaggle.com/competitions/playground-series-s6e8/overview

Competition data: https://www.kaggle.com/competitions/playground-series-s6e8/data

Solution overview

The final pipeline had four stages:

Start from the disclosed 205-model OOF Rank-Logit-Regime fusion by
Byer/HBoyang.

Convert both meta-level prediction inputs to strict percentile ranks before
blending, using the same representation for OOF validation and test
inference.

Replace one global blend weight with OOF-selected weights conditioned on
prediction-risk quantiles. I trained independent 8-, 10-, and 12-bin
variants and rank-averaged their outputs.

Correct two test rows whose complete feature vectors exactly duplicated one
labeled training row with an unambiguous target.

The final submitted prediction can be summarized as:

base rank + fusion rank
 -> risk-conditional blend (8 bins)
 -> risk-conditional blend (10 bins)
 -> risk-conditional blend (12 bins)
 -> equal rank ensemble
 -> exact-duplicate correction

Public foundation and attribution

The main predictive strength came from the public 205-member OOF fusion in:

Byer/HBoyang, S6E8 Rank-Logit-Regime Fusion:
https://www.kaggle.com/code/hboyang/s6e8-rank-logit-regime-fusion-lb0-97125

That notebook also credits the public OOF libraries it consumes. I do not claim
those base models as original work. My additions were the inference-consistency
fix, the risk-conditional blending layer, repeated validation audits, and the
exact-duplicate post-processing.

I also trained local lookup, XGBoost, LightGBM, and Transformer models using
ideas adapted from Tamerlan Omralinov's Apache-2.0 notebook:

Tamerlan Omralinov, S6E8 | Lookup-Transformer + Insights:
https://www.kaggle.com/code/tamerlanomralinov/s6e8-lookup-transformer-insights-lb-0-97041

These local models were useful for experiments but were not the main source of
the final ensemble's performance.

Validation and inference consistency

The source fusion selected its top-level alpha on two ranked OOF inputs, but its
published test path mixed a raw probability input with a ranked input. Since
ROC AUC depends only on ordering, I applied a strict ordinal rank transform to
both inputs on both train and test.

An uncapped nested five-fold search selected blend weights
[0.725, 0.725, 0.725, 0.725, 0.825]. I used their mean, alpha = 0.745, at
inference. A separate fine-grid scan peaked near 0.74, and the 0.70–0.80 region
was broad rather than a sharp optimum.

This correction moved OOF ROC AUC to 0.970422 and improved every one of 15
validation slices checked.

Risk-conditional blending

A single global alpha assumes that the two meta-models have the same relative
value across the full score distribution. That was not true in OOF.

For each row, I computed a risk coordinate as the mean of the two input ranks.
Rows were assigned to equal-width rank bins, and a separate alpha was selected
inside each bin on OOF predictions. Bins containing only one class fell back to
the global alpha. Finally, I ranked the combined predictions again.

I built three variants with 8, 10, and 12 bins and averaged their final ranks.
The progression was:

Exact-duplicate post-processing

Two test rows had complete feature vectors that appeared exactly once in the
training set. Their matching training labels were unambiguous, so I replaced
those two predictions with the corresponding labels. This affected only test
IDs 735378 and 862871.

What did not work

Several ideas looked better in honest OOF but did not transfer to the hidden
test split:

A seven-variable soft student improved all 15 local validation slices, but
its private score was lower.

A depth-9 pair-target-encoding model raised local OOF further, but also lost
on the final leaderboard.

Residual anti-blends achieved the best local OOF (0.970705) and passed
nested-fold audits, yet produced the weakest hidden-test result among the
late candidates.

Expanding the public pool from 205 to 214 members and training additional
Rank-Gauss stacks added almost no OOF value.

Local Lookup-Transformer, XGBoost, and LightGBM models were useful standalone
baselines but were too weak or too correlated to improve the public fusion.

The main lesson was that tiny OOF improvements were not automatically reliable
under the train/test shift. The conservative rank-aligned risk-bin ensemble was
more robust than the more aggressive residual corrections.

Reproducibility notes

Metric: ROC AUC

OOF protocol: stratified five-fold validation, with repeated slice and
nested-weight audits for promoted blends

Final blend alpha: 0.745 before conditional weighting

Conditional variants: 8, 10, and 12 risk bins

Final post-processing: strict percentile rank plus two exact-duplicate labels

Thanks again to all public contributors. The most useful part of this
competition was learning how much care is needed when transferring a small OOF

### 233rd Place Solution

来源：https://www.kaggle.com/competitions/playground-series-s6e8/discussion/738691

First off, congratulations to all participants and especially the top finishers! This was a fun and highly competitive tabular playground challenge. I managed to finish 233rd out of 3,540 teams (Top ~6.5%) with a final private score of 0.97101 (Public: 0.97128), working strictly with free/local resources.

Here is a full breakdown of the pipeline, feature engineering, experimental validation, and lessons learned.

1. Overview & Strategy Summary

The core philosophy of our approach was disciplined out-of-fold (OOF) cross-validation to prevent overfitting to the 20% public leaderboard split, combined with exploring genuine model/feature diversity.

Key components of the final solution:

Feature Engineering: Ratio features, time-budget residuals, interaction terms, and a multi-level target-encoding lattice.

Adversarial Validation: Verified feature drift between train and test splits (Adversarial AUC: ~0.565, confirming high distribution stability).

Pseudo-Labeling Experimentation: Tested high-confidence pseudo-labeling (>98% / <2% thresholds) on the Lattice Triad.

Ensembling / Stacking: 177-member multi-seed OOF stack integrated with an elite anchor stream via percentile-rank averaging.

2. Feature Engineering & The Lattice Structure

We developed custom domain features focusing on screen-time mechanics and behavioral ratios:

Screen Time Accounting Residual: 
time_accounting_residual = daily_screen_time_hours - (social_media_hours + gaming_hours + work_study_hours) (only calculated when all 4 fields are present to avoid manufactured residuals).

Behavioral Ratios:

free_time = 24.0 - sleep_hours - work_study_hours

screen_to_free_time = daily_screen_time_hours / (free_time + 1e-3)

minutes_per_app_open = (daily_screen_time_hours * 60.0) / (app_opens_per_day + 1e-3)

social_per_age = social_media_hours / (age + 1e-3)

weekday_screen_time = (daily_screen_time_hours * 7.0 - weekend_screen_time * 2.0) / 5.0

Target-Encoding Lattice:

Generated out-of-fold target encodings across pairs and triples of categorical and binned continuous features with smoothing (smooth=20.0) inside a Stratified 15-Fold cross-validation scheme.

3. Adversarial Validation (Drift Check)

Before finalizing submissions, we conducted an adversarial validation experiment:

Combined train and test datasets (dropping addicted_label) and labeled them is_test = 0 vs 1.

Trained a 5-fold LightGBM model to detect distribution shifts.

Result: Total Adversarial AUC was 0.5654, confirming that train and test distributions were nearly identical and highly stable against private shakeups.

5. Key Takeaways & Lessons Learned

Feature Space Saturation: In synthetic tabular datasets of this type, pure tree-based models hit a mathematical ceiling relatively quickly. Incremental gains from additional tree models saturated near 0.97128 public.

The Importance of Honest Local CV: When multiple submissions tied at 0.97128 on the public LB, trusting the submission with the highest honest local OOF CV (the 177-member stack blend at 0.97009 OOF) proved solid and held up on the private leaderboard.

Next Frontier — Deep Learning on GPU: The top finishers were able to pull ahead by utilizing large-scale GPU-accelerated Neural Network architectures (MLPs/ResNets) alongside GBDTs. Setting up GPU pipelines for deep tabular models will be our primary focus for upcoming playground episodes.
