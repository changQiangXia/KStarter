### #3 solution 

来源：https://www.kaggle.com/competitions/playground-series-s3e13/discussion/406409

3rd place solution Playground Series - Season 3, Episode 13

I want to express my gratitude to the organizers at Kaggle for putting together the Playground Series. As a beginner, participating in these competitions can be very challenging but they can teach valuable skills.

I would also like to give a special thanks to @Matt OP, @Tanoi, @Elric and @broccoli beef for sharing their expertise in their respective notebooks: 

https://www.kaggle.com/code/mattop/ps-s3-e13-important-features-for-each-disease/notebook 

https://www.kaggle.com/competitions/playground-series-s3e13/discussion/402933

https://www.kaggle.com/competitions/playground-series-s3e13/discussion/403493,

https://www.kaggle.com/competitions/playground-series-s3e13/discussion/403156

Their insights were invaluable and helped me greatly.

Here's what worked for me:

To start, I wanted to come up with a reliable validation method. Based on the previous Playground competition, I decided to use RepeatedStratifiedKFold. I selected k and n based on the average validation score, standard deviation, and standard error of the mean. I found that 10 repeats of 10-folds seemed to be a good choice to assess the validation scores.

For my baseline method, I used SVC, which had a validation score of 0.367 +- 0.025 std.

I used the features provided by Tanoi and found that including 'kidney-failure' resulted in a cross-validation score of 0.370 +- 0.025.

I also grouped features based on their names and added up their values. For example, I added up the values of features that contained the words pain, loss, or inflammation. Including the summed-up features containing the word pain improved the cross-validation score to 0.375 +- 0.026.

I also included polynomial features and selected a feature pair that resulted in the highest cross-validation score: 'back_pain' and 'yellow_skin', this gave a score of 0.3937. Next, I further tested including additional pairs of polynomial features ('itchiness', 'bullseye_rash', and 'diarrhea', 'hypoglycemia'): the corresponding validation score further improved to 0.3989.

Feature selection: I preselected some algorithms that performed well on the initial feature set and checked what would be a good VarianceThreshold cutoff rate for them. I tested XGBClassifier, SVC, BernoulliNB, NuSVC, and LGBMClassifier. All of them resulted in the highest cross-validation score when using a threshold of 0.1. These were all the algorithms that I used for the final ensemble without weighing.

The public score of my final submission was 0.37089, and the private score was 0.52302.

Here's what did not work or might have worked:

Due to the vast amount of original features in the dataset, I thought that clustering techniques would be beneficial to this task. I tried several of them, including MeanShift, Birch, BisectingKMeans, and KMeans. MeanShift had the best cross-validation score of 0.357 +- 0.039, so it did not provide any improvement.

I also tried dimension reduction techniques, such as PCA, but did not invest too much time into them. It might be worth exploring more in the future.

### MAP@3 explained

来源：https://www.kaggle.com/competitions/playground-series-s3e13/discussion/402411

The competition provides a summary of the metric and a code to generate required predictions. This metric is new to me, so I read those two links and do a bit more research. In this post, I will try to explain what I learnt from them in my own understanding.

Why a new metric?

So far this year, all playground classification tasks are binary: positive/negative classes. This is the first time, we have a multi-class classification problem: 11 diseases.

For binary classification, we often use either ROC AUC or log loss. In both metrics, we submit predicted probabilities. The ROC curve shows how well the model is able to rank these probabilities for the positive and negative points. Log loss is more about absolute value of the predictions (e.g., if a point is positive (1.0), the prediction of 0.9 will have a better score compared to the prediction of 0.8; however if a point is negative (0.0), the prediction of 0.9 will pay a stronger penalty).

For multi-class classification, negative log-likelihood (an extension of logloss) can be used. If the classes are balanced, simple accuracy is an alternative. However, in this competition MAP@3 is chosen. 

The limitation of those metrics is that only the most probable prediction is considered. For example, in a 1000-way image classification, predicting the correct class is really difficult if you only have one chance, and it's not very useful to compare model performance if all models perform poorly on their top choice. We need a more forgiving metric. 

What is it all about?

Top-5 accuracy is one metric where you can submit 5 predictions and you get a full point if any of them is the same as the true answer. MAP@3 is a similar metric but it takes into account the order of your predictions: you get a higher score if you're correct at your earlier guesses. 

In MAP@3:

for each row: the solution is X and you make 3 guesses [A,B,C]. If you're correct in your first choice (X==A), you get a full point 1.0. If X==B, you get 0.5. And if X==C you get 0.33.

then you simply take an average of those scores.

The provided code is a bit complicated because the ground truth could be a list (like in movie recommendation). But in this competition it's just a single disease. So, it's reduced to a very simple form.

Is it a reasonable metric?

Yes, I think so, considering this example. You go to see a doctor because you have a fever. Based on your symptoms, the doctor thinks you might get a common cold, a flu or covid; in that order of reducing probability. Then, the doctor could ask you to carry out some tests to check if you have a common cold or not (well, I'm exaggerated here). If it's actually a common cold, full stop. Otherwise, you need to be carried out another examination to see if you have a flu, and so on. So, apparently, it's important to consider multiple predictions and the earlier the doctor guesses right, the better.

Thank you for reading.

Hey guys. Sorry for posting the code so late. Below is a summary of my approach.

The dataset was quite small if we consider the number of levels of the target variable, so I assumed that:
