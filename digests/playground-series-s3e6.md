### 1st place public / 2nd place private leaderboard solution

来源：https://www.kaggle.com/competitions/playground-series-s3e6/discussion/389391

Thanks for the congratulations on building a stable model for this competition! Tbh, I was shocked it was as stable as it was. As I am seeing a number of requests for an explanation of what I did, I described my process below:

There were 5 core parts of what I did to the data to get to my results: Data Preparation, Initial Regression Modeling, Classification using XGBoost and SMOTE, Price per Square Meter Modeling, and then what I called Price Adjusting. 

Data Preparation

Drop 'cityCode' attribute

Use the Test data frame to determine what data points from the training data were outliers. Anything that had an attribute value higher than the max value in the Test data frame, I dropped. Essentially, I tried as best as possible to make the training data look like the test data.

Split the data into training and test data (I used 20% test)

Normalize the data using MinMax scaler

Initial Regression Modeling

Train an XGBoost Regressor and a Random Forest Regressor

Use the average of the two regressor's predictions to predict the test data

This gave me an initial public score of 110001. The next steps I took were to adjust these prices predictions to lower that score.

Classification using XGBoost and SMOTE

This was based off of the findings from this discussion post: https://www.kaggle.com/competitions/playground-series-s3e6/discussion/384412

Essentially, I categorized each data point by the price per square meter. The three categories were $10/square_m, $100/square_m, and $1000/square_m. 

Add labels to the training data using the above measures

Use SMOTE to balance the data for each classification (the data was VERY imbalanced toward the $100/square_m category).

Train an XGBoost Classifier using the data from SMOTE

Predict the classification of the test data

In previous submissions I had tried to use this classification as a feature in the regression model, but the results were subpar. It turned out that even 1% misclassification would massively increase the error. Therefore, as you will see below, I used this classification very conservatively. 

Price per Square Meter Regression

Using the training data, train 3 different linear regression models on square meter v.s price: one for $10/square_m, one for $100/square_m, and one for $1000/square_m.

Price Adjusting

This was the part that really boosted the score. 

I used a combination of the classification with the predicted price from the initial regression model in order to adjust the regression price predictions. Because I knew that all price predictions should be around the 10, 100, 1000 price per square meter lines I used the below algorithm to fix the initial regression predictions on the test data:

If the price per square meter (from the initial regression model) was over $110 and the classification was for $1000, then I predicted the price using the $1000/square_m linear regression model. Else, I used the $100 linear regression model. 

If the price per square meter was less than $50, then I just fit it all to the $10 linear regression model. 

If the price per square meter was greater than $50 and less than $110, I just fit it using the $100 regression model. 

Applying this last step of price adjustment took my public score from a 110001, with just using the Initial Regression model, to a 77494.

### Playground Series - Season 3, Ep.6 🎉 5th place 🎉

来源：https://www.kaggle.com/competitions/playground-series-s3e6/discussion/389145

Hey kagglers 👋!!

My first attempt in open Kaggle competition is end with great results!

I trust 98% my cross validation (CV) and I took the 5th place, and If I trust it 100% I would take the 3rd place, but this should be a lesson for me! DON'T TRUST THE PUBLIC LEADERBOARD!!

My solution notebook is here: https://www.kaggle.com/code/mscgeorges/pss36-multi-stratifiedkfold-votingensemble

Things that worked 🔥

Remove outliers - Run IQR for each column and remove the rows with the outliers (just 20 records). The outlier removal was not so important for the final model performance but it was important for the CV, because the RMSE metric is very sensitive to outliers and can lead to missleading results.

Piece-Wise model (I like the terminology from @PRASAD)- Split the models based on different periods (based on made column). The best score was by spliting the data in 4 periods.

Multi-StratifiedKFold - Run StratifiedKFold many times with different SEEDS. This give me the confidence to have good statistics about model performance (MeanScore +/- SD). The second key point is the selection of the "Statified" CV. Due to "Piece-Wise model" approach I had to stratify the data based on the "made" column in order to have consistent results.

Ensemble Model - From CV I observed that different models (e.g Random Forest, XGBoost) had case that were good and others are not, so an ensemble model created a more stable solution.

Low number of estimators - I used few estimators because with more estimators the models were overfitting in data noise

Use all the features (except CityCode) - The most dominant feature was the size of the house (squareMeters column). It was the only feature with significan correlation (~ =53%) with the target and feature importance (~ =99%), all the others were look to be noise. But the CV show me that the other features were play some role and maybe in edge cases were helping the model to take the right decision, so I keep them!

No extra features - After searching for artificial features that would probably help the model performance, I couldn;t find features which improve the CV score, so I didn't use any extra features.

Include original data - The original data were looked different (based on Adversarial validation) but If we keep only the squareMeters columns the dataset were approximately the same, so I tried to include them in the training dataset and the results were better.

### Discard 30 % of the data!

来源：https://www.kaggle.com/competitions/playground-series-s3e6/discussion/384915

Utkarsh Gaikwad's notebook has been at the top of the public notebooks for three days now with a rmse of 127439. It uses Pycaret, an open-source, low-code machine learning library that automates machine learning workflows.

What does Pycaret do in this notebook?

It cross-validates and compares 20 different models with default hyperparameters and finds that RandomForestRegressor gets the best RMSE.

It refits the RandomForestRegressor with default hyperparameters to 70 % of the training data.

It predicts the test prices with this model.

Note that

You can make Pycaret tune the hyperparameters by calling tune_model(). The notebook doesn't.

You can make Pycaret refit the model to the complete training data by calling finalize_model(). The notebook doesn't. 

The obvious question is: If we fit the same model to the whole training data, does the score improve? More data is always better, isn't it? I did the experiment and the score deteriorated from 127439 to 155871.

Lesson learned: Discard 30 % of the data and you get a better score! 🙃

Perhaps there is something else to be learnt: The competition has been set up so that rmse fluctuations of >10000 points are standard. Don't be fooled by these fluctuations when you compare different approaches!

### 9th Place Solution

来源：https://www.kaggle.com/competitions/playground-series-s3e6/discussion/389151

My brief write-up of the 9th place solution can be found in the attached link. 

https://www.kaggle.com/code/brendanmoore14/9th-place-solution

A simple automl approach using autogluon, with the original data included within the training loops, but not the cross-validation, ended up being my highest local cross-validation. 

I used a 5-fold StratifiedKFold split, with the classes being the three groups of price/sqm (~10/sqm, ~100/sqm, and ~1000/sqm). 

I tried multiclass classification on these three groups, but it ultimately did not improve the modelling. 

Feature engineering, oversampling of the minority classes (~10/1000/sqm), and undersampling of the majority classes (~100/sqm) were also not helpful in my experimentation to improve the local cross-validation. 

In the notebook, I have outlined what worked for me and what did not. Unlike some of the other top scores, I was not able to achieve high local cross-validation using a single model.
