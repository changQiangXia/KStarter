## write-up 正文（8 篇）

### 1st Place Public - Shakedown to 967th Place Private - Hahaha

来源：https://www.kaggle.com/competitions/novozymes-enzyme-stability-prediction/discussion/376116

Wow, big shakedown. It hurts! Congratulations to all teams that did well on private leaderboard. Impressive!

I spent a lot of time on this competition, so I will share my approach. I did have an unselected submission that would have won 1st place private so I believe there are things to learn from my solution.

Solution Summary

Like everyone, I struggled to create a local validation. Since the test data was one enzyme, I decided to use public test as my validation. So my strategy was as follows:

Generate as many strong single model/features as possible

Probe LB to acquire the public test labels via mathematical optimization

Train one model using my single models as features and public test labels as targets

This approach worked well. But i had no way to know which trained model was best. For my final two submission, I chose to use (1) hill climbing with positive weights and (2) hill climbing with positive and negative weights because i felt these two model will not overfit and would do well on private. Their public LBs were 609 and 645 respectively which seemed good. 

During the competition, I also trained (3) a random forest with sklearn default settings but i suspected it was overfitting because RF allows for non-linearities and interactions. In retrospect, the random forest was the best and achieved private LB 546 first place. 

[图 1: best.png]

Another reason I didn't choose RF was because its public LB was 0.829 which also suggested overfitting. After the competition ended, i changed the random forest hyperparameters to depth=4 and achieved public LB 655 and private LB 558! 🔥

[图 2: best2.png]

Probe LB

Since Kaggle LB returns an error if all of public prediction is zeros (and does not count against submission quota), we can determine the exact public/private split using only 2 quota submissions. We slowly move where our non-zero predictions are.

 
Public LB data is exactly df.iloc[:541] and df.iloc[1757:] and df.iloc[1169]. Public LB is residuals 16 thru 123 inclusive plus wildtype and private LB is residuals 124 thru 221 inclusive. So the public LB is the first half of residuals while the private LB is the second half of the residuals.

Once we know the public split exactly, it is a mathematical optimization problem to maximize public LB. Download all 350 public submission from all versions of public notebooks. Then find X such that the correlation of X with each of the 350 submission equals their LB score. Next create 5 new submission each day where submission.csv values are chosen to acquire the most information where your optimization is least confident. I ran my optimization algorithm 24 hours a day for 3 months, each day i uploaded my new 5 submissions and any new public notebooks to my optimization algorithm. My optimization algorithm achieved public LB 865 

Build Single Model/Features

While my optimization algorithm was running, I set out to discover new features and/or single models. I searched the internet, current research, etc. For each row of test data, compute feature (or infer model) and submit and observe LB score.

The Best Feature

The strongest feature on private LB was RSASA. No public notebooks nor discussions mentioned it. This is relative solvent accessible surface area. Robert posted a notebook here which submits SASA to LB and achieves public LB 407 and private LB 466. (Also RopeOnMars published SASA here). 

SASA is the surface area of an amino acid exposed to the outside (i.e. the solvent) of the enzyme. RSASA is the relative surface area (i.e. 50%, 75% etc of amino acid is exposed). This single feature (its not even a model, its just a single amino acid property but does require PDB structure) achieves public LB 442 and private LB 496.

### How To Use Kaggle's Train Data

来源：https://www.kaggle.com/competitions/novozymes-enzyme-stability-prediction/discussion/358320

Kaggle Competition Data

Many people are confused about this competition's data. When we download train.csv and test.csv from Kaggle, the datasets are very different. 

The test data contains 2413 rows and all 2413 rows come from the same one wild type protein. The rows of test data are 1 mutation applied to VPVNPEPDATSVENVALKTGSGDSQSDPIKADLEVKGQSALPFDVDCWAILCKGAPNVLQRVNEKTKNSNRDRSGANKGPFKDPQKWGIKALPPKNPSWSAQDFKSPEEYAFASSLQGGTNAILAPVNLASQNSQGGVLNGFYSANKVAQFDPSKPQQTKGTWFQITKFTGAAGPYCKALGSNDKSVCDKNKNIAGDWGFDPAKWAYQYDEKNNKFNYVGK. We can create a test dataframe as displayed below with a column for wild type and a column for mutant sequence. Our job is to predict dTm the change in Tm.

The train data contains 31390 rows. These are many different proteins and come from many different wild types (or they are wild types themselves).

[图 1: k_test3.png]

Submission CSV

We must submit 2413 predictions in our submission.csv file. The competition metric is Spearman Correlation Coefficient which is a ranking metric. When Kaggle receives our predictions, the first thing they do is submission['tm'] = rankdata( submission['tm'] ). In other words the numbers we submit do not matter only their order matters. (Next they take the Pearson Correlation Coefficient of our ranked predictions compared with ranked ground truth. That becomes Spearman) Therefore instead of submitting Tm we will submit dTm. Both quantities have the same rank ordering and will achieve exactly the same CV LB.

Step 1 - Find Groups in Train

The first step in using competition train data is to find groups of similar proteins that differ from each other by 2 or less mutations. This is shown in the diagram above. After finding groups, we can deduce the group's wild type by finding the most common amino acid letter for each position shown below. In most cases, the train wild type is not in Kaggle train data. This is not a problem.

[图 2: k_train3.png]

Step 2 - Find Wild type

After we deduce each train group's wild type, we can create a new dataframe with pairs of wild type and mutant sequence. Each pair is mutation distance 1 just like test data. We now have train dataframe that is similar to test dataframe. We can now train our model with this train dataframe and predict the test dataframe

Step 3 - Filter Based on Data Source and pH

Within each group, we need to decide how to deal with different data source and pH. This is still an ongoing discussion. The easiest thing to do is to count the occurrences of each unique pair of data_source and pH. Then within each group keep only the rows with the pair of highest count and discard the rest. There are many other things we can do, but we must do something and we must be aware that different data sources and different pH can affect the relative Tm of different rows if we do nothing.

Step 4 - Rank Normalize Targets

The last step is to rank normalize the targets. We do not know the Tm for the train wild type because most often it is not in Kaggle's train data. This isn't a problem. Based on the Tm for the mutant sequences we know which dTm would be largest and which would be smallest. For each group take all the Tm, rank them from 1, 2, 3, ..., N-1, N. And divide by N to get 1/N, 2/N, 3/N, ..., (N-1)/N, N/N. This will be our new target to train our models with. It is best to remove groups with group size less than some value like 25. Otherwise the small groups will have too many rank normalized targets of 0 and 1 and bias our model training. (Alternatively we can keep small groups and smooth their targets see comment section for more info).

### 11th place solution

来源：https://www.kaggle.com/competitions/novozymes-enzyme-stability-prediction/discussion/376147

I want to start by expressing my admiration for many competitors who figured out how to navigate a terrain that was completely foreign to you. More importantly, you were so gracious to share those insights with us. It takes a long time to figure out the domain knowledge needed for protein modeling, using protein language models, to perform energy and molecular dynamics calculations. Yet many of you did it and made it easier for us to have a meaningful and productive competition. Thank you!

You will have heard this in other write-ups by now, but I will still repeat it: ensembling the solutions is the way to go.

I started this competition on a lazy note, mostly because it was not obvious how the train dataset they provided could be used without a major time investment. There were several very nice solutions based on test data alone, so I went along with that. Like everyone else, I was figuring out what molecular quantities we can calculate from test data are most informative, and how to blend them to get the best score. Along the way I kept warning that pLDDT values and B-factors are not really predictive of thermal stability, yet there was enough evidence they worked fine for this protein. At some point in the middle of Octobar, as I fortuitously sat in the 3rd place, it occurred to me that I needed to decide: focus on getting the best result on this nuclease, or try to make the best general model that will hopefully work on this protein. It is difficult to give your best effort until you fully commit, so I went with the latter option.

I knew already that Rosetta’s energy function worked well, but had never used FoldX before for the purpose of mutagenesis. It turns out that FoldX scores alone on test data got me to ~0.47 on public LB. I used Rosetta’s lesser-known programs ddg_monomer and pmut_scan which are designed to score mutants. pmut_scan alone scored 0.499 on public LB, which convinced me that it is imperative to use these programs and their physics-based energy functions. In parallel, I started building a train dataset, and doing a full-scale AlphaFold2 modeling of all wild-type proteins and mutants. In the end the total was 2335 test mutants and 2964 train mutants, of which the last 300 PDB models or so are yet to be completed. That gave my GPU a constant workload since early November. It was relatively easy to get dTm values for the first 1000-1500 train mutants that had a good match between residue numbers and were measured at a single pH value. It became difficult to do it in the second half, as I was manually verifying that protein residues matched PDB residues, had to find which pH value was physiologically relevant before including them, and so forth. It took until mid-December to complete the train dataset (except for AlphaFold2 modeling), but eventually I had 2964 curated mutants for training. Extracted ~50 features from PDB files, calculated FoldX, ddb_monomer and pmut_scan scores, did ESM2 and ProtT5 embedding and subtracted mutant values from the wild-type. Finally, I symmetrized the dataset by adding the minus sign to dTm and all other quantities. This was now a tabular dataset that could be modeled using any ML approach, and I chose LightGBM for speed and TabNet for diversity of its models. When this dataset was stratified by dTm and divided 75:25 train:test, I got ~0.6 10-fold CV, and 0.65 Spearman correlation coefficient on test data. It seemed to work, and I think it will work even better in predicting ddG as opposed to dTm. I will paste below the relative importance of features as determined by SHAP from LightGBM trees. You will see that energy-based features (FoldX, ddg_monomer and pmut_scan scores) were most important, followed by language embedding expressed as PCA components. Structural features extracted from PDB files worked relatively well on their own (~0.5 10-fold CV), but when they were in a big feature set very few of them made it to top 50 features by importance.

Now it was time to test this model on our nuclease and – womp, womp - it didn’t work very well. Best LightGBM models were scoring 0.47-0.5 on public LB, while best TabNet models were in the 0.45-0.48 range. All of them had considerably higher CV scores and behaved well when I set a general test dataset aside, but that didn’t translate to Novozyme’s protein. Eventually I blended 5 LightGBM models and 2 TabNet models that scored 0.531 on public LB and 0.511 on private LB. That was a good score given our assumptions at the start of this competition, but it wouldn’t have been good enough for any medal.

In the last two weeks I went back to my test-based models, and decided to blend them with my LGB and TabNet model from general training. Since I didn’t have out-of-fold data here to guide the blending process, that had to be done again using only public LB scores as a guideline. This always involves luck. In the end I chose an equal blend of publicly available ThermoNet V3 (I think it scored ~0.59), my pmut_scan model (0.499), a slightly different SASA model from the one I published (0.453), a slightly different depth model from the one I published (0.42), two LGB models from general training that scored 0.505 and 0.5 and a single TabNet model that scored 0.477. That blend had 0.604 on public LB and 0.529 on private, which was in the end my best submitted score. There were >20 blends with either 2 or 3 TabNet models that scored in high 0.53s on private LB, but I didn’t select any of them based on lower public LB scores.

There were many other things that didn’t work, and several for which I am not sure yet if they work. I will add them later to this post or write a separate topic.

Thanks again to all of you for your support and kind words throughout the competition and especially in the past two days. I always learn something from each competition, and this one was no different.

### 2nd place solution & private LB 0.577 QUICK OVERVIEW

来源：https://www.kaggle.com/competitions/novozymes-enzyme-stability-prediction/discussion/376134

Hi everyone! My solution is very simple. It's just an ensemble of different methods and a little smoothing at the end. 

a quick overview:

[图 1: inbox%2F3350264%2Fc36a345c2440a24230fb59f7e6023607%2Fwhole.png]

In the +ve weights block we have different methods. let me know if you want the explanation of each of them separately, I will make another post for it but as they are available on the internet, I didn't write about them here.

I'm assuming that up to the ensemble, everything is clear.

Now coming to the smoothing part:

for me, combing ML models (the ones I have mentioned) with the positive block drops the score, my assumption is that it makes the values extreme. even if we overfit the public LB, we might drop the private LB. 

Private LB was mostly from ~500 rows to ~1600 rows so if we have extreme values based on public LB, this part of private LB could drop significantly. So to avoid shakeup we needed some smoothing.

Now we have many methods for smoothing, we could simply try log transform but the problem is we don't know which part of the prediction needs smoothing and which doesn't. one method to solve this is to train a neural network but as we have training data belonging to different distributions, this won't help us here. 

So I did something risky: I ensembled all the ML models and subtracted them from the ensemble.

let's say we have an ensemble prediction of 0.9 and ground truth of 0.5 and an ML prediction of 0.6. now subtracting ML prediction from ensemble 0.9-0.6 = 0.3 will put us a little closer to 0.5.

The reason I called it risky is that if you didn't set the right weights, you will fall terribly on private LB. assume ground truth and ensemble both 0.9 and ML pred as 0.6. it will add a big error difference here.

So to make it work, we need to set weights based on CV scores but in this competition, we don't have similar training data so I had to set the weights based on public LB. 

With different combinations of the above, I was able to make about ~30 submissions in the range of private scores 0.545 to 0.577. I found their private and public score a little reliable and correlating.
