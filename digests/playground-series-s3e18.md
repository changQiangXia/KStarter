Domain Knowledge Regarding the Data By Luis Frentzen

Interesting post providing an overview of the multi-label classification problem we are faced with on this competition.

Some key points:

Task: Input: Molecules | Output: Classified into their respective Enzyme Commission (EC1 and EC2) classes.

Dataset: Each row represents a molecule to be classified into it's corresponding EC classes.

Target: The EC number is a numerical classification scheme for enzymes based on the chemical reactions they catalyze. (EC Classes: Oxidoreductases, Transferases, Hydrolases, Lyases, Isomerases, Ligases.)

Data Source: The dataset is synthetically generated from the Multi-label Classification of enzyme substrates dataset.

Imbalanced Classes: The target variables have an imbalanced distribution.

 
The Features:

 
Molecular Descriptors:

 

 
ExactMolWt: Exact molecular weight

 
HeavyAtomMolWt: Molecular weight of heavy atoms only (excluding hydrogens)

 
NumHeteroatoms: Number of heteroatoms (atoms other than carbon and hydrogen)

 
These variables provide information about the size, weight, and presence of specific atoms in the molecule.

 

 
Connectivity and Structural Descriptors:

 

 
BertzCT: Bertz complexity index

 
Chi1: 1st order molecular connectivity index

 
Chi1n: Chi1 normalized

 
Chi1v: 1st order molecular variance connectivity index

 
Chi2n: 2nd order molecular connectivity index

 
Chi2v: 2nd order molecular variance connectivity index

 
Chi3v: 3rd order molecular variance connectivity index

 
Chi4n: 4th order molecular connectivity index, normalized

 
These variables capture different aspects of the connectivity and complexity of the molecule.

 

 
Surface Area Contribution Descriptors:

 

 
EState_VSA1: Electrotopological state

 
EState_VSA2: Electrotopological state

 
PEOE_VSA10: Partial equalization of orbital electronegativity Van der Waals surface area contribution for a specific atom type

 
PEOE_VSA14: Partial equalization of orbital electronegativity Van der Waals surface area contribution for a specific atom type

 
PEOE_VSA6: Partial equalization of orbital electronegativity Van der Waals surface area contribution for a specific atom type

 
PEOE_VSA7: Partial equalization of orbital electronegativity Van der Waals surface area contribution for a specific atom type

 
PEOE_VSA8: Partial equalization of orbital electronegativity Van der Waals surface area contribution for a specific atom type

 
SMR_VSA10: Solvent-accessible surface area Van der Waals surface area contribution for a specific atom type

 
SMR_VSA5: Solvent-accessible surface area Van der Waals surface area contribution for a specific atom type

 
SlogP_VSA3: LogP-based surface area contribution

 
VSA_EState9: E-state fragment contribution for Van der Waals surface area calculation

 
These descriptors provide information about the surface area contributions for specific atom type fragments within the molecule.

 

 
Fingerprint Density Descriptors:

 

 
FpDensityMorgan1: Morgan fingerprint density for radius 1

 
FpDensityMorgan2: Morgan fingerprint density for radius 2

 
FpDensityMorgan3: Morgan fingerprint density for radius 3

 
These descriptors represent the density or count of specific substructures in the Morgan fingerprint.

 

 
Classes:

 

 

EC1: Binary feature, to be predicted label (Oxidoreductases)

 

 
Catalyze oxidation-reduction reactions, involving the transfer of electrons between molecules.

 

EC2: Binary feature, to be predicted label (Transferases)

 

 
Transfer functional groups (e.g., methyl, acetyl, phosphoryl) between molecules.

 

EC3: Binary feature of the EC class (Hydrolases)

 

 
Catalyze the hydrolysis (breaking of chemical bonds with water) of various substances.

 

EC4: Binary feature of the EC class (Lyases)

 

 
Catalyze the addition or removal of groups from substrates without hydrolysis or oxidation.

 

EC5: Binary feature of the EC class (Isomerases)

 

 
Catalyze the rearrangement of atoms within a molecule to form isomers (same molecular formula, different arrangement).

 

EC6: Binary feature of the EC class (Ligases)

 

 
Catalyze the joining of two molecules through the formation of new chemical bonds.

 

Note about the features: Some features are highly imbalanced.*

Implementing the metric optimally By Ravi Ramakrishnan

The competition rules state that we are measured with AUC for each target and the final score is an avg AUC of each predicted column.

But some notebooks are using a different implementation: They calculate the GINI score by converting the GT and the predictions into a single continuous array of EC1 and EC2 stacked together.

Further testing a more accurate implementation yields scores that are less optimistic (and more realistic) than the ones reported in the notebooks.

Another implementation in the comments (broccoli beef):

def (y_true,y_pred):
 return np.([(y_true[:,i],y_pred[:,i]) for i in (y_true.shape[])])

Less is perhaps more for EC2 By Ravi Ramakrishnan

EC2 is harder to predict than EC1. (Our predictions are just above random)

There are values in fr_COO and fr_COO2 that appear in test data but NOT in training data By bogoconic1

We have a situation here!

Some integer_values/categories appear in the test data but not in the training data. (Columns: fr_COO and fr_COO2)

Also from the comments:

Konstantin Dmitriev Added that there is no fr_COO == 7 and fr_COO2 == 7 in both train and original datasets.

And that NumHeteroatoms == 40 and NumHeteroatoms == 48 are also absent both in train and original datasets.

 
I would like add a trick for these types of problems:

 The most obvious solution would be to remove out of distribution values from the test data on prediction [or to clip them].

 BUT there is another trick for this: Frequency encoding.

 You basically use something like df.groupby('column').transform('count') / len(df) to create a new feature based on the frequency of each value in the column.

 And this work also in test time because what you say to the model is "A value that is rare". This is WITHOUT specifying the value itself. So OTHER rare values that are present in the training set hold the same information.

 [This example is just one way to do this, search for "frequency encoding" if you want to see many variations of this method. I just wanted to point this out! :)]

### Domain Knowledge Regarding the Data

来源：https://www.kaggle.com/competitions/playground-series-s3e18/discussion/419646

This time we focus on multi-label classification where we are tasked to predict the variable EC1 and EC2. The dataset is synthetically generated from the Multi-label Classification of enzyme substrates dataset. Each row represents molecules that we need to classify their EC (Enzyme Commission) classes. Enzymes are known to act on molecules with structural similarities with their substrates. The Enzyme Commission number (EC number) is a numerical classification scheme for enzymes, based on the chemical reactions they catalyze. It is stated that substrate molecules can belong to multiple EC classes at the same time, thus defining the multi-class classification problem. This problem is very crucial in fields like drug discovery and development, understanding enzyme function or metabolic analysis, and many more.

The dataset is quite large containing a total of 38 columns and 14.8k rows. However the original contains 3 csv files with each having around 200-500 columns.

Molecular Descriptors variables such as ExactMolWt (exact molecular weight), HeavyAtomMolWt (molecular weight of heavy atoms), and NumHeteroatoms (number of heteroatoms) give information about the size, weight, and presence of specific atoms.

Connectivity and Structural Descriptors variables like BertzCT (structural complexity index) and Chi descriptors (molecular connectivity indices) capture different aspects of the connectivity and complexity of the molecule.

Surface area contribution descriptors such as EState_VSA, PEOE_VSA, SMR_VSA, etc. provide information about the surface area contributions for specific atom type fragments within the molecule. Often involve calculation based on Van der Waals surface area contribution.

Fingerprint Density Descriptors like FpDensityMorgan1, FpDensityMorgan2 represent the density or count of specific substructures in the Morgan fingerprint.

Classes description:

EC1: Oxidoreductases

Catalyze oxidation-reduction reactions, involving the transfer of electrons between molecules.

EC2: Transferases

Transfer functional groups (e.g., methyl, acetyl, phosphoryl) between molecules.

EC3: Hydrolases

Catalyze the hydrolysis (breaking of chemical bonds with water) of various substances.

EC4: Lyases

Catalyze the addition or removal of groups from substrates without hydrolysis or oxidation.

EC5: Isomerases

Catalyze the rearrangement of atoms within a molecule to form isomers (same molecular formula, different arrangement).

EC6: Ligases

Catalyze the joining of two molecules through the formation of new chemical bonds.

In this post, I will be outlining my approach for S3E18. I treated the problem as two separate classifications instead of a multi-output classifier

In the preprocessing phase, I dropped HeavyAtomMolWt and fr_COO2 (since 99% of its values are same as fr_COO) and also removed erroneous records where FpDensityMorgan1 is -666. I then dropped the duplicate rows. The train set had 15824 records after preprocessing.

EC1

I used an ensemble of CatBoost, LGBM and XGBoost, all gone through Optuna hyperparameter tuning. This ensemble gave a local OOF CV score of 0.71205

Subsequently, I blended this ensemble with (1) and (2) for the EC1 prediction 

EC2

Note that the ROC_AUC score for EC2 is only ~0.58, just slightly better than a classifier that predicts all 1s. I tried doing an ensemble but did not get a local CV score of >0.592. ### Not "multi-label", but two competitions in one

来源：https://www.kaggle.com/competitions/playground-series-s3e18/discussion/420127

Although the term "multi-label classification" is in the competition title and has been mentioned several times during the last few days (e.g. here, here and here), I don't think that "multi-label classification" gives good models.

My viewpoint is that we have two separate competitions with common features, but distinct targets. There is no reason why a single model (with a single set of hyperparameters) would be optimal for both competitions. When I tuned a few models for either target, the results depended very much on the target:

[图 1: inbox%2F7917824%2F972524f20bfbeff02767d6de46afe59a%2Fbars(1).png]

K nearest neighbors needs 1180 neighbors to predict EC1; for predicting EC2 it's better to look at only 490 neighbors.

In predicting EC1, a random forest wins against ExtraTrees, whereas for EC2 it's the opposite.

Logistic regression is better than KNN for EC1 but not for EC2. This indicates that EC1 could be almost linearly separable while the decision boundary for EC2 is completely nonlinear.

Conclusion: Don't try to predict both targets at once — think of the two targets as two separate competitions.
