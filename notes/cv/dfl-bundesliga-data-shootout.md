## 1. 任务与数据

- 预测目标：由**足球转播视频**识别比赛事件（进球、角球等），输出事件类型与时间。
- 数据形态：广播视频（镜头会移动/切换）+ 事件标注。
- 构造陷阱：**相机运动**导致球员/球的位置不断变化；球体小、速度快、遮挡多；事件稀疏。

## 2. 方案谱系

| 方案 | 名次 | 关键点 |
| --- | --- | --- |
| 光流（相机运动补偿）→ 球检测 → 轨迹代价最小化 → 两阶段动作识别 → 集成与后处理 | 2nd | 把视频任务拆成**五个可独立验证的环节**；用"轨迹代价最小化"跨帧精修球位置 |
| 其他方案 | 见讨论区 | |

## 3. 关键技巧

- **先做全局运动补偿**（光流估相机运动），再做目标检测——广播视频的必备步骤。
- **跨帧轨迹优化**（代价最小化）比逐帧检测更稳。
- **两阶段动作识别**（粗定位 → 细分类）。
- **模块化流水线**：每步可独立调试（与 Lux/Kore 的工程化思路一致）。

## 4. 可迁移性评估

- **可直接迁移**：
  - 视频任务先做**相机运动补偿**；
  - 用**轨迹级优化**替代逐帧独立预测；
  - 两阶段（定位 → 分类）的事件识别；
  - 把长流水线拆成可验证模块。
- 需要前提：光流/目标检测/动作识别工具链。
- 不建议照搬：直接用视频分类模型端到端（忽略相机运动）。

## 5. 对新手的关键启示

1. **广播视频 ≠ 固定机位**：先解决相机运动。
2. **时序一致性**（轨迹优化）比单帧精度更重要。
3. 与 NFL 系列（球员追踪）对照：体育视频任务的方法论（检测 + 追踪 + 事件）高度通用。

## 6. 轻读结论（2026-10 补）

**一句话**：德甲转播视频的事件检测（小目标球 + 稀疏标注 + 私榜未见比赛）——**两条路线都能夺冠**：1st 走"单阶段 2.5D+3D 灰度模型 + 推理工程"，2nd 走"光流→球检测→Dijkstra 轨迹→两阶段动作识别"；球附近的显式定位是分类的关键前置。

- 1st（Team Hydrogen，139 票）：1024² 灰度 + 15 帧（5 时间步 ×3 帧）；effnetv2_b0/b1（大主干过拟合）；**3D 卷积只在最后一块**；Mixup；BCE + 3 目标列（事件附近小窗口硬标签）；**SoccerNet 预训练 +0.02**（伪标签预训练失败）；推理 +128、只预测隔帧、双模型交替、后处理降假阳；单模型 2.5h / 双模型 ~5h；本地 0.857 与公榜强相关并最终全量重训。
- 2nd（K_mat）：自监督 RAFT 光流 → warp 差异通道 → 浅层 CenterNet 球热图 → top-10 峰值 → **Dijkstra 最低成本球轨迹** → 裁剪球附近区域 → 两阶段动作识别（2D+1D CNN → 浅层 1D CNN）→ 高斯滤波 + 峰值检测；工程参数 12.5fps/N=11/M=3/L=51/K=7。
- 社区：视频分类入门（75 票）、YOLOv5 球检测（49 票）、"沮丧的方法"（42 票）、外部数据（40 票）。

**裁决**：先配平"分辨率×帧率×模型数"推理预算；显式球定位是分类前置；时序可放网络（3D）或外置（光流/轨迹）。

**悬案**：3rd/4th/5th/6th 细节未细读；1st 的目标列与后处理未展开。
