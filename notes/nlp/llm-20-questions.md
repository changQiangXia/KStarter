## 1. 任务与数据

- 任务形式：经典的"20 问"游戏——一方（guesser）需要用尽可能少的问题猜出秘密词，另一方（answerer）或环境给出是/否回答。提交 agent 与平台内其他 agent 配对。
- 数据形态：候选词表 + 对话历史；需要**信息论式的提问策略**。
- 构造陷阱：
  - 提问质量决定信息增益（要问"能最大化区分候选"的问题）；
  - 关键词匹配的鲁棒性（对手的回答可能不标准）；
  - 工程复杂度高（多模块协作）。

| 其他方案 | 见讨论区 | |

## 3. 关键技巧

- **信息增益优先的提问策略**（二分候选空间）。
- **规则 + LLM 混合**：确定性逻辑负责可判定的部分，LLM 负责措辞与模糊理解。
- **模块化 + 大量测试用例**：高复杂度 agent 任务的可靠工程实践（9th 的明确做法）。
- **候选词表与关键词库**是核心资产。

## 4. 可迁移性评估

- **可直接迁移**：
  - **信息增益驱动的提问/查询策略**（检索、主动学习、诊断系统通用）；
  - "规则处理确定性 + 模型处理模糊性"的混合架构；
  - 复杂 agent 任务用**松耦合模块 + 测试用例**控制风险。
- 需要前提：对局规则与环境接口的理解。
- 不建议照搬：端到端 LLM 一把梭（可控性差）。

## 5. 对新手的关键启示

1. **"提问"也是一种可优化的算法**（信息增益）。
2. **agent 类任务先做工程拆分与测试**，再谈策略提升。
3. 与 Pokemon/Orbit Wars 对照：agent 比赛的胜负常由工程可控性决定。
