# Vibe Code with Gemini 3 Pro Hackathon（精简）

> 主题：other ｜ 子类：hackathon ｜ 类别：Featured ｜ 截止：2025-12-12 ｜ 队伍数：4083 ｜ 指标：人工评审
> 出处：`intel/gemini-3/`（讨论区索引 + 正文）

## 任务

用 Gemini 3 Pro 构建应用的创意黑客松，**提交物是项目与 write-up，由主办方人工评审**，不是预测任务。因此讨论区里数量最多的是"怎么写 write-up 才能被评审看到"这类元话题。

## 关键要点

- 参赛量极大（4083 队 ≈ 4100 份 write-up），评审方的阅读负担本身就是赛制的一部分。
- 讨论区高频主题几乎都与提交规范相关（write-up 是否可编辑、评审时间线、格式要求）。
- 这类比赛"技术含量"不体现在模型上，而体现在**产品完成度与表达**。

## 可迁移要点

- 遇到"人工评审"类比赛，**先读评审标准与提交规范**，再决定投入方向——与预测类比赛的逻辑完全不同。
- write-up 的表达质量直接决定成绩，这与预测类比赛（只看分数）形成鲜明对照。
- 对新手而言，这类黑客松是低成本上手 Kaggle 平台的入口，但**不能作为方法论的训练场**。
