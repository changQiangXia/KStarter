# Vibe Code with Gemini 3 Pro Hackathon（精简）

> 主题：other ｜ 子类：hackathon ｜ 类别：Featured ｜ 截止：2025-12-12 ｜ 队伍数：4083 ｜ 指标：人工评审
> 出处：`intel/gemini-3/`（讨论区索引 + 正文）

## 任务

用 Gemini 3 Pro 构建应用的创意黑客松，**提交物是项目与 write-up，由主办方人工评审**，不是预测任务。因此讨论区里数量最多的是"怎么写 write-up 才能被评审看到"这类元话题。

## 关键要点

- 参赛量极大（4083 队 ≈ 4100 份 write-up），评审方的阅读负担本身就是赛制的一部分。
- 讨论区高频主题几乎都与提交规范相关（write-up 是否可编辑、评审时间线、格式要求）。
- 这类比赛"技术含量"不体现在模型上，而体现在**产品完成度与表达**。

## 可迁移要点

- 遇到"人工评审"类比赛，**先读评审标准与提交规范**，再决定投入方向——与预测类比赛的逻辑完全不同。
- write-up 的表达质量直接决定成绩，这与预测类比赛（只看分数）形成鲜明对照。
- 对新手而言，这类黑客松是低成本上手 Kaggle 平台的入口，但**不能作为方法论的训练场**。

## 轻读结论（2026-10 补）

**一句话**：一周 vibe-coding hackathon：4083 队 / ~4100 份 write-up，**50 个奖 / 6 名评委**；官方因体量延期评审（69 票 / 207 评论），社区一边惊叹 write-up 质量（"205 页列表"）一边质疑评审可信度（AI 模拟评审、AI 评委）；工具侧被 429/配额、提交按钮卡死与"代码改动幻觉"困扰。

- 官方（651844/667609）：一周免费 AI Studio 额度；要"wow 因子"与影响力；评审超期、公布时间未定；获奖名单帖 23 票 / 116 评论。
- 社区审查（662567/668733/667965）：write-up 列表 205 页；"能信任 AI 评委吗"（15/25）；"用多个 AI 模拟评审"（7/10）。
- 平台问题（653500/660971/662435/655429）：429/配额、提交卡死、提交后能否编辑、Gemini 假称改代码。

**裁决**：超大评审制赛按"数月等待"计；产品完成度与叙事优先；保留可验证演示与开源链接；提前验证提交链路与配额。

**悬案**：获奖作品与 rubric 未收录；本场 0 图。
