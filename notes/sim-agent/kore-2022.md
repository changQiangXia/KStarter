## 1. 任务与数据

- 对局形式：太空资源争夺类对抗游戏（多单位扩张/对抗）。
- 特点：与 Kore Beta 同源，规则明确，**启发式策略空间大**。

## 2. 方案谱系

| 方案 | 名次 | 关键点 |
| --- | --- | --- |
| **纯规则方案**（在 Beta 版冠军思路上改扩张策略） | 1st | 作者自述本想学 RL，结果发现"改一个扩张策略"就能快速爬榜，于是**决定专注规则路线**，最终夺冠；开发方式"像做软件产品"（有清单、逐步迭代） |
| 其他方案 | 见讨论区 | |

## 3. 关键技巧

- **规则路线的上限常被低估**：本场冠军就是纯规则。
- **借鉴前一版本（Beta）的公开冠军方案**，只改动关键策略（扩张）即获大幅提升。
- **以软件工程的纪律开发 agent**（清单、迭代、可维护性）。

## 4. 可迁移性评估

- **可直接迁移**：
  - **先穷尽规则方案的上限，再考虑 RL**（成本低、可控性强）；
  - 在系列赛（Beta → 正式版）里复用并改进已有方案；
  - 用工程纪律组织 agent 开发。
- 需要前提：对游戏机制的清晰理解。
- 不建议照搬：一上来就上 RL（本场冠军的路径恰好相反）。

## 5. 对新手的关键启示

1. **新手的正确起点往往是规则策略**，而不是 RL。
2. **"改一个关键策略"常胜过重写整个系统**。
3. 与 Otto（纯规则进前三）、Santa 2021（手工解法）合并观察：**规则/手工方案在 Kaggle 上被系统性低估**。
