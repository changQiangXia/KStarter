## 1. 任务与数据

- **任务形式**：把 N 棵树（可旋转）尽量紧凑地放进一个正方形，最小化正方形边长。属于**连续 + 组合的几何包装优化**。
- **数据特性**：问题定义清晰、无噪声、无隐藏测试分布——**分数完全由优化质量决定**，是"纯优化"型比赛。
- **排行榜特点**：名次差距极小（小数点后多位），需要持续压榨；社区共享氛围强（有专门的 "Santa Etiquette" 规则帖）。

## 2. 验证与评估方案

- 无训练/验证集划分问题；评估就是**在本地精确计算目标函数**。
- 真正的"验证"是：**能否稳定复现并持续改进**——多位选手用更小 N 的解热启动更大 N 的解。
- 社区自建交互式编辑器（Interactive Editor）与可视化工具，用于人工检查布局。

## 3. 方案谱系

| 方案 | 名次 | 关键点 |
| --- | --- | --- |
| 遗传算法（分层种群交互）+ GPU 松弛 | 1st | 分层机制防止单一解主导种群；GPU 局部极小搜索大幅提高接受率；利用对称性降低自由度 |
| 矩形组合 + 定制 Sparrow（Rust）+ C++ 模拟退火 | 3rd | 用较小矩形解组合出大方形的初值；Rust 重写算法支持热启动；C++ SA 做最后压缩 |
| 模拟退火实战技巧 | 高票帖 | 退火调度、邻域设计、接受准则等经验总结 |
| "大 N 用密铺（tessellation）" | 高票帖 | 大规模问题的结构化初值构造 |
| 对称性分析（"为什么最优解是不对称的"） | 高票帖 | 用 24 核实验验证对称约束的代价 |

## 4. 关键技巧

- **两类算法交替**：全局搜索（GA / Sparrow）负责跳出局部最优，局部搜索（SA / 松弛）负责精修。
- **热启动 / 增量构造**：用 N 的解初始化 N+1 的问题（3rd 明确列为关键组件）。
- **工程性能决定上限**：Rust / C++ / GPU 重写是为了在同样时间内尝试更多候选解。
- **对称性利用与反思**：对称约束能减少自由度，但社区实验证明最终最优解是**不对称**的——需要数据来判断而非直觉。
- **社区协作**：可视化工具、密铺策略、退火技巧都是公开共享的公共知识。

## 5. 可迁移性评估

- **可直接迁移**：
  - **"全局搜索 + 局部精修"的双层结构**是所有组合优化问题的通用骨架。
  - 增量热启动（用小规模解初始化大规模问题）。
  - 用可视化工具人工诊断优化结果。
  - 性能工程（语言/GPU 重写）直接换算成分数。
- **需要前提**：
  - 目标函数必须能快速精确评估（本场成立）。
  - 需要较多本地算力（大量并行评估）。
- **不建议照搬**：
  - 具体的邻域/退火参数（与问题几何强耦合）。
  - 先验假设"最优解一定对称"——本场被实验否定。

## 6. 对新手的关键启示

1. 这是**最适合新手练手的比赛类型**：无需数据清洗、无过拟合风险，反馈即时。
2. **优化质量的差距来自搜索效率**——算法结构 + 工程性能，而不是模型选择。
3. **先做小而快的实验验证假设**（如对称性），再投入大规模计算。
4. **社区共享密集**：这类比赛的公开讨论是高质量的学习材料。
