# KStarter 开赛—收官 SOP（操作手册）

> 定位：把 `analysis/THEORY.md`（v0.7：L1–L133 + T1–T37）、`analysis/failures.md`（12 类失败模式 + 1964 条条目）、`analysis/evidence_map.md`（规律 × 数字证据）落成可执行步骤。
> 适用：kaggle 竞赛（打榜/评测/agent/研究赛）从开赛到复盘；新场次增量分析也按本 SOP 执行。

## 0. 工作流总览（建议节奏）

| 阶段 | 时间盒 | 目标 | 产出 |
| --- | --- | --- | --- |
| 侦查 | 0–2h | 数据/指标/平台/提交契约摸清 | 一页"开赛计划"+ 风险登记 |
| 基线 | 2–8h | 指标口径正确的最简模型 + 本地 CV + 首次合法提交 | 可复现 baseline + LB 锚点 |
| 迭代 | 20–60% 赛程 | 验证设计、特征、模型、后处理逐项对照 | 实验日志（含失败项） |
| 冲刺 | 最后 20% | 稳定单模/集成 + 提交策略 + 交付文档 | 选定的 1–3 个提交 |
| 收官 | 截止前 48h | 格式/凭证/字数/链接核查 | 提交凭证 + write-up |
| 复盘 | 赛后 | 深读文档 + claims/theory/failures 回流 | `analysis/deep/<slug>.md` + 更新台账 |

## 2. 验证设计决策树

```text
有实体键（玩家/患者/用户/设备）？
├─ 是 ─ 实体是否整体落在 train 或 test？
│        ├─ 是 ─ GroupKFold(实体) 为诚实口径；与 KFold 分数各记一版（L116/T31）
│        └─ 否 ─ 先查重复/近重复，再做 GroupKFold 防重复实体
├─ 有时间键？
│   ├─ 预测未来 ─ 时间切分（purge/embargo）；禁随机 KFold（L21）
│   └─ 仅时序特征 ─ 时间块 CV + 滚动验证
└─ 合成数据？
    ├─ 原数据可得 ─ 随机目标 z 检验（L115）
    ├─ 原数据可用 ─ 对抗验证后再合并（L131）
    └─ 生成痕迹明显 ─ 检查孪生行/顺序指纹（L1）
```

**CV/LB 关系判据**（每次开赛都做）：

1. 公榜样本量 / CV 样本量：< 1/3 时公榜按"随机变量"处理（L6/T31）；
2. 记录 CV–LB 的秩相关（至少 3–5 次提交后再判断）；
3. LB 只用于验证"绝对水平"与提交格式，不用于逐次调参（T3/T37）。

## 3. 指标结构速查表

| 指标 | 奖励什么 | 忽略什么 | 常见结构套利 | 证据 |
| --- | --- | --- | --- | --- |
| RMSE/MAE | 平均/绝对误差 | 尾部在 MAE 下被线性化 | 目标变换、稳健损失 | 通用 |
| MedAE | **中位数那一个样本** | 两端样本 | 对极端样本降权、档位整形 | L114/s3e25 |
| AUC/NDCG/top-K | 排序正确性 | 概率绝对校准 | 秩平均、追加预测、校准不变融合 | L14/L38 |
| LogLoss | 校准 + 区分度 | — | 校准/温度缩放 | L23 |
| R² | 方差解释 | 异常值主导 | 极端值裁剪/分层建模 | planttraits |
| F1/阈值指标 | 阈值处精度/召回 | 阈值外排序 | 阈值搜索、先验校正 | L22/L25 |
| 容差型（MAP@{K}/误差容差） | 落在容差内的比例 | 超容差的幅度 | target 整形、两极化流水线 | L37/L128 |
| ELO/对局积分 | 长期胜率 | 单局波动 | 提交对冲/对手分布分析 | lux/maze |

## 4. 数据审计清单（逐条打勾）

- [ ] 实体键唯一性：`df[entity].nunique()` vs 行数；实体是否跨 train/test；
- [ ] 时间泄漏：特征的最大时间与标签时间的关系；滚动特征是否"截至当前"（L26，scrabble）；
- [ ] 重复行：全列 hash；近重复：embedding 近邻/pHash（图像）、MinHash（文本）；
- [ ] 哨兵值：-1/-666/-999/空字符串/none vs None；
- [ ] 类别 OOD：test 取值集合 − train 取值集合；用频率编码而非硬编码（s3e18）；
- [ ] 缺失结构：缺失是否与目标相关（s4e12 的 NaN 信息）；缺失指示特征（L19）；
- [ ] 分布漂移：对抗验证 AUC（>0.6 需警惕）（L30/L131）；
- [ ] 合成痕迹：生成顺序/索引、孪生行、重复倍数（S5E2 ≈80 份副本）。

## 5. 建模决策树（按主题）

### 5.1 表格

```text
样本量/特征类型？
├─ 中小样本 + 高基数类别 ─ GBDT（CatBoost 原生类别）+ 线性/核模型做多样性（L13）
├─ 低信号/随机目标 ─ 稳集成 + 分布整形，不堆深模型（L115/T28）
├─ 多目标 ─ 先做目标级模型选择实验，再决定拆/合（T29）
└─ 指标为中位数/分位 ─ 样本权重 + 目标形态整形（L114）
```

### 5.2 CV / 多模态

```text
数据域差？
├─ 多来源/多田块 ─ 高分辨率 + IBN/直方图均衡 + 度量损失 + TTA（L129）
├─ 训练无掩码、测试有掩码 ─ 按测试掩码分布增强或用 logits（hotel-id）
├─ 无 GT 检测/计数 ─ 过滤 + 密度分层（L128）
├─ 未知类检测 ─ 1−max(prob) + 集成 std（fathomnet）
└─ presence-only 标签 ─ 网格邻域换标/温度软化（L130）
```

### 5.3 NLP / Agent

```text
任务形态？
├─ 提示词/生成任务 ─ system prompt + few-shot + 可机读输出（makersuite）
├─ 检索/匹配 ─ 双塔 + 大规模 I/O（wikipedia）
├─ 安全红队 ─ CoT/工具/通道三面 + 推理预算（L119）
├─ RL 对战 ─ 规则基线 → 课程 + 快模拟器 + 对手多样性（L124–L127）
└─ Agent 元竞赛 ─ schema 本地校验 + 预算工作流（L122/L123）
```

## 6. 评审制交付模板

1. **问题**：一句话 + 为什么重要；
2. **数据与口径**：来源、字段字典、已知缺陷；
3. **方法**：观察 → 改动 → 验证闭环（至少 1 个消融）；
4. **失败路径**：试过但放弃的方案与原因；
5. **结果**：数字 + 图表（rating 曲线/对位胜率/管线图/分布图）；
6. **局限**：数据范围、复现条件、未解决问题；
7. **交付**：公开 notebook + 模型/数据链接 + 字数/页数合规。

检查：字数（2000/3 页等）、附录是否计分、图表数量限制、外部素材授权、指向自己团队的链接可访问（L117/L122）。

## 9. 赛后复盘模板（写入 `analysis/deep/<slug>.md`）

固定 7 段：一句话重述与数字账 → 逐方案对照矩阵 → 共识分歧与裁决（带置信度）→ 证据分级 → 悬案与缺口 → 图表证据（相对路径）→ 出处（真实 topic id）。

同步更新四件套：

- 新数字 → `analysis/claims.csv`（跑 `scripts/build_claims.py`）；
- 新图证 → `analysis/images_index.csv`（跑 `scripts/build_images_index.py`）；
- 新技法/传播链 → `analysis/lineage.md`；
- 新失败模式 → `scripts/build_failures.py` + `scripts/build_failures_md.py`；
- 新规律/张力 → `analysis/THEORY.md`，并跑 `scripts/build_evidence_map.py` 补证据台账。

## 10. 症状 → 原因 → 修复 速查表

| 症状 | 可能原因 | 修复 |
| --- | --- | --- |
| CV 很好、LB 崩 | 实体/时间泄漏；列顺序错；分布红利 | 分组 CV；核对提交格式；降公榜依赖（F1/F2） |
| CV 与 LB 完全无关 | 公榜太小/分布不同；指标实现不一致 | 自建 holdout；下载官方 metric（F5） |
| 本地分高但提交 0 分 | 格式/NaN/列名/zip 结构 | 最小提交演练（F8） |
| 训练很稳但线上退化 | 早停/播种/预处理在推理时不同 | 固化推理管线；端到端复跑（F6/F11） |
| 验证集不可信 | 小验证、实体混折、时间穿越 | 增大 holdout；GroupKFold；purge/embargo（F2） |
| 长尾类别永远不预测 | 分布不匹配、损失失衡 | 归并 unknown/度量损失/重加权实验（F4） |
| 排行榜扎堆同一分 | 指标结构可利用 | 读指标结构，做形态整形（L114/T37） |
| 训练到一半收益停滞 | RL 拐点/数据信息枯竭 | KL/产量/胜率早停；换目标（L125） |
| 提交时间不够 | 平台/额度/队列 | 提前 48h + 预算模型（L123/F8） |
| 评审分低但方案强 | 叙事/消融/失败路径缺失 | 按交付模板重写（L117） |
