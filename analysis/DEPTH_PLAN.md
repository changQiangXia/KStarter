# 仓库深度优化方案 v2：从"速览"到"深读"

> 修正：用户指出瓶颈**不在采集量**，而在**对已有材料的剖析深度**。v2 以此为准。
> v1 中的"扩采 W1"降级为可选项（仅在个别场次材料缺口时使用）。
> 示范：`analysis/deep/tabular-playground-series-nov-2022.md`

## 0. 问题诊断（剖析为什么不深）

现有 264 篇笔记的模式 = **"谁做了什么"的单篇转述**，缺少五件事：

| 缺失 | 具体表现 | 深读要补什么 |
| --- | --- | --- |
| **跨篇对照** | 每篇帖子独立摘要，不比较 1st/2nd/3rd 的异同 | 逐方案对照矩阵；共识 vs 分歧；分歧裁决 |
| **机制推演** | 记录"做了什么"，不解释"为什么有效" | 第一性原理推演（如 Nov2022 的 1.17→w≈3.2） |
| **证据分级** | 自述、传闻、可复算数字混在一起 | 断言按"可验证/合理推断/自述/弱断言"归档 |
| **边界条件** | 只说适用，不说何时失效 | 失效条件 + 反事实推演 |
| **悬案与失败学** | 负面结果几乎不入档 | 悬而未决问题清单；"什么没奏效"专项 |

## 1. 深读层（新 W1，最高优先）：每场一篇"对照式深读"

**模板（8 组件）**——示范见 `analysis/deep/tabular-playground-series-nov-2022.md`：

1. 一句话重述：这道题**真正**在考什么（降解为哪几步）；
2. 材料与角色：每篇帖子提供了什么（含探测量、教程、主机方等非方案帖）；
3. **逐方案对照矩阵**：维度 × 方案；
4. 共识与分歧：把"方法差异"还原成"自由度差异"，并给出**裁决**（依据+置信度）；
5. **制胜增量识别（数字账）**：谁贡献了多少分，哪个动作是 95% 的收益；
6. **机制推演**：逆向工程常数/结构（本篇标杆：−1.17 → w≈3.2）；
7. 证据分级表；
8. 边界条件/反事实/悬案/失败学；
9. **图表证据（新增，强制）**：对内嵌图片用**仓库相对路径 Markdown 嵌入**
   （如 `![caption](../../intel/<slug>/bodies/<topic>_img/01.png)`），GitHub 直接渲染
   "文字分析 + 图片作证"；每图配：来源帖（topic id）+ 从图中读到、正文没有的结构/数字；
10. 对既有笔记与 playbook 的修订点；
11. 出处（全部 topic id 校验）。

### 1.1 图像层工作流（新增）

| 步骤 | 做法 | 产出 |
| --- | --- | --- |
| 索引 | 扫描 `bodies/*.html` 的 `<img>` + 上下文/alt 文本，按"架构/流程/分数表/校准图"关键词打分 | `analysis/images_index.csv`（含相对路径、来源帖、上下文） |
| OCR | 对截图/幻灯片类图片批量 OCR（表格与分数尤其重要），sidecar 存 `*_img/<file>.ocr.txt` | 可全文检索的图内文字；数字进入 `claims.csv` |
| 精读 | 对 Tier A 场的候选图用图像查看逐张阅读（优先架构图、分数表、校准/分布图；梗图跳过） | 深读文档"图表证据"节（内嵌图 + 提取结论） |
| 回写 | 关键结论回写原笔记（同样内嵌图）；无法下载的站外图床（imgur 等）保留 URL + alt 文本并在文中注明"图不可达" | 笔记升级 + 缺口清单 |

**GitHub 渲染注意**：图片路径用相对路径（从 `notes/xx/` 出发为 `../../intel/...`）；PNG/JPG/GIF 均可内联渲染；
大 GIF 会拖慢页面（必要时标注跳转）；不在仓库内的站外图不嵌入（保留链接与 alt）。

**分层执行**：
- **Tier A（约 60 场）**：材料≥6 篇且含 1st–5th 方案/机制帖/探测量的大场——做完整深读；
  （Featured/Research 优先：RSNA、BirdCLEF、Lux、March Mania、AIMO、IMC、Jigsaw、Feedback、金融族、Playground 机制场如 Nov2022/S5E2/S5E12/S6E9…）
- **Tier B（其余 ~204 场）**：执行"轻量深读"= 对照矩阵 + 共识/分歧 + 证据分级 + 悬案（4 组件），不展开完整机制推演；
- 每篇完成后回写：原笔记升级 + playbook 增补点。

## 2. 理论层（新 W2）：跨场"可证伪规律"手册

从深读里**自下而上**归纳，而不是罗列技巧：

- 每条规律写成：**命题 → 作用机制 → 适用范围 → 反例 → 证据场次（带数字）**；
- 重点收录"张力"：例如
  - 单模 vs 大集成（S5E2/S5E11/S4E10 vs S6E3/S6E9：何时前者赢？）；
  - 单参数校准 vs 灵活校准（Nov2022 的裁决模式，向其他场推广）；
  - 公开榜可不可信（可量化为"CV 样本量/榜样本量"比值——S3E9 的测量 vs 随机变量框架）；
- 产出：`analysis/THEORY.md`（每条规律配证据台账）。

## 3. 证据审计（新 W3）：数字台账与自述核验

- 抽取所有可量化断言（CV/LB 变化、阈值、折数、样本数）→ `analysis/claims.csv`；
- 标注：可复算 / 自述 / 互相矛盾；
- 在每篇深读里执行"数字一致性检查"（如 3rd 的 0.42 阈值无推导、7th 的 250 列无误差棒）。

## 4. 方法谱系（新 W4）与批判层（新 W5）——沿用 v1 思路，但以深读为素材

- 谱系：技巧传播链（CatBoost-baseline 链、DAE 血脉、先验校正传播），≥40 个节点；
- 批判：幸存者偏差、自述不可核实、公开榜污染样本、规则变化导致的伪趋势；各册 playbook 尾节 + `analysis/limitations.md`。

## 5. 执行顺序与验收

1. **深读 Tier A 第一批（10 场）** → 用户验收格式（用 Nov2022 示范确认）；
2. 滚动执行 Tier A（60 场）→ Tier B（204 场）；
3. 每完成 10 场：回写笔记升级 + 汇总"理论层"新条目；
4. 收尾：THEORY.md / claims.csv / lineage / limitations；
5. 全部产物提交 GitHub（沿用分批推送方案）。

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 深读文档 | 1 篇示范 | Tier A 60 篇 + Tier B 204 篇（轻量） |

| 谱系/批判 | 无 | 各 1 篇 |
