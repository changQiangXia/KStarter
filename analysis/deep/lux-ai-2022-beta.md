## 3. 共识、分歧与裁决

### 共识一：beta 是"机制公证"阶段，投入产出比与正赛不同（362825 / 363366；置信度高）

官方明确无奖励、以反馈为目的，并说明将基于反馈改平衡、甚至改机制。**裁决**：beta 阶段优先做"机制理解 + 工具链"（读 spec、跑 starter、验证提交链路），把策略深度优化留给正赛。置信度：高。

### 事件一：动作队列与两阶段动作空间先要写成状态机（363366 / 365579；置信度中高）

动作队列改变了"能量不足即失败"的语义（改为等待），直接影响 agent 的行为建模；两阶段有两套动作空间。**裁决**：先画"阶段/动作队列/等待规则"状态机，再写策略；对 breaking change 建版本开关。置信度：中高。

### 事件二：活跃提交限制改变评估策略（363479；置信度中）

官方试验 3 个活跃提交，旧提交会被禁用——意味着"多提交对冲"不可行，必须集中维护最优 agent。**裁决**：选好 1–3 个代表不同策略的提交并持续更新，避免广撒网。置信度：中。

### 事件三：beta 平台 bug 密度高，需要防御式工程（363556 / 365465 / 371151 / 368360；置信度中高）

验证对局失败、spawn 崩溃、重复 transfer 复制 ice、对局提前结束等都会被报告并修复。**裁决**：对局结果做异常筛选（无信息/提前结束的 episode 不作为调参依据）；提交前在本地自建 replay 校验。置信度：中高。

### 事件四：可视化工具是 agent 赛的公共基础设施（367091；置信度中高）

Lux Eye 2022 以 29 票成为本场最高热帖之一，社区用它替代官方 visualizer。**裁决**：进入新 agent 环境先找/搭 replay 工具，再谈策略；可视化是最快的机制学习方式。置信度：中高。
