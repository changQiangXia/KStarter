# 强化学习/博弈：前 50 选手决策增量（P3）

> 来源：`people/claims/gm_claims.csv` 中该领域的 47 条断言，按受控标签聚合；每条断言可经 `scripts/people/verify_claims.py` 回链原文。

## 提交/推理工程（证据单位 9）

- **条件**：1 秒/回合 + 60 秒 overage、提交文件 100MiB 上限  
- **动作**：int8 量化线性层、限制可见 fleet 数并优先最大者；对约 8% 超时的 4p 局，在剩余 1 秒 overage 时切换到 5M 小模型收尾；用 4-bit NormalFloat（group 128 + 每 group 一个 fp16 scale）把 200M 压进 100MiB  
- **机制**：量化换容量；小模型接管已决局面（critic 判断多数局已定，5M 模型 100% 转化胜势）  
- **结果**：100MiB 上限；4-bit、group 128；量化模型对原始模型胜率约 40%  
- **证据**：[orbit-wars#714324-04](https://www.kaggle.com/competitions/orbit-wars/discussion/714324)（@pressman1｜A）
- 其他案例：[@xiaoz259](https://www.kaggle.com/competitions/ai-agent-security-multi-step-tool-attacks/discussion/739181)、[@yiheng](https://www.kaggle.com/competitions/neurogolf-2026/discussion/726653)、[@yiheng](https://www.kaggle.com/competitions/neurogolf-2026/discussion/726653)、[@cdeotte](https://www.kaggle.com/competitions/llm-20-questions/discussion/520429)

## 目标编码/类别特征（证据单位 8）

- **条件**：成功候选有 hop1 工具调用与 hop2 清理响应，hop2 不计分  
- **动作**：目标：保持 hop1 精确工具调用，同时让 hop2 首 token 为 EOG；损失为 hop1 目标 NLL 均值加 λ（非 EOG 最大 logit 减 EOG logit）；每轮用梯度挑 256 个替换 token、构造 512 到 2048 候选、贪心保留最优  
- **机制**：把 prompt 工程转成标准对抗优化问题；省 token 意味着同一时间预算内跑更多候选  
- **结果**：每轮 256 个替换 token；512 到 2048 候选  
- **证据**：[ai-agent-security-multi-step-tool-attacks#739181-02](https://www.kaggle.com/competitions/ai-agent-security-multi-step-tool-attacks/discussion/739181)（@xiaoz259｜A）
- 其他案例：[@cnumber](https://www.kaggle.com/competitions/llm-20-questions/discussion/531106)、[@yiheng](https://www.kaggle.com/competitions/neurogolf-2026/discussion/726653)、[@cdeotte](https://www.kaggle.com/competitions/llm-20-questions/discussion/520429)、[@takoihiraokazu](https://www.kaggle.com/competitions/predict-student-performance-from-game-play/discussion/420077)

## Agent/LLM 工具（证据单位 7）

- **条件**：agent 容易在现有图上陷入分数平台  
- **动作**：观察历史分数：重写架构平均每任务加 0.5，优化现有图只有 0.05，因此鼓励 agent 探索新架构

## 信号/频谱处理（证据单位 3）

- **条件**：Kaggle 环境无法装包，缺快速推理 runtime  
- **动作**：ONNX runtime/OpenVino 打包失败（错误日志 404），被迫取消正在训练的 DoubleCone(6,8,6)；静态/动态量化、压缩、jit 都因 setup 时间或精度-性能权衡不可用；最终：DoubleCone(4,6,4) 预测最多 3 步 + tiny (2,6,2, 64 通道) 补满，再模式匹配填到 20 步；每轮做 1-3 次慢预测纠正 tiny 的错误，通常达 6-8 次预测、有效队列 5-6；用预测式时间管理应对 VM 性能波动  
- **机制**：在无 fast runtime 的环境里，用小模型+模式匹配填队列，并用少量慢预测纠错  
- **结果**：3 步 + tiny；队列 20；有效 5-6

## 数据清洗/去噪（证据单位 2）

## 集成权重选择（证据单位 2）

- **条件**：比赛模型是 GGUF（无梯度）  
- **动作**：用 BF16 权重跑 GCG 生成候选，用 ridge 模型重排，再只在小子集上用真实 GGUF 评估；最终候选按真实 KV-cache 顺序评测；初始 margin 极大（Gemma 约 -14、GPT-OSS 约 -38），Gemma 最终越过 0，GPT-OSS BF16 成功但 GGUF 回归约 -28  
- **机制**：量化推理与离散 token 搜索造成顽固局部最小值与迁移漂移  
- **结果**：Gemma margin 约 -14；GPT-OSS 约 -38；GGUF 回归约 -28  
- **证据**：[ai-agent-security-multi-step-tool-attacks#739181-03](https://www.kaggle.com/competitions/ai-agent-security-multi-step-tool-attacks/discussion/739181)（@xiaoz259｜A）

## 时间/分组切分（证据单位 2）

- **条件**：数据不是自然图；图边按时间/距离人工选取  
- **动作**：基础模型用自注意力（NanoGPT 风格）：输入为归一化 pulse 与 transparency，序列最多 256，优先采样 aux=False 的 pulse；输出两个 128 bin 的角度分类头；自定义损失把 one-hot 目标做高斯卷积平滑（方位角环绕、天顶角扩展 bin）  
- **机制**：人为构造的图边不反映真实关系；角度是有序类别，平滑目标引入序结构  
- **结果**：序列上限 256；两个 128 bin 头  
- **证据**：[icecube-neutrinos-in-deep-ice#402888-01](https://www.kaggle.com/competitions/icecube-neutrinos-in-deep-ice/discussion/402888)（@dipamc77｜A）
- 其他案例：[@takoihiraokazu](https://www.kaggle.com/competitions/predict-student-performance-from-game-play/discussion/420077)

## 分组聚合特征（证据单位 2）

- **条件**：FP16 在后期不稳定；序列长度方差大  
- **动作**：FP16 加 FlashAttention 训练快，但 score 到 0.990 后不稳定 → 切 FP32（仅大模型出现）；按事件长度分组 batch 减少 padding：比 FlashAttention 快 1.5x、比普通 attention 快 3.5x；每个 epoch 只加载部分训练数据。  
- **机制**：大模型对数值精度更敏感；按长度分桶直接减少无效计算  
- **结果**：1.5x 与 3.5x 提速  
- **证据**：[icecube-neutrinos-in-deep-ice#402888-03](https://www.kaggle.com/competitions/icecube-neutrinos-in-deep-ice/discussion/402888)（@dipamc77｜A）
- 其他案例：[@takoihiraokazu](https://www.kaggle.com/competitions/predict-student-performance-from-game-play/discussion/420077)

## 特征选择（证据单位 2）

- **条件**：两个模型分歧大且都未接近上限  
- **动作**：base 分类器与 vMF 栈模型输出：简单投票（差太远不平均）0.976 到 0.973，加置信度/长度/z 阈值到 0.9715；再用 XGBoost 融合两模型输出一次到 0.969；再加预测哪些预测是坏的的分类器翻转角度，18 层模型最终 0.965；推理 25 分钟内可到 0.967  
- **机制**：把融合视为学习任务：分类器可利用分歧与置信度特征选择来源  
- **结果**：0.976 到 0.965；25 分钟  
- **证据**：[icecube-neutrinos-in-deep-ice#402888-04](https://www.kaggle.com/competitions/icecube-neutrinos-in-deep-ice/discussion/402888)（@dipamc77｜A）
- 其他案例：[@ferdinandlimburg](https://www.kaggle.com/competitions/lux-ai-season-2/discussion/406702)

## 残差提升（证据单位 2）

- **条件**：需要按单位决策与空间动作  
- **动作**：残差 CNN + squeeze-excitation（也试过 RoPE ViT 但训练不稳）；spatial 输入 10 帧堆叠 + nontemporal 经 2 层 CNN 投影，global 经 2 层 MLP 投影后广播相加；8 块 3×3 CNN、d_model 256；value 头 1×24×24 均值 + 双队 softmax 归一化（训练期看双方视角，测试不用）；actor 分主头（NoOp、4 移动、5 个 sap 距离）与 sap 头（24×24 概率图按单位掩码）  
- **机制**：空间与全局信息分别编码后相加；sap 作为空间分布建模并按单位掩码  
- **结果**：d_model 256；10 个主动作  
- **证据**：[lux-ai-season-3#568621-04](https://www.kaggle.com/competitions/lux-ai-season-3/discussion/568621)（@pressman1｜A）
